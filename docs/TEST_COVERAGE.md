# Покрытие тестами

Живой документ. Обновлять в том же коммите, что и любое добавление, удаление или существенное изменение теста в `tests/`. Должен точно отражать, что проверяет каждый файл — не оставлять устаревшим.

Все тесты — `node --test`, запускаются командой `node --test tests/*.test.cjs tests/*.test.mjs` (см. [CLAUDE.md](../CLAUDE.md)). Импортируют скомпилированный `apps/api/dist/*.js` — после правок в `apps/api/src` нужен `pnpm --filter @provider/api run build` перед запуском.

**Baseline: 47/47 passing.** Допустимого красного baseline нет: любое падение требует исправления до коммита.

| Файл | Что проверяет |
| --- | --- |
| `tests/access.test.cjs` | `AdminTokenGuard`: роль `EDITOR` не может читать/менять provider/site settings; каждая роль сохраняет доступ ровно к своему контенту/тарифам/CRM; отсутствие credentials даёт 401 независимо от наличия сервисного токена. |
| `tests/admin-forms.test.cjs` | Admin-формы корректно сбрасываются после того, как браузер очищает `event.currentTarget` (регрессия конкретного DOM-поведения). |
| `tests/admin-users.test.cjs` | Управление пользователями: последнего администратора нельзя деактивировать или понизить в роли; сброс пароля отзывает сессии и не возвращает данные пароля в ответе; создание пользователя требует валидный email, роль и достаточно длинный пароль. |
| `tests/block-validation.test.cjs` | Валидация `PageBlock`: валидные блоки и частичное изменение видимости принимаются; невалидная форма блока и попытка сменить `parent` отклоняются; исполняемые (`javascript:`) и protocol-relative CTA-ссылки отклоняются. |
| `tests/city-import.test.cjs` | Импорт городов: принимает согласованные русские алиасы колонок XLS; блокирует дублирующиеся slug и отсутствующие обязательные значения; для нового города создаётся стандартный набор черновых страниц. |
| `tests/coverage.test.cjs` | `CoverageService`/`AddressChecksController`: пустой или невалидный адрес никогда не вызывает внешний coverage API; неопубликованный сайт не вызывает внешний API; результат различает negative/unknown/malformed-ответ и сетевой сбой. |
| `tests/crm-status.test.cjs` | `CrmLeadsController`, смена статуса лида: авторизованный оператор фиксируется в истории; конкурентное изменение возвращает конфликт без искажения истории; повторная установка того же статуса не создаёт дублирующий переход; неподдерживаемый статус отклоняется. |
| `tests/lead-check.test.cjs` | `PublicLeadsController`: лид отклоняется для неопубликованного сайта; отклоняется недоступная (не найденная/архивная) страница или тариф; используется persisted-статус и ответ проверки адреса, а не подделанный клиентом; ручной лид не может подделать положительный coverage-результат; неизвестный `addressCheckId` отклоняется перед сохранением; проверка адреса не может быть привязана к другому адресу; повторные заявки за 24 часа подавляются отдельно по нормализованному телефону и нормализованному адресу, сохраняют причину/ссылку на исходный лид и не запускают проверку договора или доставку. 8/8 тестов файла проходят. |
| `tests/lead-access.test.cjs` | Одноразовый fallback-доступ: raw token не хранится в БД, валидная ссылка используется ровно один раз; истекший, измененный, отозванный и относящийся к другой заявке token отклоняется; email содержит admin URL с token во fragment и без HMAC query-подписи. |
| `tests/public-data.test.mjs` | Публичный API-срез данных: приватные provider/site настройки никогда не попадают в public-контент; тарифы API распределяются по тем же категориям услуг, что использует публичный сайт; нулевая промо-цена сохраняется как есть, отсутствие промо-цены — fallback на стандартную цену. |
| `tests/tariff-identity.test.cjs` | Deterministic identity key тарифа: ручное переименование тарифа обновляет ключ идентичности; повторный импорт находит legacy-тариф по slug вместо создания дубликата. |
| `tests/tariff-import.test.cjs` | Импорт тарифов: XLSX-парсер читает первый лист и сохраняет пустые ячейки как есть; валидация создаёт согласованный identity key и отдельно выделяет промо-цену; валидация блокирует дублирующиеся business-ключи, невалидные статусы услуг и отсутствующие города; отчёт валидации сообщает о дублирующихся ключах до применения; `apply` создаёт только валидированные строки с учётом `acceptedKeys`. |
| `tests/web-build-data.test.mjs` | Три реальные сборки `apps/web`: успешная загрузка fixture через HTTP API и smoke готового `dist` (canonical, H1, реальная цена, robots, sitemap, root URL, отсутствие localhost); обязательный fail-fast без API; demo-данные только при явном `ALLOW_DEMO_DATA=true`. |
