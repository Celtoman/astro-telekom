# Городская техническая поддержка

CITY_SUPPORT выпущен 17 ноября 2026 года в защищённом тестовом контуре для 207 городов. Исправления порядка элементов и состояния редактора проверены на коммите `703df070`. Опубликована ревизия 34. [Протокол приёмки](research/2026-11-17-support-implementation.md), [контракт CMS](plans/2026-11-17-support-cms-contract.md), [план переноса](plans/2026-11-17-support-implementation-plan.md), [задача #611](https://github.com/Celtoman/astro-telekom/issues/611).

Порядок чипов, магазинов, тем, шагов и ограничений задаёт renderer по явным ключам; порядок ключей PostgreSQL JSONB не используется как композиция. Переключение доступности rich-text не создаёт событие изменения и не должно включать несохранённый draft.

## Содержание и маршруты

Один общий PageTemplate CITY_SUPPORT содержит 13 фиксированных секций. Городские Page-shell используют `/{location}/tehpodderzhka`; новые города получают shell при создании/импорте. Материализация каталога проверяет состав, порядок и видимость блоков. Старый immutable snapshot не получает SUPPORT при CODE rebuild. Новый снимок включает поддержку всех своих опубликованных городов и использует общий inventory для HTML, sitemap и коллизий URL.

Миграции 0075/0076 добавляют enum и working-only backfill только сайта Дом.ру: шаблон, городские shell, SEO и историю рабочей ревизии. Повтор не перезаписывает авторский контент. Коллизии останавливают транзакцию. Первые шесть вопросов сохраняются из Screens, ответы копируются по совпадающим вопросам CITY_HOME FAQ с переменными. Далее FAQ поддержки независим. Пустая обязательная переменная при выпуске даёт точную диагностику поля.

## Редактор и API

`/templates/support` повторяет ручной цикл существующих редакторов: сохранить рабочую версию, открыть сохранённый предпросмотр выбранного города, отдельно опубликовать. Неполный безопасный черновик сохраняется, список отсутствующих полей возвращается редактору; строгая проверка публикации требует заполнения. Конфликт ревизий и ошибка запроса сохраняют введённые данные.

Все маршруты имеют prefix `/api/v1` и AdminTokenGuard:

| Метод и путь | Контракт |
| --- | --- |
| GET `/admin/sites/:siteId/support` | Рабочий content/revision, missingFields, previewPath, системные контакты и опубликованная версия из exact serving snapshot |
| PATCH тот же путь | Только `{expectedWorkingRevision,content}`; Serializable, фиксированные блоки и ContentRevision; stale revision — 409; сохранение не публикует |
| POST `.../support/media` | Один multipart JPEG/PNG/WebP, максимум 10 МБ и 24 млн пикселей |
| GET `.../support/media/static/:slot` | Приватный проверенный по SHA исходник начального макета |
| POST `.../support/media/static/:slot/crop` | Импорт начального исходника в media и подготовка области |
| GET `.../support/media/:id` | Метаданные и private previewPath своего сайта |
| GET `.../support/media/:id/file?variant=<sha256>` | Только принадлежащая файлу производная, private/no-store, nosniff |
| POST `.../support/media/:id/crop` | `{crop:{x,y,width,height}}`, нормализованная область внутри оригинала |

Ограниченный редактор допускает текст, жирное выделение, переменные и типизированные ссылки. Назначения: главная, городской ADDRESS, города, OFFICIAL_SITE, ACCOUNT, SPEED_TEST, FAQ поддержки и два системных контакта. Произвольный HTML и inline URL не принимаются. Внешние HTTPS-ссылки сообществ и магазинов редактируются отдельно. FAQ: 1–50 полных пар при публикации, добавление/удаление/перестановка в редакторе. Общие Header/Footer/AddressOnly не получают локальных переопределений SUPPORT.

## Изображения и сборка

Десять редактируемых слотов используют существующий EditorialMediaAsset и private media storage. Четыре иллюстрации инструкций и телефонное увеличение имеют crop; остальные показывают полный источник в принятой композиции. Телефон всегда использует один файл: полный снимок без обрезки и отдельную производную выбранного номера. Начальные Figma-байты immutable в `/images/support/v1`; приложение — JPEG с корректным расширением `.jpg`.

Каталог фиксирует `supportMedia`: выбранные full/crop варианты с ключами, SHA и размерами. Builder переносит только captured variants вместе с editorial media и проверяет целостность. Authenticated preview получает private bytes и использует общий с витриной renderer/CSS. Исходники, производные, working content, ContentRevision и sourceSnapshot в отчётах проверки входят в reference-аудит резервной копии; очистка по одному лишь текущему опубликованному каталогу недопустима.

## Адаптивы Screens

На ПК введение и карточки сообществ занимают левую колонку, снимок VK начинается справа на уровне введения. Карточки «Одноклассники» и Telegram стоят рядом, ссылки выровнены по нижнему краю. На планшете приложение сохраняет текст и магазины слева, мокап справа. Кнопки магазинов идут после двух абзацев в раскладке 2+1. На мобильных H1 использует 28/33 px, карточки первого экрана имеют поля 16 px, чипы занимают два ряда общей высотой 72 px. ## Проверки и выпуск

Модель, типизированные ссылки, rich-text, переменные, старые snapshots, all-city routes и финальный Astro HTML проверяются SUPPORT suites. SQL rehearsal проверяет fresh seed/backfill/idempotence/provider isolation/rollback, HTTP rehearsal — реальный upload/crop/private bytes/save/409 и чужой сайт. Браузерная проверка редактора и четырёх раскладок фиксируется отдельно от автоматических тестов.

Перед выпуском обязательны полный `pnpm check`, exact-SHA зелёный CI, finished/healthy Coolify и CODE. Общая CMS-публикация требует проверки полного working diff: посторонние черновики не включаются и не удаляются автоматически. Успех подтверждают receipt/SQL acknowledgment и реальные HTML всех городов, а не одна постановка задания в очередь.
