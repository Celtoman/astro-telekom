# Полная общая HOME: локальная интеграция этапов 5–7

Дата: 16 октября 2026 года. Учёт: [#344](https://github.com/Celtoman/astro-telekom/issues/344). Основание — [утверждённые паспорта и действия](../plans/2026-10-16-general-home-passports-actions-draft.md) и [план](../plans/2026-10-16-general-home-implementation-plan.md). Этот документ подтверждает локальную реализацию и проверки; внешний deployment и CMS-публикация требуют отдельных доказательств.

## Реализация

`pages/index.astro` выбирает полную композицию только при наличии строгого `catalog.generalHome`. Состав: Header → Hero1d → 2g → B14 → B15 → B06b → Movix → B16 → 2e → B13 → B19 → Footer. Десять контентных блоков имеют устойчивые `data-home-block`, один H1 остаётся в Hero. `GeneralHomeComposition.astro` собирает существующие компоненты; Header/Footer используют общий безопасный renderer `general-home-shell.ts` и исходную Figma-оболочку на белой странице.

Без новой композиции старые immutable snapshots сохраняют прежний Header/Footer и Hero. CITY_HOME и тарифные страницы не получают новые блоки. Версии композиции, Hero и CITY_HOME не объединены. Контент/порядок не редактируются через произвольный HTML, CSS или меню.

Шапка «Подключить» и B06b открывают смонтированный существующий FLOW 2. Мобильное меню закрывается до открытия формы; Escape возвращает фокус к открывшему действию. Встроенный 2g использует ту же AddressForm с отдельным ID. Городские service URL строятся из canonical slug; исходный city-home href хранится независимо от текущего назначения picker. Повторное открытие обычного выбора города сбрасывает прежнее service/anchor/callback-намерение.

Дефолт Москвы берётся только из опубликованного каталога. Если её нет, адресные/городские действия предлагают выбрать настоящий город; шапка показывает «Выберите город». Контекст городских ссылок не становится городом консультации без ручного выбора: модальный FLOW 1 на полной HOME передаёт только подтверждённый citySlug, как встроенный 2e. Прежние страницы сохраняют прежнее правило контекста.

Общие график ежедневно 24/7 и срок звонка 15 минут сохранены. Поддержка абонентов использует отдельный телефон. Пользовательское соглашение остаётся обычным текстом в Footer: новый URL, документ или подмена согласием не добавлены.

## Preview и диагностика

`preview-document.mjs` выводит весь утверждённый состав и новую оболочку из того же каталога и общих renderer. Явный trusted loader включает CSS композиции/оболочки и исходные assets. Формы, ссылки, FAQ и городские controls в sandboxed preview неактивны; исполняемый код из каталога не загружается.

Неполный безопасный черновик не заменяется демоданными. Если API или renderer сообщает известные HOME block/field, `PreviewApp` показывает предметное название и ссылку «Исправить поле» в действующий редактор. Неизвестные поля не порождают произвольных ссылок. Повторная загрузка/общая ошибка не сохраняют прежнюю ссылку восстановления или iframe.

Исходная миграция оставляет FAQ пустым; это поведение defaults не изменено. Полная строгая HOME не публикуется и не получает фиктивных ответов ради preview. В визуальных fixtures применены явно синтетические вопросы и 52 города; это не сохранённый каталог владельца.

## Найденные и исправленные интеграционные дефекты

- [#346](https://github.com/Celtoman/astro-telekom/issues/346): порядок CSS полной страницы менял голубую secondary-кнопку 2g на красную. Локальный селектор усилен без изменения общих primary-кнопок; computed цвета и восемь public/preview PNG перепроверены. Независимый reviewer оценил свою правку как resolved и ship.
- [#347](https://github.com/Celtoman/astro-telekom/issues/347): прежний public-dialogs обрабатывал юридические ссылки только внутри FLOW dialog, поэтому inline2e выполнял навигацию. Добавлен standalone-вход только для этой формы, с теми же templates, панелью и стилями. Телефон/согласие остаются в исходной форме; закрытие удаляет временный dialog и возвращает фокус. Юридические тексты и URL не менялись. Независимый reviewer принял этот ограниченный scope.

## Доказательства

[Полный пакет](evidence/2026-10-16-general-home-full/README.md) содержит Figma Header/Footer, public/preview всей страницы и оболочки, legal-modal и административную диагностику.

- Полная public HOME и настоящий HTML-renderer административного preview: 1440/834/390/320; одинаковая геометрия всех 12 секций, белая основа, один H1, без duplicate ID и общего overflow. Header — 129/121/109px D/T/M; Footer — 315/399/610px. На 320 Footer естественно растёт, отдельного Figma-макета этой ширины нет. Прежние принятые адаптации отдельных блоков описаны в [приёмке компонентов](2026-10-16-general-home-stage5-blocks-acceptance.md).
- FLOW 2 из шапки/B06b; только один открытый dialog после мобильного меню, Escape/фокус, canonical service URL, подтверждённый город и отсутствие Москвы, сброс намерения picker. Ошибок JS нет.
- Юридические документы inline2e: 1440/834/390/320, сохранение телефона/согласия, Return/Escape/фокус, без второй пустой формы. Регрессия документов внутри FLOW 1 и два подтверждённых API receipt проверены перехваченными запросами. Настоящие заявки не создавались.
- Собранный `PreviewApp`: точная диагностика пустого FAQ, ссылка на его items, восстановление после refresh; настоящий sandboxed iframe с десятью блоками на трёх переключателях размера, все действия отключены. Общая ошибка убирает старый iframe/ссылку. Browser requests только GET к fixture API.
- `general-home-build.test.mjs` строит настоящий immutable artifact через StaticArtifactBuilder и API-rendered catalog. Проверены все блоки, FLOW 2, versioned local assets, сохранность inline CSP hash, объединение self/data с точными origins трёх внешних изображений и отсутствие исследовательского URL в image permissions. Городская HOME сохраняет прежнюю оболочку. Старый Hero-only snapshot отдельно покрыт прежним static-builder suite.

Первое чтение loopback HTTP получало переписанный антивирусом CSP и внедрённый Kaspersky script. Исходный HTML не содержит этих изменений. Повторная проверка передавала неизменённые байты реальной сборки браузеру через Playwright route fulfilment, сохраняя действующую CSP. В этой проверке ошибок CSP/JS нет; политика приложения не ослаблялась.

Профильные тесты, web/admin typecheck и сборка админки прошли. Итог общего `pnpm check` и числовой baseline фиксируются только в [TEST_COVERAGE](../TEST_COVERAGE.md). Применены impeccable, ux-audit, form-cro и Astro workflow; новые дизайн-решения не вводились. Браузерные сценарии проверяют необходимость полей, явное согласие, восстановление, единственный modal и доступность действий, но не измеряют конверсию.
