# Статическая проверка Hero A

Статус: node --check пройден; root отрендерил4 варианта, автор выполнил визуальную проверку всех4 PNG. Результат и обязательное исправление общего CTA-tail — в review.md.

- SOURCE.widgets[0].text передаётся целиком H1.
- SOURCE.widgets[1].paragraphs[0] передаётся целиком lead, [1], [2], [3] — отдельным панелям; ни один не скрыт и не превращён в шаг.
- SOURCE.widgets[3].text передаётся целиком подписи IMG-0.
- SOURCE.widgets[4].text и links[0].href используются для linked primary UI Library button.
- IMAGES[0] используется через figure, пропорции 469×486 сохранены, scaleMode FIT.
- Все четыре пути buildVariant возвращают COMPONENT. Ширины1360/720/358/288; gap/padding/radius/color — текущие связанные переменные. H1 — специальные Heading/Page styles, body — Body/Medium.
- Нижняя композиция D:1280=800+32+448. T:672=352+32+288. M358: внутренний358, padding предметной зоны20 => изображение318. M320: внутренний288 => изображение248. Фиксированные ширины рассчитываются до FILL, текст автоматически растёт по высоте.
- Primary CTA на Mobile располагается сразу после H1 и gap16; полный вводный абзац остаётся следующим. На Desktop primary является отдельной видимой частью верхней строки.
- Семантический порядок Mobile намеренно CTA → lead → иллюстрация → пояснения. В реализации изображение имеет альтернативный текст IMAGES[0].alt; растровая форма не фокусируется.
- Нет переключения страниц, Figma/API-вызовов на выполнение скрипта, изменений сохранённого hero, общих мастеров или сборки итоговой страницы.

После рендера проверить actual PNG D/T/M/320: ширины, читаемость H1/body, перенос CTA в288, полные тексты, подпись/увеличение под своим изображением, отсутствие клиппинга и ложной формы; font family Geist и реальные bound variables подтверждает координатор. Клавиатура, screen reader, увеличение текста и работа URL/zoom требуют соответствующего прототипа/реализации.
