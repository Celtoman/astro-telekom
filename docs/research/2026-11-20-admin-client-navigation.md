# Переходы внутри админки, #627

20 ноября 2026. Сравнение после первого пакета ускорения API. Исходный код `d281e643` переключал раздел после получения и подмены целевого HTML. В новой сборке известные маршруты переключаются через History API в общем `AdminWorkspace`. API по-прежнему загружает данные каждого раздела. [Исходный замер во внешнем контуре](https://github.com/Celtoman/astro-telekom/issues/627).

## Локальные замеры в браузере Codex

На одном HTTP fixture с синтетической сессией проверено по 30 переходов на маршрут для каждой сборки. Метрика измеряет отклик от активации ссылки до изменения `document.title`. Для исходной сборки фиксировались события мыши, для новой применялась программная активация тех же ссылок в браузере с ожиданием кадров между переходами. Числа показывают порядок времени и отделяют переход от загрузки таблиц. Они не характеризуют сетевое время внешнего контура или время появления данных.

| Маршрут | p50 исходного, мс | p95 исходного, мс | p50 нового, мс | p95 нового, мс |
| --- | ---: | ---: | ---: | ---: |
| Города | 33,8 | 69,9 | 26,9 | 44,3 |
| Тарифы | 41,7 | 85,9 | 14,2 | 20,9 |
| Новости | 32,8 | 37,5 | 11,1 | 14,9 |
| Публикация | 33,6 | 38,8 | 10,9 | 21,6 |

Журнал HTTP fixture позволяет сверить запросы HTML независимо от окна событий Chrome DevTools. В исходной сборке на обычном переходе запрашивался HTML целевого маршрута. При клиентских переходах новой сборки остались запросы к API и загрузка JS-модулей по необходимости. Отдельно найден переход из свёрнутого меню React Aria, который открывал новый документ. После подключения RouterProvider к общему guard он перестал загружать целевой HTML.

Проверены переход из списка с `returnTo` в редактор новости, сохранение введённого текста при отмене ухода, отмена и подтверждение «Назад», возвращение «Вперёд» по исходному URL и отдельный запрос документа `/preview`. В браузерной консоли на этих сценариях не было ошибок и предупреждений. В итоговой сборке проверены перенос фокуса на якорь публикации, закрытие меню на ширине 390 px, баннер при несовпадении версии с последующим запросом нового HTML и возврат на отдельный экран входа после 401. Прямые URL и границы CSP проверяет сборка статических документов.
