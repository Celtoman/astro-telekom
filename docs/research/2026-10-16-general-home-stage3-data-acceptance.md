# Общая HOME — подготовка рабочих данных, этап 3

Дата: 16 октября 2026 года. Учёт: [#344](https://github.com/Celtoman/astro-telekom/issues/344), исправление аудита [#345](https://github.com/Celtoman/astro-telekom/issues/345). Основание: [утверждённый план](../plans/2026-10-16-general-home-implementation-plan.md) и последующее автономное поручение владельца.

## Изменения

`0061_general_home_composition` переводит только известные рабочие HOME провайдера domru с Hero2.0.0 на десять согласованных блоков. Сохраняет Hero, его ID, контент и titleTemplate. Неизвестный состав или версия останавливают всю транзакцию. Существующие SitePublication, publishedRevision, CITY_HOME и другие провайдеры не меняются. Изменение получает системную before/after revision и audit; повторный запуск сохраняет правки и не создаёт ревизий.

Начальные данные девяти блоков хранятся в `apps/api/src/assets/general-home-v1.json`; defaults возвращает независимую копию. JSON в неизменяемой SQL-миграции сверяется тестом с этим источником. Свежий seed создаёт ту же композицию, повторный seed не перезаписывает данные владельца. FAQ остаётся пустым черновиком, поэтому новая HOME не проходит публикационную проверку до внесения настоящих ответов. Демовопросы/ответы, числа городов и телефоны из картинки не загружаются.

Две иллюстрации и шесть логотипов перенесены из утверждённых Figma Screens в `apps/web/public/images/general-home/`. Временные MCP URL не становятся публичными ссылками. SVG — прямой экспорт исходных логотипов без перерисовки; блоки не превращены в картинки. [Снимок текстов и геометрии D/T/M](evidence/2026-10-16-general-home-data/figma-content.json) фиксирует источник переноса; это не доказательство готовой вёрстки.

При проверке аудита подтверждён #345: dotted paths ранее читались как буквальные ключи. Теперь вложенные поля и data массивов сохраняют действительные значения до/после, отсутствующие значения — null; чтение прототипов запрещено. Старые события не переписываются.

## Проверки

- API lint и сборка завершились успешно.
- Профильный набор `general-home-data`, `publication-workflow`, `seed`: 20 тестов, без падений и пропусков.
- PostgreSQL18 rehearsal `scripts/rehearse-general-home.mjs`: отказ без частичной записи, два целевых сайта, чужой провайдер, сохранённый Hero/CITY_HOME/снимок, before/after история, атомарный HTTP-controller save с реальным актором, stale409, повтор без дублей/потери правок, неизвестная версия. Используется только собственный временный контейнер.
- Seed rehearsal дополнительно подтверждает блокировку новой HOME пустым FAQ и успешную проверку с явно синтетическим FAQ только внутри изолированной БД.
- Итоговый `pnpm check` прошёл полностью: lint всех workspace, Prisma validate, demo build и весь test suite. Точное общее количество ведётся в [TEST_COVERAGE](../TEST_COVERAGE.md). Первый запуск выявил устаревший migration head в документации (исправлен) и таймаут runtime rehearsal при параллельной нагрузке; runtime отдельно и полный итоговый повтор прошли.

Внешние рабочие данные и опубликованный сайт на этом этапе не изменялись. Перед deployment миграция должна применяться вместе с совместимым API/renderer и планом заполнения FAQ; код и контент публикуются разными действиями. Редакторы, публичная вёрстка и preview относятся к следующим этапам.
