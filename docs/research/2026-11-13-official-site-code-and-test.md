# OFFICIAL_SITE: перенос Screens в код

13 ноября2026. Задача [#589](https://github.com/Celtoman/astro-telekom/issues/589), [принятый план](../plans/2026-11-12-official-site-implementation-plan.md). Страница перенесена из Screens и активирована в [защищённом test-контуре](https://tv-internet-dom.ru/official-site-domru). Exact-SHA CI, code deployment, CODE и CMS-публикация успешны; опубликованная страница проверена во встроенном браузере на1440/834/390/320. Ограничения внешней проверки админки и реальных устройств перечислены ниже.

## Источник и границы

[Screens](https://www.figma.com/design/BdxNHlBVZWejREtOEIWDkI?node-id=1167-3):1440/834/390/320, фреймы1168:1797/1813/1829/1845. Двенадцать размещений сохранены. «Плюсы и минусы» перенесены с принятыми текстами, зелёной/розовой поверхностями и независимыми высотами групп; Figma не менялась.

Минимальный CMS редактирует SEO, H1/введение, главный официальный URL, семь фиксированных иллюстраций с alt/подписями и FAQ. Остальной контент/порядок/композиция закреплены в коде. Используются общие оболочка, AddressOnly и FLOW2. ACCOUNT ведёт на локальный маршрут; отсутствующие разделы сохраняют принятые внешние ссылки. Растровые изображения не превращаются в собственный магазин или конструктор.

Миграции0071/0072 подготавливают только рабочие данные, сохраняют authored content и immutable snapshots, проверяют canonical collisions. CODE прежнего snapshot не добавляет новый URL. Для его появления нужна отдельная успешная CMS-активация.

Неподтверждённые цены/доставка/охват и старые акции на иллюстрациях оставлены по прямому решению владельца только для защищённого test; [фактологическая граница](2026-11-12-official-site-fact-review.md), PF-206. Публичная актуализация и решение о реальном трафике остаются отдельными.

- Chromium/Edge157 и WebKit26.5:1440/834/390/320. Двенадцать размещений, семь загруженных растров, отсутствие горизонтального переполнения body, FAQ и оглавление. Максимальное отклонение высоты блока от Figma менее0,06px, вызвано округлением. Это сравнение геометрии, не заявление о побайтовой идентичности растеризации шрифтов.
- На мобильных реально пройдены все семь областей: menu, overview, services, regional, equipment, additional image, additional cards. Все3+5карточек показаны полностью, движение в обе стороны и вертикальный жест проверены. Chromium — native touch через CDP, WebKit — native wheel/keyboard. Кнопки карусели не добавлены.
- На десктопе и планшете оба движка дополнительно проверили нативные окна regional/equipment: край, возврат и ArrowRight. Четыре сочетания прошли.
- Дополнительные16проверок: четыре эталона плюс360/768/1024/1280 в двух движках. Проверены точные размеры всех карточек, центровка текстовых колонок, подписи у изображений и отсутствие обрезанного текста карточек.
- На четырёх эталонах отдельный стресс-прогон удвоил вычисленные font-size/line-height текстовых элементов official-page до изменения DOM. Карточки выросли по содержимому без обрезания, блоки не наложились, body не переполнился. Это синтетическая проверка устойчивости типографики, не native browser zoom и не сертификация доступности.
- Предпросмотр CMS сравнивался с runtime на восьми сочетаниях ширины/движка; геометрия совпала. Исправлены порядок стилей, собственные override оболочки, первое применение встроенных шрифтов и изолированный read-only вариант общей адресной формы. Прочие потребители AddressOnly не изменены.

В двух мобильных движках дополнительно проверены alternatives/no providers/technical error, повтор проверки, возврат фокуса и retry заявки с тем же submissionKey и сохранённым вводом. API полностью перехвачен синтетическими ответами; настоящих заявок/уведомлений не отправлялось.

Во время визуальной сверки исправлены центровка ограниченных колонок, перенос H1 на десктопе, цвет цифр конструктора и выделений в карточках услуг. Эти исправления воспроизводят Screens; принятые блоки не перепроектировались.

Браузерная эмуляция не заменяет физические устройства и проверку скринридером. Полная WCAG-сертификация не заявляется.

## Ограничения и отдельный остаток

- Вход в внешний интерфейс CMS через IAB остаётся непроверенным: HTML открывается после Basic Auth, но проверка сессии/POST входа зависает, последующая обычная навигация иногда даёт ERR_INVALID_AUTH_CREDENTIALS. Те же учётные данные через HTTP успешно читают рабочий editor source, review и publication-state. Авторизация приложения не менялась; альтернативный браузер владелец не разрешил. Внешняя визуальная проверка редактора/его iframe не объявляется выполненной. Их local runtime/preview-проверки остаются отдельным доказательством.
- В IAB проверены нативная колёсная прокрутка и клавиатура; физический touch-screen, устройства и screen reader не проверялись. Полный FLOW2 проверен локально с синтетическим API, без действительных лидов. Нового внешнего запроса покрытия/настоящей заявки ради QA не выполнялось.
- Preset320 в интерфейсе preview отсутствует, хотя renderer на320 проверен локально; находка PF-217 записана отдельно и не реализуется в рамках сохранения дизайна.
- Старые факты и акции разрешены только для защищённого test. Перед публичным выпуском нужна согласованная актуализация; готовность к реальному трафику определяет владелец.

Исходная рабочая папка и её посторонние незавершённые изменения сохранены. Выпуск находится в отдельной рабочей копии `astro-telekom-official-site`; перенос чужих MCP/infra-правок в коммиты этой задачи не выполнялся.
