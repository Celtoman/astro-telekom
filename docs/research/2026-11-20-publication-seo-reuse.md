# Повторная подстановка SEO при проверке публикации

Сравнение для [#638](https://github.com/Celtoman/astro-telekom/issues/638) от 20 ноября 2026 года. В рамках одной проверки рендер использует вычисленные title, description и Open Graph, если совпали маршрут, поля SEO-шаблона и исходные значения его переменных. При несовпадении выполняется обычная подстановка. Проверка полного набора шаблонов, предупреждения о длине и дублях между URL выполняются при рендере. Текст без фигурных скобок проходит через быстрый путь подстановки.

## Локальный замер

Сравнивались сборки NestJS до правки (`4e4e1162`) и после неё. Один процесс Node.js 24.22.3 загружал обе сборки. Для снимка CITY_HOME v3 с 207 городами, 3 805 тарифами и 4 018 URL измерялся один вызов проверки публикации с финальным рендером каталога. После двух прогревов каждой сборки выполнено девять измерений на сборку с чередованием порядка. Время снимка фиксировалось на `2026-11-20T07:00:00.000Z`. Источник синтетический, время загрузки БД, сети и сборки HTML в замер не входит.

| Метрика | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Полная проверка, медиана | 1 531,53 мс | 1 203,95 мс | −21,4% |
| Финальный рендер, медиана | 544,69 мс | 390,90 мс | −28,2% |
| SEO-подстановки в финальном рендере | 11 841 | 0 | −11 841 |

Отдельный прогон со счётчиком подтвердил число SEO-подстановок. При измерении времени счётчик отключался.

## Эквивалентность

До и после правки совпали полные объекты отчёта и каталога и их SHA-256. В каждом временном прогоне для CITY_HOME v3 проверялись те же хэши. Исходные снимки проверялись на неизменность.

| Сценарий | Результат | URL | Диагностики |
| --- | --- | ---: | ---: |
| CITY_HOME v3, включая городские и тарифные переменные | `PASSED_WITH_WARNINGS` | 4 018 | 413 |
| Исторический снимок с прежними блоками, шаблонами и `NOINDEX` | `PASSED_WITH_WARNINGS` | 11 | 6 |
| Исторический снимок с отсутствующими значениями SEO и неизвестной переменной тарифа | `BLOCKED` | 11 | 6 |
| Некорректный `indexState` шаблона без соответствующего маршрута | `BLOCKED` | 11 | 4 |

В контрольном сценарии замена имени города и текста SEO-шаблона в финальном рендере при прежних URL дала полный каталог, совпадающий с обычным рендером этого изменённого входа. Число подстановок составило 11 вместо 25 за счёт совпавших входов других маршрутов. Регрессионные тесты сверяют в том числе `relatedPath` предупреждений о дублях и отдельные координаты ошибок SEO и переменных.

Прошли сборка и проверка типов API, 41 тест проверки публикации, SEO, переменных, городского каталога и новостей, четыре проверки FAQ/cookie, включая Astro-сборку, и отдельный сценарий выборочной публикации FAQ/cookie на временной PostgreSQL 18.6. Для последнего сценария из изолированного Windows worktree команда миграции вызвана напрямую установленным Prisma CLI с тем же конфигом через временный локальный wrapper.

## Остаток проверки переменных

Подстановки текста с переменными по-прежнему вызываются в preflight и рендере. Их входы включают разные представления исходных данных и разные координаты диагностики. Пробное повторное использование значения по тексту и контексту в шести чередующихся запусках снизило медиану рендера с 192,69 до 175,93 мс и увеличило медиану полной проверки с 603,77 до 619,91 мс относительно одного быстрого пути для текста без скобок. Правка включает быстрый путь. Следующий эксперимент может измерить стоимость повторного разбора текста на токены при сохранении вычисления значений и диагностик для каждого вызова.
