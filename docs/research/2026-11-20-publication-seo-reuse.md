# Повторная обработка SEO и текстовых шаблонов при проверке публикации

Сравнение для [#638](https://github.com/Celtoman/astro-telekom/issues/638) от 20 ноября 2026 года. В рамках одной проверки рендер использует вычисленные title, description и Open Graph, если совпали маршрут, поля SEO-шаблона и исходные значения его переменных. При несовпадении выполняется обычная подстановка. Проверка полного набора шаблонов, предупреждения о длине и дублях между URL выполняются при рендере. Текст без фигурных скобок проходит через быстрый путь подстановки.

## Разбор текстовых шаблонов

В проверке и рендере одного снимка общий кеш содержит до 256 разобранных текстовых шаблонов. Он хранит литералы, определения переменных и порядок их употребления. Значения подставляются из текущего контекста, а предупреждения и записи об использовании получают координаты текущего поля. Для строк с ошибками синтаксиса сохраняется штатная обработка, включая порядок отказов и точную диагностику.

Готовые подстановки для текста с переменными требуют сравнения контекстов и восстановления координат. Пробный кеш результата по тексту и контексту на исходном корпусе увеличил медиану полной проверки с 603,77 до 619,91 мс относительно быстрого пути для текста без скобок. Прототип отдельного кеша отформатированных значений помог на насыщенном корпусе, на корпусе с уникальными тарифными текстами увеличил полную медиану с 1 476,98 до 1 556,50 мс относительно общего разбора шаблонов.

### Повторные операции в полном проходе SEO

На интегрированном коде `25446217` поиск города для SEO повторяется для каждого URL этого города. Кандидат запоминает в рамках одного полного прохода первый результат исходного поиска по точному slug. Для контрольного корпуса это до 207 поисков по списку городов вместо 4 012. Выбор первого тарифа и ошибки отсутствующего города или тарифа сохраняют прежний порядок. Рендер и отдельная проверка URL по-прежнему получают собственные данные.

Ключ дубля заменяет только группы из нескольких пробельных символов и одиночные пробельные символы, отличающиеся от обычного пробела. Исходный текст title и description, `trim()` и `toLocaleLowerCase('ru')` сохраняются. Регрессия сравнивает предупреждения и их `relatedPath` с прежним правилом на 289 комбинациях пробельных символов и строках с кириллицей, греческой сигмой и буквами с диакритикой. Отдельный сценарий подтверждает первый совпавший город и тариф, в том числе при дублирующих slug.

Для оценки полной длительности сравниваются две Linux-серии по 32 чередующиеся пары с исходником `4e4e1162` и одна отдельная серия с интегрированным `25446217`. Обе исходные серии должны показать 2× по p50 полной длительности. CPU и рендер записываются отдельно. На каждом измеренном полном вызове проверяется SHA отчёта и каталога, а на исходных контрольных сценариях также сравниваются полные объекты.
