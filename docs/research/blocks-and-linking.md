## 2. Как строится перелинковка

| Связь | Наблюдаемый пример | Предлагаемое правило |
|---|---|---|
| Федеральная главная → город | tarify-dom.ru, МТС | Поиск и список только опубликованных городов |
| Город → категория | МТС, Ростелеком, domru.store, provider-dom.ru | Ссылка формируется по идентификатору раздела и города |
| Город → якорная группа | tarify-dom.ru, dom-provider.online | Якорь существует в опубликованном шаблоне; не смешивать с URL категории |
| Категория → тариф | domru.store, Ростелеком, provider-dom.ru | Отбор только доступных предложений города, единый URL предложения |
| Тариф → альтернативные тарифы | tarify-dom.ru, МТС, Ростелеком, domru.store | Тот же город; сортировка по близости услуг/скорости/цене или ручной выбор |
| Категория → соседняя категория | дом.ru.com: интернет → ТВ | Перекрестные связи по сценарию, а не список всех разделов подряд |
| Услуга → тарифная подборка | МТС | Основное действие ведет к релевантной подборке или заявке |
| Карточка → список каналов | domru-internet.ru | Переход привязан к конкретному ТВ-пакету, если список зависит от пакета |
| Город → другие города | tarify-dom.ru и региональные блоки остальных | Учитывать регион и доступность раздела в целевом городе |
| Городская карта → карта другого города | domru.store: Челны → Казань | Сохранять тип текущего раздела при географическом переходе |
| Город → общая справка | МТС, дом.ru.com, provider-dom.ru | Явно отличать общую публикацию от региональной; не подставлять город в любой URL |
| Статья → коммерческая страница | На примерах подтверждены переходы к статьям; обратное направление изучено не полностью | Для нашего сайта назначать релевантные услуги/категории, не обещать наличие этой логики у конкурентов |
| Город → общий фильтр каталога | domru-internet.ru | Региональный контекст должен сохраняться явно и проверяться при прямом входе |
| CTA → всплывающее окно | tarify-dom.ru, internet-tv-dom.ru | Это действие интерфейса; не учитывать как самостоятельную SEO-страницу |
| Город → HTML-карта → раздел/тариф | МТС, Ростелеком, domru.store | Карта обновляется из того же набора опубликованных страниц |

### Разные типы адресов нельзя смешивать

- `/kazan/internet/` — самостоятельная страница, если открывается с собственным содержимым.
- `/kazan/#internet` — якорь внутри документа.
- `/kazan#/p/zayavka` — состояние интерфейса/маршрут на клиенте; назначение устанавливается просмотром.
- `/tour-item/?type[0]=internet` — параметризованный каталог.
- `/tour-item/tarif-giga-300-a11/` — самостоятельная карточка вне городского префикса; при этом ее содержание может быть городским.
- `kazan.example.ru/tarify` — город в поддомене. В данной выборке содержимое такого примера осталось за reCAPTCHA.

Количество пунктов меню не равно количеству независимых страниц. Один и тот же адрес может повторяться в шапке, теле и подвале. Ссылка с фрагментом не доказывает существование целевого блока. Ссылка на страницу не доказывает успешную загрузку самой страницы.

| Категория тарифов | Выбрать пакет заданного типа | Отфильтрованные карточки, таблица, критерии выбора, стоимость, оборудование, FAQ |
| Посадочная услуги | Разобраться в услуге и подключении | Описание, проверка адреса, условия, популярные тарифы, оборудование, этапы, FAQ |
| Карточка тарифа | Проверить точные условия | Цена/срок акции, состав, платежи, оборудование, ограничения, заявка, альтернативы |
| Акции | Найти подходящую действующую акцию | Условия, сроки, применимые города/тарифы, CTA |
| Проверка адреса | Узнать доступность или заказать проверку | Адресная форма, результат либо объяснение ручной проверки, применимые тарифы, FAQ |
| Поддержка/контакты | Найти нужный канал обращения | Подключение и обслуживание отдельно, контакты, полезные ссылки |
| Оборудование/пакет каналов | Изучить состав продукта | Характеристики, варианты оплаты/совместимость, связанные тарифы |
| Статья/справка | Ответить на конкретный вопрос | Содержание, основной текст, связанные материалы и услуги |
| HTML-карта города | Найти любой опубликованный раздел | Группы страниц, категории, тарифы, переходы к другим городам |

Шаблоны — предложение, не обязательный список публикаций для каждого города. Создавать только те страницы, для которых есть содержимое и доступные предложения. Перестановка блоков не должна требовать копирования всей страницы.

## 4. Важные нюансы для данных и админки

1. **Тарифная линейка и предложение в городе раздельны.** Одинаковое название может иметь разные скорость, состав, цену, оборудование и акции. Все витрины ссылаются на одно региональное предложение.
2. **Промоусловия структурированы.** Обычная цена, цена периода, длительность, даты действия и условия участия — отдельные поля. «Скидка при покупке роутера» не должна исчезать из краткой карточки.
3. **Минимальная цена имеет правило расчета.** Указывать, учитывается ли акция, ТВ без интернета, оборудование и разовые платежи. Сводка не должна противоречить каталогу.
4. **Город берется из контекста страницы.** Баннер, H1, форма, телефон и внутренние ссылки не должны определять его независимо. Для геоназваний нужны регион, тип населенного пункта и грамматические формы.
5. **География и область действия контента — явные поля.** Общая инструкция может быть одна на весь сайт; тариф, адрес подключения и местный офис — привязаны к городу.
6. **Наследование прозрачно.** Сайт → шаблон → регион/город → конкретная страница. Редактор видит источник каждого значения и переопределения. Удаление переопределения возвращает наследование.
7. **Связи через сущности, а не вставленные вручную URL.** Страница хранит связь с категорией, городом, тарифом, оборудованием. При смене slug ссылки обновляются, прежний URL учитывается в редиректах.
8. **Городское меню зависит от публикаций.** Недоступную услугу не показывать как доступную; при переключении города переходить к соответствующему разделу, а при его отсутствии — к явному состоянию выбора/главной города.
9. **Категория и фильтр раздельны.** Пользовательский фильтр может существовать без отдельной индексируемой посадочной. Не создавать автоматически все сочетания скорости, цены, ТВ и аудитории.
10. **Контакты разделены по назначению.** Подключение, техподдержка, бизнес и офисы — разные источники; подпись кнопки должна соответствовать получателю обращения.
11. **Заявка сохраняет контекст.** Город, URL страницы, предложение, категория услуги, тип объекта и версия показанных условий. Реальная интеграция с CRM/почтой определяется отдельно.
12. **Проверка адреса должна соответствовать возможностям backend.** Без базы покрытия/API — заявка на ручную проверку; не показывать выдуманное подтверждение доступности.
13. **Дата обновления связана с данными.** Разделять дату изменения текста, проверки тарифа и проверки покрытия. Не обновлять «базу адресов» только потому, что сменился месяц.
14. **Отзывы и офисы не генерируются для видимости наполнения.** Нужны источник и применимость; общие отзывы не представлять как отзывы жителей конкретного города без оснований.
15. **Городские карты генерируются автоматически.** Они должны отражать публикацию и доступность, а не быть отдельным вручную поддерживаемым списком.
16. **Предпросмотр и история.** Черновик, просмотр в городе, список затронутых страниц перед массовым обновлением, возможность отката и журнал изменений.

## 5. Наблюдения, которые не нужно копировать

| Наблюдение | Статус | Проектное следствие |
|---|---|---|
| Москва в баннере страницы Казани dom-provider.online | Повторно видно в текущем проходе | Один источник городского контекста |
| 560 руб. в карточке ТВ и 385 руб. в нижней сводке дом.ru.com | Зафиксировано ранее в этой же задаче | Таблицы и сводки из той же базы предложений |
| Заголовок МТС «в других городах Москвы» | Видно в текущем проходе | Проверять шаблон географической фразы и тип региона |
| Регион на федеральной странице Ростелекома отличается между просмотрами | Наблюдение; механизм не установлен | Проверять прямые городские URL и отдельную логику федерального входа |
| Общие URL категории и тарифа domru-internet.ru показывают Казань | Проверено в последовательной сессии | Не полагаться только на URL при анализе; для своей системы явно задать региональный контекст |
| Пустой document.title карточки provider-dom.ru | Наблюдение DOM; серверный HTML не проверен | Проверка обязательных метаданных при публикации |
| Несколько одинаковых H2 «Заявка» в DOM карточек | Не доказанный визуальный дефект | Не считать скрытые/адаптивные элементы отдельными блоками страницы |
| Меню с якорями на вложенной странице дом.ru.com | Цели якорей не проверены | Добавить проверку существования целевого блока |

## 6. Проверяемые критерии для будущей реализации

Это предложения к следующему этапу, а не отчет об уже реализованных функциях.

- Изменение цены предложения обновляет карточку, сравнение, страницу тарифа и применимые сводки города.
- Снятый с публикации тариф исчезает из выдачи, рекомендаций и HTML-карты по согласованному правилу; его URL получает отдельно выбранное поведение.
- На странице Казани город в H1, форме и внутренних городских ссылках остается Казанью при прямом входе.
- Переключение города на странице категории ведет к той же категории целевого города, если она опубликована.
- Общая страница справки не размножается автоматически по всем городам.
- Переименование slug сохраняет корректность внутренних ссылок и позволяет настроить редирект.
- На странице без акции не выводятся пустые промополя и недостоверные сроки.
- Таблица каналов и количество каналов используют один актуальный пакет данных.
- Предпросмотр показывает итог наследования и перечисляет страницы, которые затронет массовое изменение.
- Навигационные ссылки, якоря и действия открытия окон различаются в редакторе и проверяются соответственно.
