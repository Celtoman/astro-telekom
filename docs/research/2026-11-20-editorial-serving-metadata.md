# Проверенные метаданные опубликованных новостей

Чтения списка, категорий, связанных материалов и выбранной поверхности предпросмотра используют версию проекции из [#635](https://github.com/Celtoman/astro-telekom/issues/635), когда она подготовлена и включена. Основа проверки и первого набора точечных читателей описана отдельно. [Проекции каталога](2026-11-20-serving-catalog-projections.md)

PostgreSQL берёт ID, сайт, ревизию, releaseSequence, поколение и точный `validationId` из одной строки `SitePublication`. В том же SQL statement он связывает текущее поколение с проекцией, проверяет ожидаемый digest прямого `/active` и получает результат по `SitePublicationValidation.id`. Допустим фактически активированный RUNNING до SQL acknowledgment. После замены `catalog` и `validationId` под прежним ID старое поколение перестаёт быть доступным по триггеру из миграции 0080.

Список, категории и связанные материалы получают только результат существующей редакционной выборки. Предпросмотр дополнительно получает поля сайта, краткие сведения о городах и нужные маршруты оболочки. PostgreSQL извлекает эти поля из JSONB, а API проверяет оболочку прежними правилами. При отсутствии пригодной оболочки исторический renderer получает исходник по уже выбранному `validationId`. Полный исходник для публикации по-прежнему использует `editorialServingSource`.

Если проекция отсутствует или неполна, API проверяет полный каталог по тому же захваченному ID и читает исходник по его `validationId`. Расхождение известного digest останавливает чтение. Список сохраняет прежний ответ `publishedAvailable: false` при недоступной проверке. Предпросмотр возвращает ошибку. Для этого пакета достаточно схемы миграции 0080.

## Локальный профиль

Сравнение выполнено на PostgreSQL 18 с синтетическим каталогом из 207 городов, 3 933 тарифов и с исходником из 36 новостей. Оба режима прочитали один снимок. Для каждого сценария выполнены два прогрева и 12 чтений. Байты измерены на сокете PostgreSQL. p95 измерялся по вызову серверного читателя с локальным HTTP `/active`, обработкой результата и сверкой digest. Режим полного чтения передавал 24 943 968 байт каталога и отдельный SQL-ответ редакционного списка или предпросмотра.

| Сценарий | Байты полного чтения и SQL-ответа | Байты с подготовленной проекцией | p95 до и после, мс |
| --- | ---: | ---: | ---: |
| Список, 10 выбранных записей | 24 948 456 | 4 967 | 1 055 → 217 |
| Предпросмотр статьи с оболочкой | 24 950 700 | 39 694 | 1 278 → 821 |
| Сводка опубликованных категорий | 24 944 244 | 706 | 2 380 → 419 |

Выбранные записи, оболочка предпросмотра и сводка категорий совпали между режимами. Предпросмотр по-прежнему требует извлечения полей оболочки из JSONB и остаётся дороже списка. Проверки на отдельной БД подтвердили исторический ID через доверенный контекст, RUNNING до ACK, отказ при неверном digest, fallback на исходный `validationId` после удаления строки проекции и переход на новое поколение после замены каталога с `validationId`. Уже выбранный исторический исходник остался доступен по прежнему `validationId`.
