## Задача и метод

Интегрировать принятые список новостей C, статью A и 404 из [Screens](2026-11-06-active-screens-owner-acceptance.md), включая удобное управление содержимым. Пользователь один, добавление ручное, несколько публикаций в месяц, новости без регионов.

Применены `grilling`, `product-design-and-ux`, `interaction-design`, `web-accessibility`, `schema-markup`. Изучены официальные материалы Ghost, WordPress, Sanity, React Aria, W3C, Open Graph и обязательный dashboard-референс. Это исследование документации и проектные выводы, а не пользовательское тестирование или визуальная приёмка ещё не созданной админки.

## Сценарии: подтверждённые направления и детали проектирования

Q22–Q24 подтверждены после первого исследования. Дополнительные детали безопасности, API и хранения уточняются в исполнимом контракте; остальные предложения таблицы не выдаются за отдельные ответы владельца.

| Ситуация | Предлагаемое поведение |
| --- | --- |
| Неполный материал | Автосохранение черновика разрешено. Обязательные для публикации поля проверяются перед выпуском, а не мешают начать писать. |
| Ошибка автосохранения | Постоянное сообщение с повтором, время последнего подтверждённого сохранения; набранный текст остаётся. Не показывать «Сохранено» до ответа сервера. |
| Две вкладки | Принято Q22: конфликт не перезаписывает молча сервер или текущий текст; показываются сохранённый и свой варианты. Даже одному администратору этот сценарий возможен. |
| Истёкшая сессия | Ввод сохраняется в текущем состоянии; повторный вход и восстановление не должны молча сбрасывать форму. Q22 принимает локальное восстановление и удаление копии после успешного сохранения; изоляция аккаунтов, срок и очистка при logout описываются в техническом контракте. |
| Выпуск | Показать точную сохранённую версию и затронутые представления. Новая категория может быть явной зависимостью выбранной новости; посторонние черновики не включаются. |
| Нет ответа на запуск выпуска | Проверить состояние уже созданной операции; не запускать новую публикацию вслепую. «На сайте» — только после подтверждения результата. |
| Ошибка проверки | Русское объяснение, ссылка/фокус на поле; различать запрет публикации и рекомендацию. Счётчик длины SEO сам по себе не блокирует выпуск. |
| Медиа | Незавершённая загрузка видна, её можно повторить/отменить. Сохранённая публичная версия файла не заменяется по тому же адресу из черновика. Используемые опубликованные файлы нельзя удалить без проверки связей. |
| Восстановление редакции | Принято Q23: опубликованные версии и последние20 контрольных черновиков. Просмотр изменений → восстановить в черновик → предпросмотр → отдельная публикация. |
| Узкий экран и клавиатура | Контент идёт до настроек; верхняя панель не закрывает фокус/поле. Видимые подписи, доступные действия без hover/drag, возврат фокуса из модалок. |

## Open Graph и Schema

Владелец включил оба направления в объём. Следующие детали — проектное предложение реализации, не выполненная проверка.

- [Open Graph](https://ogp.me/): статья получает `og:type=article`, список и категория — `website`; `og:url` соответствует canonical. Используются заголовок, описание, абсолютный URL изображения, его alt/размеры, название сайта и locale. Даты и рубрика статьи формируются из опубликованных данных.
- Предлагаемый fallback текста: индивидуальный OG → индивидуальный/шаблонный SEO → заголовок и анонс. Изображение: отдельное социальное → обложка → штатное изображение сайта. Общая запасная социальная картинка не выдаётся за фотографию события в Schema.
- В админке отдельная группа «Социальные сети»: автоматические значения, необязательные переопределения, сброс к автоматическим и приблизительный preview карточки. Реальный внешний сервис управляет собственным отображением/кешем.
- Новостная статья: `NewsArticle` по содержанию, категория `articleSection`, реальные автор и издатель, опубликованные даты с timezone; другие редакционные типы не маскируются под новости. [Google Article](https://developers.google.com/search/docs/appearance/structured-data/article).
- Общий список и категория: [CollectionPage](https://schema.org/CollectionPage) и [ItemList](https://schema.org/ItemList) видимых материалов. [BreadcrumbList](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb) соответствует реальной иерархии. Один связанный граф без дублирующих независимых сущностей страницы.
- Каждая страница пагинации имеет свой canonical и настоящие ссылки; она не канонизируется на первую. [Google Pagination](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).
- Черновики не попадают в публичный sitemap/Schema/подборки. 404 не получает Article/NewsArticle или разметку несуществующего материала.
- Проверка JSON-LD и применимых Google типов входит в будущую приёмку; успешный валидатор не гарантирует расширенный результат. [Правила Google](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

## Будущая проверка UX

Проверить сценариями: создать и прервать черновик; вернуться из списка; исправить опубликованную новость; заменить обложку без изменения живой; создать категорию; открыть вторую вкладку; потерять сеть/сессию; восстановить редакцию; опубликовать ровно выбранный материал; снять и повторно выпустить; проверить все четыре preview и метаданные итогового HTML. Отдельно клавиатура, фокус, сообщения скринридера, zoom/reflow, светлая/тёмная тема admin. Реальные сессии с участниками не проводились и не заявляются.
