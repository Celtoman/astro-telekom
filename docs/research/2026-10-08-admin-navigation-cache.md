# Ускорение повторных переходов админки

Дата: 8 октября 2026 года. Работа согласована владельцем в [#271](https://github.com/Celtoman/astro-telekom/issues/271), исходная находка — [#270](https://github.com/Celtoman/astro-telekom/issues/270). Локальные и внешние проверки фиксируются отдельно; числа не являются SLA.

## Контролируемые browser-замеры

Сравнены две production-сборки admin с одинаковыми read-only копиями внешних ответов и искусственной задержкой каждого API 450 мс. Browser fixture обращается только к локальному серверу; реальный каталог не изменяется. Готовность — появление таблицы и правильного заголовка раздела, включая готовые строки из памяти. Серверная revalidation после этого продолжается и показана оператору.

Три повторных перехода на каждый раздел, медианы:

| Раздел | До, мс | После, мс | Серия до | Серия после |
| --- | ---: | ---: | --- | --- |
| Города | 719 | 122 | 569, 997, 719 | 132, 122, 97 |
| Тарифы | 687 | 232 | 598, 887, 687 | 232, 111, 244 |

При повторном открытии появился статус обновления, затем «Данные обновлены». Отсутствие завершённых resource timing entries в момент появления cached rows не означает отсутствия запросов: проверка идёт в фоне. В исходной серии были long tasks до 184 мс; в повторной серии новой сборки зарегистрированных long tasks до готовности не было. Первый переход без данных всё ещё ждёт API: новая серия дала 994 мс для холодного открытия городов и 862 мс для первого открытия тарифов. Улучшение холодного старта этими двумя наблюдениями не доказано.

## Серверные чтения и эквивалентность

До изменений внешние read-only GET, медианы трёх последовательных измерений: tariff list 705 мс, city list 902 мс, first-screens 1651 мс, variable-catalog 1712 мс. Включены сеть, guard/proxy, чтение тела и сервер; это не SQL-duration и не время интерфейса в cookie-сессии владельца.

SQL проверен на отдельной PostgreSQL 18: большой синтетический каталог, пять контекстов выбора города/тарифа, latest SUCCEEDED вместо следующей PENDING publication, параметризованный slug/site boundary, legacy source/usage evidence и HOME fallback. Проекции дают тот же variable DTO, не переносят тарифы других городов и полный publication snapshot в Node. Скрипт удаляет только созданный им контейнер. Immutable catalog в рабочем контуре не изменяется.

## Границы

Кэш находится только в памяти вкладки и ограничен текущей проверенной сессией, возрастом 30 секунд и 32 ответами. Fresh editorial reads, optimistic revisions и unsaved guard сохраняются. Внешние mutation/import/publish сценарии не подменяются локальными mocks. Завершение публикации наблюдается по publishedRevision; повторное открытие всё равно читает сервер. Массовый data-prefetch не добавлен, [#266](https://github.com/Celtoman/astro-telekom/issues/266) остаётся отдельной находкой.

Полный локальный pnpm check завершился успешно. Cache/revalidation, mutation boundaries, TTL, logout/401 и поздние ответы проверены автоматическими fixtures. Повторная интерактивная проверка unsaved guard остановилась на нативном диалоге, которым инструмент не смог управлять; browser-save/conflict сценарий не объявляется подтверждённым. Встроенный браузер блокирует внешний домен (ERR_BLOCKED_BY_CLIENT), внешний browser E2E не выполнен. CI, exact deployment и внешняя эквивалентность будут добавлены после проверки.
