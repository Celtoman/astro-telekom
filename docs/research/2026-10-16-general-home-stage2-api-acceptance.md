# Общая HOME — локальная приёмка API и каталога, этап 2

Дата: 16 октября 2026 года. Учёт — [#344](https://github.com/Celtoman/astro-telekom/issues/344). Следующее прямое поручение владельца разрешило автономно завершить все этапы, создавать коммиты, push и deployment; прежняя граница только этапа 1 отменена.

## Реализовано

- Guarded GET/PATCH `/api/v1/admin/sites/:siteId/page-templates/general-home` в существующем AdminPageTemplatesController. Полный состав10 блоков, safe draft, сохранение существующих ID/позиций, serializable-транзакция с expectedWorkingRevision, одна attributed working revision/before-after audit; 409 при stale/P2034. Системные поля/версии не принимаются с клиента.
- `general-home-template.ts`: явная версия включает только известный состав/implementation с Hero2.0.0. Неверные позиции/ID/состав/версии отклоняются. Старый unversioned Hero остаётся прежним; новые блоки без версии не игнорируются молча.
- Рабочая и опубликованная HOME раздельны. SQL читает immutable sourceSnapshot и catalog.generalHome; при отсутствии нового опубликованного состава возвращается null. Каталог без исходного шаблона валидируется отдельно; неизвестная опубликованная версия не подменяется рабочими данными.
- `SiteCatalogService`: новый `catalog.generalHome`, общие системные connectionHours/callbackWithinMinutes, вложенные SITE-подстановки и usage-ссылки на конкретный блок. Значения проверяются после подстановки; исходный snapshot не изменяется. Hero в новой проекции использует тот же разрешённый контент, что совместимый catalog.homeHero.
- Publication preflight выдаёт GENERAL_HOME_NOT_READY для HOME/block/field/reason; ContentValidationError сохраняет block и в HTTP-теле. Неполный безопасный черновик сохраняется, но не становится публикуемым.
- Старый PATCH первого экрана сохраняет девять новых блоков/метаданные состава. Новых миграций, рабочих данных, редакторов, публичных блоков или выпусков этот этап не выполняет.

## Проверки

Новый suite `general-home-editor.test.cjs`:8 сценариев. Семь первоначальных сценариев подтвердили отсутствие новой функциональности; после реализации прошли. Дополнительный fallback-сценарий сначала обнаружил приём неизвестной опубликованной версии; после исправления проходит.

Профильный набор контрактов/API/публичного каталога прошёл без ошибок. Реальный PostgreSQL rehearsal admin read projections проверяет старые snapshots, полную новую HOME и legacy отсутствие sourceSnapshot. Полный `pnpm check` на итоговом коде прошёл: lint → db:validate → demo build → тесты, без failures/skips. Точное количество хранится в [TEST_COVERAGE](../TEST_COVERAGE.md).

Первый полный gate выявил прежние ожидаемые формы SQL/public Site и редакционную коллизию слова baseline с размерами макетов. Ожидания обновлены под новый контракт; исторические формулировки о Figma-сравнении уточнены без изменения значений/макетов. Правила CI и тестовые проверки не ослаблялись.

## Границы

Это локальная приёмка API. Действующие рабочие данные ещё не имеют полной композиции; до следующего этапа новый GET честно отвечает404. Внешний HTTP/save, браузерный редактор, визуальная приёмка новых блоков и deployment будут проверены при внедрении следующих этапов. Старые immutable публикации не переписывались.
