# Расход DaData в astro-telekom — 19 октября 2026

Статус: read-only аудит реализации, текущего runtime и сохранённых данных. Код и runtime-конфигурация astro-telekom не менялись. Отдельная техническая находка об учёте расхода: [#353](https://github.com/Celtoman/astro-telekom/issues/353).

## Какие действия вызывают API

| Сценарий | Путь к DaData | Что расходует |
|---|---|---|
| `POST /api/v1/address-suggestions` | `DadataService.suggest` → `suggest/address` | Один запрос «Подсказок» на каждый принятый запрос к маршруту |
| Тот же маршрут без cookie `address_city_kladr` | Дополнительно `DadataService.locate` → `iplocate/address` | Ещё один запрос «Подсказок», если IP задан и не локальный |
| `POST /api/v1/address-checks` с выбранной подсказкой | `DadataService.clean` → `clean/address` | Платная стандартизация, отдельная от суточного лимита «Подсказок» |
| Фоновое решение по заявке | `DadataService.cleanPhone` → `clean/phone` | Платная стандартизация телефона |

Простое открытие страницы не вызывает IP Locate: он вызывается из контроллера подсказок после ввода адреса. Текущая версия использует официальные API paths `suggestions/api/4_1/rs` и `cleaner/api/v1`.

## Что уже ограничивает расход

- Ввод начинает поиск с трёх символов, debounce 500 мс.
- В браузере есть кэш 20 нормализованных запросов внутри экземпляра формы и отмена предыдущего fetch.
- `credentials: include` передаёт cookie города; контроллер устанавливает её на 86400 секунд, включая значение `none` для неуспешного определения. При корректной cookie повторный IP Locate не выполняется.
- Специализированный rate-limit по умолчанию — 60 запросов в минуту на IP. Это ограничение не является общим суточным бюджетом аккаунта DaData.
- Серверного кэша suggest/locate и отдельного счётчика исходящих запросов в текущем DadataService нет. Отмена браузерного запроса не гарантирует отмену уже начатого backend-вызова DaData.

Значение DADATA_TOKEN совпадает с domru-smart-bot; сравнение выполнено без вывода секретов. Историческая статистика получена непосредственно через DaData `get_daily_stats(date=...)`; даты ответов проверены. Логи бота за 11–15 октября покрывают полные сутки, MSK.

16 октября у бота 0 вызовов «Подсказок», у аккаунта — 4165. Это доказывает расход вне проверенного процесса domru-smart-bot, но не определяет конкретное другое приложение. Агрегированная статистика DaData не содержит разбивки по приложению; доля astro-telekom исторически не установлена.

По платной стандартизации отдельная сверка согласуется с текущей БД: 14 октября аккаунт показывает 28 записей, бот — 25, в astro-telekom сохранены 3 AddressCheck. Это согласование величин, а не независимая атрибуция каждого биллингового запроса.

В ходе аудита не выполнялись платная проверка адреса и создание заявки. Основная задача дальнейшего наблюдения и критерии для отдельного учёта зафиксированы в [#353](https://github.com/Celtoman/astro-telekom/issues/353).
