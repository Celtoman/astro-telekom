# Компактное чтение каталога городов, #628

20 ноября 2026. [Исходный инцидент](https://github.com/Celtoman/astro-telekom/issues/628).

Список читал тарифные строки, историю ревизий и блоки HOME всех подходящих городов, хотя отдавал 25 строк. Теперь первый запрос получает данные города и агрегат действующих опубликованных тарифов. Последняя ревизия определяется через `MAX(siteRevision)`. Без фильтров готовности и неопубликованных изменений детальные чтения выполняются для выбранной страницы. При включении соответствующего фильтра вычисление происходит до пагинации. Общий шаблон HOME читается и валидируется один раз за запрос. Для городов с локальной исторической HOME сохраняется проверка активных блоков. Вся выдача читается в одном снимке PostgreSQL через Repeatable Read. Формат запроса, ответа и курсора сохранён.

## Проверка корректности

На PostgreSQL 18.6 применены все 78 миграций. Синтетический набор содержит 207 городов двух сайтов, 3 920 тарифов, 1 720 ревизий и 191 HOME, из них 12 с локальными блоками. Сравнены полные ответы прежнего обработчика и нового для 166 страниц в 32 вариантах. В набор входят русский регистр и буква «ё», совпадающие ключи сортировки, статус города, регион, готовность, наличие профиля и тарифов, неопубликованные изменения, пустые результаты и последовательность курсоров. Отдельный регрессионный тест проверяет переключение между чтением страницы и чтением для фильтра, один общий шаблон и локальную HOME версии 2.0.

## Замеры

Каждый сценарий на одном стенде выполнен 30 раз на сборку после прогрева. Таймер стоит вокруг вызова обработчика без HTTP, авторизации и обратного прокси. Число строк получено из `pg_stat_statements` по прикладным SQL-запросам и показывает строки, возвращённые PostgreSQL за один ответ. Для обычного списка среднее время выполнения SQL в базе составило 8,2 мс до изменения и 3,2 мс после. Адаптер Prisma включает обмен данными и обработку результатов, его p95 составил 62,5 и 40,6 мс. Отдельный `JSON.stringify` уже собранного списка занял 0,35 и 0,32 мс p95. p95 отдельных стадий рассчитаны независимо.

| Сценарий, 25 строк | p50 обработчика до → после, мс | p95 до → после, мс | SQL-строк на ответ до → после |
| --- | ---: | ---: | ---: |
| Первая страница по названию | 58,6 → 42,0 | 70,6 → 54,2 | 5 016 → 294 |
| Только готовые к публикации | 54,4 → 47,0 | 59,7 → 57,3 | 5 016 → 571 |
| Неопубликованные изменения, по числу тарифов | 49,5 → 32,0 | 55,9 → 35,8 | 5 016 → 435 |

Во встроенном браузере на внешнем коде `ec15d787` до выпуска три первых входа из свежего документа «Обзор» показали 1 336, 1 008 и 835 мс до первой строки. Заголовки ответа `GET /admin/cities` пришли за 984, 673 и 501 мс от отправки запроса. Повторный вход с данными в памяти вкладки показал первую строку за 43 мс. Ошибок и предупреждений в консоли не было. Эти замеры описывают отдельные проходы, p95 для внешнего контура по ним не вычислялся.
