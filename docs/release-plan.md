# План релизов и статус первого MVP

Этот документ группирует работу по релизным границам. [План от 21 сентября](plans/2026-09-21-target-platform-implementation-plan.md) сохраняет последовательность реализации, а [аудит от 24 сентября](research/2026-09-24-decision-implementation-reconciliation.md) — состояние на дату проверки. Текущие факты реализации описаны в [current-state.md](current-state.md), механические статусы задач — в GitHub Issues. Ранний [стабилизационный план](plans/2026-09-07-platform-stabilization-and-mvp.md) сохранен как исторический.

## Release 0 — локальный прототип

Статус: **реализован, но с известными ограничениями**.

- Monorepo, Docker Compose, Prisma migrations и seed.
- NestJS API, HttpOnly-cookie/совместимые Bearer-сессии с единым уровнем доступа администратора и CRUD базовых сущностей.
- Статический Astro-сайт с Release 1 route inventory, страницей каждого опубликованного города и detail каждого опубликованного тарифа этого города; service detail сохранены как будущие данные без URL.
- XLSX-import городов/тарифов с validate/apply reports.
- Прием лида, deduplication, contract check, delivery attempts и доставка в Tarifnik/email fallback.
- Static admin с рабочими каталогами и импортами тарифов/городов, заявками и редиректами; отдельный BullMQ worker обрабатывает доставки, оповещения, пересборки и PII retention.

Release 0 — историческая граница локального прототипа. После нее уже реализованы рабочие ревизии, audit, guarded undo импортов, корзина и расписание публикаций; универсального per-entity rollback и части эксплуатационных панелей по-прежнему нет. Защищенный внешний test-контур подтверждает deployment-механику конкретных ревизий, а решение о готовности к реальному трафику принимает только владелец. Demo fallback в public build требует явного `ALLOW_DEMO_DATA=true` и больше не срабатывает молча при недоступном API.

## Release 1 — минимальный публичный запуск

Цель: один реальный партнерский сайт Дом.ру с достоверным статическим HTML для каждого опубликованного города, наблюдаемой публикацией, безопасной обработкой лида и проверенным delivery sandbox. Казань остается тестовым городом раннего этапа, но больше не определяет структуру релиза.

Публичный состав фиксирует [каноническая структура сайта](site-structure.md): `/`, `/{location}` для каждого города канонического импорта, `/{location}/{tariffSlug}` для каждого опубликованного тарифа опубликованного города, карта покрытия, города обслуживания, три legal-страницы и общий шаблон 404. При `N` опубликованных городов и `T` их опубликованных тарифов это `N + T + 6` обычных HTML-маршрутов. Остальные контентные и service pages относятся к следующим релизам, даже если записи уже есть в базе.

Условия завершения:

1. Публичный output, sitemap, внутренние ссылки и redirects соответствуют exact составу `N + T + 6`; переход на городскую структуру, live-приемка HTTP 404 и возврат тарифных страниц завершены в [#136](https://github.com/Celtoman/astro-telekom/issues/136), [#141](https://github.com/Celtoman/astro-telekom/issues/141) и [#149](https://github.com/Celtoman/astro-telekom/issues/149). Live inventory после публикации ревизии 7 24 сентября — 207 городов, 3 805 тарифов и 4 018 уникальных URL. Legacy-дубли `HOME` устранены в закрытой [#150](https://github.com/Celtoman/astro-telekom/issues/150); актуальный deployed SHA проверяется отдельно.
2. Все automated checks green в чистом окружении.
3. Production build блокируется, если API-данные отсутствуют, origin не является чистым HTTPS origin или final SEO output не проходит проверку. API/origin fail-fast, post-build sitemap/raw HTML gate и воспроизводимый первый Coolify bootstrap [#55](https://github.com/Celtoman/astro-telekom/issues/55) подтверждены; внешний production CI/CD не должен разрешать demo mode.
4. Импорт тарифов имеет утвержденную полную семантику и не оставляет устаревшие публичные предложения.
5. Rebuild job имеет status/retry и подтвержденный результат HTML.
6. Fallback link безопасно открывает нужную заявку либо удалена из письма.
7. Админский вертикальный поток import -> apply в рабочую версию -> явная публикация -> deployment status показывает реальные данные.
8. Real/sandbox contracts DaData, Tarifnik `address/check`, Dom.ru `contract-asterisked`, Tarifnik `appeal/create` и email согласованы и проверены. Обычная форма и видимая проверка подключения разделены; delivery невозможен без обязательной проверки провайдеров и однозначного `contacts: []`.
9. Срок хранения сырых заявок 180 дней согласован и обеспечивается policy-driven purge.
10. `TARIFNIK_UTM_CAMPAIGN` переведен с test-метки на подтвержденное production-значение.
11. Встроенный PostgreSQL backup/restore не является критерием этого репозитория: владелец использует внешнее решение, а [#145](https://github.com/Celtoman/astro-telekom/issues/145) закрыта как `not planned`.

25 сентября на защищённом test-контуре выполнена [одна сквозная синтетическая заявка](research/2026-09-25-release-one-synthetic-lead-acceptance.md) через публичный API-путь с положительной проверкой адреса и расчётом тарифа: лид дошёл до `DELIVERED`, внешний Tarifnik подтвердил `created_duplicate` с `appeal_id`, обычное уведомление — `SUCCEEDED`. Это доказательство технического sandbox-пути на exact deployed SHA; интерактивная отправка кликом в браузере и перевод `TARIFNIK_UTM_CAMPAIGN` на production-значение не проверены. Milestone и открытые Issues остаются механическим источником статуса задачи, допуск трафика — решением владельца.

Отдельная перепроверка реквизитов и legal basis в [#144](https://github.com/Celtoman/astro-telekom/issues/144) имеет приоритет `P3`, находится вне milestone Release 1 и не является условием его завершения или решения о трафике. Эти сведения сохраняются как входные данные для владельца, который принимает решение о готовности к реальному трафику самостоятельно.

## Release 2 — расширенный контентный контур

Цель: добавить городские тарифные, сервисные и прочие страницы из полной структуры без hardcoded Казани и без нарушения release-aware публикации.

City HOME, published-only Release 1 sitemap, глобальная навигация, одношаговые HTTP 301 с CRUD/hit tracking и multi-city build smoke уже подчиняются явной релизной политике. Перед Release 2 эту policy нужно расширить отдельным решением, а не возвращать автоматическую публикацию всех `Page`/`Tariff` со статусом `PUBLISHED`.

## Release 3 — управляемая CMS и эксплуатация

Цель: дать редактору управляемые версии, шаблоны/блоки, аудит, историю импортов и эксплуатационные панели без demo UI.

Рабочие ревизии, audit log, отложенная публикация, корзина, типизированные переменные V1–V2 и SEO/OG-шаблоны S1–S4 уже реализованы раньше этой границы. C1 завершена в границах черновых паспортов без утверждения владельцем; C2 перевела городские HOME на общий шаблон. Остаются редакторы страниц и блоков C3–C5, очистка legacy-контента C6, финальное утверждение паспортов, завершение V3, media, analytics, monitoring и универсальный per-entity rollback. Проверка всех URL перед публикацией P1 реализована и развернута на внешнем test-контуре deployment `tuszecyovtkywimzjebxajwo`; 24 сентября первый реальный отчет `cmufiu1dl001q01uf4a33hqdb` проверил 4 018 URL без issues перед успешной публикацией ревизии 7. Backup/restore остается внешней эксплуатационной ответственностью владельца и не планируется как часть Release 1 или Release 3 этого репозитория. Для PII purge срок 180 дней уже согласован; низкоприоритетная перепроверка юридической основы ведется отдельно в #144.

## Внешние зависимости

Живые test-контракты DaData, обоих API Tarifnik, положительная/отрицательная семантика `contacts` Дом.ру и фактическая доставка синтетического письма Resend подтверждены; полный городской справочник, безопасная retry-политика, HTTP/contract-проверка и persistent outbox обычного уведомления реализованы. Миграция `0015`, worker и ручной retry outbox подтверждены на production-контуре: сохраненное уведомление перешло из `revision 1 / FAILED / HTTP 403` в `revision 2 / SUCCEEDED` с provider ID. Перепроверка реквизитов и legal basis остается низкоприоритетной задачей [#144](https://github.com/Celtoman/astro-telekom/issues/144), но не gate; [#31](https://github.com/Celtoman/astro-telekom/issues/31) закрыта решением владельца. [#145](https://github.com/Celtoman/astro-telekom/issues/145) отменена как ненужная для репозитория: backup/restore обеспечивает внешнее решение владельца. Изменение production campaign Tarifnik не входит в автономную работу агента и требует отдельного решения владельца. Дополнительных правил Tarifnik по rate limit и SLA владелец не получал; callback отсутствует.
