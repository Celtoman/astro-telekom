## Runtime/CMS-контракт

Актуальное согласование редактора ведётся отдельно в [контракте CMS](2026-11-17-support-cms-contract.md). Q10–Q17 подтверждены. При расхождении ранних предположений ниже с контрактом приоритет у явно принятых решений владельца. В частности, AddressOnly не получает локальных полей SUPPORT; самостоятельный FAQ первоначально использует ответы действующего городского FAQ.

- PageType/PageTemplateKind/SeoTemplateKind CITY_SUPPORT; единственный общий PageTemplate и городской Page-shell.
- Фиксированы IDs, порядок и типы13 контентных секций между системными Header/Footer. CMS редактирует заголовки, абзацы, шаги, ссылки, изображения и FAQ в заданной структуре. Геометрия, иконки и адаптивы системные.
- Городские формы берутся из существующего справочника и registry CITY_NAME / CITY_NAME_GENITIVE / CITY_NAME_PREPOSITIONAL. Пустые обязательные значения дают точную диагностику, а не подставленный выдуманный падеж.
- Основные телефоны/графики — Site-настройки; для корпоративного номера используется уже реализованная отдельная общая настройка. Выделенный местный номер не выдумывается из общего телефона.
- Изображения: точные отдельные Figma-исходники, именованные слоты src/alt/caption, валидируемый единый источник полного телефонного снимка и его выноски, immutable локальные assets. Полностраничные QA PNG не используются как UI.
- Сохранение меняет working revision с optimistic concurrency и ContentRevision; strict publication gate диагностирует недостающие поля.
- Сайт и admin preview используют один renderer/CSS; preview не отправляет реальные запросы.
- Интеграция проходит через storage/materialization/public catalog/variable usages/published template projection/API DTO/admin editor/public routes/SEO/sitemap/static build/publication assets.
- Новый город получает shell штатным путём, без самопубликации. Выпуск добавляет по одному SUPPORT URL для каждого опубликованного города выбранного снимка.
- Старые snapshots при CODE rebuild не расширяются и не получают новые SUPPORT URL автоматически.

## Действия и навигация

- Семь локальных якорей, нативная горизонтальная прокрутка чипов/карточек, корректная вертикальная прокрутка, клавиатура и видимый фокус.
- Все телефонные действия — tel; внешние официальные назначения и магазины сохраняются.
- Текстовые ссылки поддержки в общей оболочке ведут на городской URL; выбранный город и раздел сохраняются при смене города. Выделенный номер остаётся tel.
- AddressOnly сохраняет существующий address/lead-контракт; реальные тестовые заявки не отправляются без необходимости.
- FAQ использует существующий доступный disclosure-паттерн.

## Состояние исходного дерева

Основной checkout содержит чужие незавершённые изменения и индекс. Работа выполняется в отдельном detached checkout от актуального remote master, без новой ветки. Чужие файлы и индекс сохраняются; в push входит только подготовленная история поддержки поверх текущего master.

## Границы результата

Экспертная, автоматическая и браузерная проверка не объявляются пользовательским исследованием или полным WCAG-аудитом. Выпуск относится к защищённому test-контуру и не является решением о допуске реального трафика.
