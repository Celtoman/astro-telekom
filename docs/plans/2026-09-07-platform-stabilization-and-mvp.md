# Platform Stabilization and MVP — архитектурное обоснование

Статус: с 8 сентября 2026 этот файл — только обоснование состава и порядка задач. Пошаговые статусы, чек-листы и текущий прогресс ведутся в GitHub Issues (label `task`, milestone «MVP: безопасный Казань-релиз»). Как устроена вся система — [docs/task-management.md](../task-management.md). Не вести здесь чек-листы заново — это и была причина рассинхронизации, которую система из `task-management.md` устраняет.

**Goal:** довести локальный прототип до проверяемого первого MVP для одного сайта Дом.ру в Казани без публикации демо-данных, недостоверных статусов и незащищенных ссылок.

**Architecture:** сначала стабилизируется release gate и надежный контур данных. Затем единый outbox на BullMQ делает доставку лидов и пересборку наблюдаемыми. Публичный Astro-сайт получает build-time контракт, который блокирует production-сборку при недоступных данных, после чего расширяется от фиксированной Казани к опубликованным городам и страницам.

**Tech Stack:** pnpm 11, Node.js 22, TypeScript, Astro 7 static output, NestJS 12/Fastify, PostgreSQL 18, Prisma 7, Redis 8, BullMQ 6, Caddy, Docker Compose.

## Приемка MVP

MVP готов только когда чистый production-like контур проходит `pnpm check`, миграции, build без demo fallback, raw HTML audit, endpoint health с БД, импорт полного тарифного снимка, наблюдаемую пересборку, проверку адреса, безопасную обработку заявки и sandbox-доставку. Отдельно должны быть утверждены реальный контракт Tarifnik и правила работы с персональными данными. Механическая проверка прогресса — [milestone «MVP: безопасный Казань-релиз»](https://github.com/Celtoman/astro-telekom/milestone/1).
