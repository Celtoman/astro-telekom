# URL сайта: сохранение адресов и новые маршруты

Дата: 12 октября 2026 года. Основа: [согласованный состав страниц](2026-10-12-site-structure-agreement.md), [исследование действующего сайта](../research/2026-10-12-tarify-dom-site-structure.md) и ответы владельца.

Статус: сохраняемые страницы оставляют действующие URL; пять новых адресов и 301 для `/akcii-domru` согласованы владельцем. Сценарии для старых общих страниц проверки/поддержки и пяти страниц моделей оборудования отложены: владелец решит самостоятельно позже. Это документ согласования, не описание реализованных маршрутов и не разрешение публиковать изменения.

## Принятое правило

URL существующих страниц, которые входят в новую структуру, сохраняются. Предварительные альтернативные пути из старого канона не заменяют адреса источника. В частности, `/faq`, `/wifi-router`, `/policy`, `/soglasie` и `/lichnyy-kabinet-dom-ru` не переименовываются ради общего правила оформления slug.

Новые адреса нужны для новых страниц и перенесённых внутрь локаций функций. Для `/akcii-domru` согласован 301 на `/akcii-i-skidki`; остальные назначения redirects для исключённых/перенесённых страниц отложены владельцем и исключены из текущего обсуждения. Выбор адресов не запускает перенос данных, изменение приложения или публикацию.

| --- | --- |

| Существующие новости и акции | Полные действующие URL, включая `/novosti/{slug}`, `/akcii-i-skidki/{slug}` и `/bez-rubriki/{slug}`. Классификация публикации не меняет её URL автоматически. |

Исходный объявленный реестр — [sitemap-urls.csv](../research/evidence/2026-10-12-tarify-dom-structure/sitemap-urls.csv). Он является датированным срезом, а не доказательством HTTP-доступности каждого экземпляра. Три юридических страницы проверены отдельно по ссылкам Footer. Существующие полные URL тарифов и городов переносятся с явным соответствием сущности, без автоматического переписывания slug по названию.

Сосновый Бор имеет исключение: город `/sosnovyj-bor`, часть тарифов под `/sosnoviy-bor/…`. Решение сохранять URL не разрешает автоматически исправить эти адреса или сопоставлять города только по префиксу тарифа. Для реализации требуется явная карта соответствий сущностей и адресов.

## Согласованные новые адреса

`{location}` означает действующий адресный slug основной страницы локации. Пять адресов утверждены ответом владельца; для карты покрытия владелец предложил собственный вариант.

| Страница | Согласованный URL |
| --- | --- |
| Проверка подключения внутри локации | `/{location}/proverka-podklyucheniya-k-domru-po-adresu` |
| Техподдержка внутри локации | `/{location}/tehpodderzhka` |
| Общая карта покрытия | `/karta-pokrytiya-domru` |
| Контакты партнёра | `/contacts` |
| Общая HTML-карта сайта | `/sitemap` |

В предыдущем проходе короткий вариант проверки адреса и поддержка проверены на Казани; `/contacts` и `/sitemap` вернули HTTP 404. После ответа владельца отдельно проверены `/karta-pokrytiya-domru` и `/kazan/proverka-podklyucheniya-k-domru-po-adresu`: оба вернули HTTP 404. В исходном sitemap согласованные городские суффиксы и путь карты покрытия не объявлены. Это не HTTP-проверка каждого города и не проверка коллизий рабочего каталога новой платформы.
