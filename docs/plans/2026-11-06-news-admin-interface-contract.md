# T2: интерфейсный контракт админки новостей и404

Статус: CONTRACT READY / UI IMPLEMENTATION PENDING. Источники — согласованные Q1–Q25, план#534, действующий AdminShell и обязательная admin design system. Новые пользовательские решения не вводятся; детали ниже делают согласованный путь проверяемым. Контракт не является скриншотом, пользовательским тестом или визуальной приёмкой готового экрана.

## Задача пользователя и навигация

Основной путь: «Все новости» → создать/открыть → написать → увидеть подтверждение сохранения → проверить → выпустить → открыть фактическую публичную версию. Возврат восстанавливает поиск/категорию/состояние/страницу/scroll.

Sidebar «Новости»: «Все новости», «Категории». Настройки списка — через «Страницы → Новости» и вторичную ссылку из списка;404 — «Страницы →404». Никакой третьей внешней CMS, смены ролей и обязательного согласования другим человеком.

## Схемы экранов

```text
Все новости                           [Создать новость]
Поиск по заголовку   Категория   Состояние   [Сбросить]
Заголовок             Категория  Дата       Состояние  …
Новый роутер…         Новости    19.09.2024 Черновик   …
                         Постраничная навигация списка

← К списку        Черновик сохранён   [Предпросмотр] [Опубликовать]
Основной контент                     Настройки
  Заголовок                         На сайте: прежняя версия / нет
  Анонс карточки                    Категория [+Создать]
  Обложка: загрузка/кадр/alt         Дата и часовая зона
  Панель форматирования             Адрес
  Основной текст                    Автор / источник
                                    Связанные новости
                                    SEO (раскрытие)
                                    Социальные сети (раскрытие)
```

На Mobile content раньше settings; верхние действия допускают две строки. Меню не прячется в hover. Клик по заголовку в таблице — обычная ссылка; строка не перехватывает клавиатуру. Мобильное представление сохраняет title/status/date/actions без растягивания viewport. Поля не теряют ширину из-за длинного заголовка или адреса.

## Поля и действия редактора

| Группа | Правило |
| --- | --- |
| Заголовок и анонс | Видимые labels, счётчик ограничения при необходимости, без HTML. Неполный draft разрешён. |
| Текст | H2/H3, bold/italic, списки, цитата, ссылка, image/caption, undo/redo. H1, цвета, шрифты, колонки и HTML не доступны. Toolbar имеет доступные имена и состояния. |
| Обложка | DropZone и кнопка выбора, progress/retry/remove,16:9crop, оригинал сохранён, alt/декоративное назначение/подпись контекстные. Незавершённая загрузка видна. |
| Категория | Одна из общего справочника. Inline create не закрывает редактор и не теряет ввод; новый id явно выбран после успеха. |
| Дата | Видимая часовая зона; хранится timezone-aware date. Публикационная дата не заменяется временем импорта или autosave. |
| Адрес | Предложенный slug до фиксации адреса, затем ручное действие. После публикации изменение title не меняет slug. Показывается полный destination и будущий301. |
| Автор/источник | Необязательные отдельные группы; Person/Organization фактические. Ввод источника не объявляет его автором автоматически. |
| Related | Auto показывает реальную подборку; manual≤3 уникальных live news, без self/draft. Снятая запись исключается с понятным пояснением. |
| SEO/social | Автоматические итоговые значения и источник fallback, необязательный override и сброс. Social preview приблизителен; JSON-LD формируется системой. |
| Выпуск | Прежде flush/save точного draft → review состава/ошибок/зависимостей → явное подтверждение выпуска. Ошибки ведут к полям. Повтор не создаёт вторую операцию. |

Не использовать перезаполнение editor content на каждый autosave response: это сбрасывает курсор/выделение. External content устанавливается при открытии другой записи, явном restore или выбранном разрешении конфликта. Новый черновик получает стабильный client operation/id до первого POST, чтобы повтор после сбоя не создавал дубли.

## Состояния и восстановление

| Состояние/триггер | Видимый результат | Действие/фокус |
| --- | --- | --- |
| Initial load | Skeleton/«Загружаем новости…» | Без показа ложного empty. |
| Нет записей | Объяснение и «Создать новость» | Доступно с клавиатуры. |
| Фильтр ничего не нашёл | «По этим условиям новостей нет» | «Сбросить фильтры», без потери поля поиска. |
| API list failure | Alert и «Повторить» | Ранее загруженные данные отмечены как прежние. |
| Draft изменён | «Есть несохранённые изменения» | Не объявлять каждое нажатие скринридеру. |
| Autosave | «Сохраняем…» | Фокус/курсор остаются в тексте. |
| Saved | «Черновик сохранён…» + подтверждённое время | Dirty guard снимается только с подтверждённого digest, не по признаку наличия live draft. |
| Есть live и новый draft | «На сайте прежняя версия» | «Предпросмотр» с режимами draft/live. |
| Save failure/offline | Постоянная ошибка и время последнего успеха | Retry, текст остаётся, локальная копия не удаляется. |
| Reload recovery | «Найдены несохранённые изменения» | Показать дату/материал; восстановить либо оставить серверную редакцию. |
|409две вкладки | Сравнение своего и серверного варианта | Autosave приостановлен; явный выбор, без молчаливого перезаписывания. |
|401 | Сессия недоступна | Recovery сохраняется для того же аккаунта; повторный вход не публикует и не принимает конфликт автоматически. |
| Upload failure | Ошибка рядом с файлом | Retry/cancel, текст и прежняя cover сохранены. |
| Publish validation blocked | Сводка с названиями полей и ссылками | Перевести фокус к сводке/полю, раскрыть содержащую его группу. |
| Review stale | «Данные изменились после проверки» | Повторная проверка; состав не заменяется скрыто. |
| Queue/build/check/activate | Текстовый этап существующего progress | Не выдумывать процент; editor может продолжать draftR+1, выпускаетсяR. |
| Outcome uncertain | «Проверяем результат публикации» | Чтение прежнего operationId; новая операция недоступна до выяснения. |
| Failed before activation | Прежняя live-версия сохранена | Понятная причина/повтор после проверки. |
| Success | «Опубликовано» и фактическая ссылка | Только подтверждённый receipt; если уже draftR+1, остаётся «есть изменения». |
| History compare | Дата/тип редакции и различия | «Восстановить в черновик», не «Опубликовать старую». |
| Withdrawal | Название, URL и перечисление последствий | Явное действие; после успеха404и исчезновение из подборок. |

## Категории и общие настройки

Категории: имя/slug, публичное и общее количество; число открывает отфильтрованные новости. При rename/reassign review показывает затронутые live-материалы. Наличие draft-body у материала не означает его включение в такой выпуск. Delete без переноса использования заблокирован с объяснением; hide пустой категории не является физическим удалением истории.

Настройки списка и404: те же Field/Card/Error/Preview/Publish patterns; фиксированная композиция.404destinations — HOME и CITIES по реальному route inventory, а не вручную скопированные исторические paths. Предпросмотр404доступен без создания публичного `/404` route с200.
