# Общая HOME: утверждённые паспорта новых блоков и карта действий

Дата: 16 октября 2026 года. Версия документа: 1.3. Статус: **APPROVED / DATA_API_IMPLEMENTED / EDITORS_READY_LOCALLY**.

Владелец утвердил паспорта и карту действий 16 октября 2026 года с уточнениями раздела 7. Утверждены поля, источники, ограничения и назначения действий; готовность реализации этим не подтверждается. При первоначальном согласовании код и реестр не менялись. Сначала владелец разрешил этап 1, затем автономное завершение всего плана с проверками, коммитами, push и deployment. Локально выполнены этапы 1–4: контракты/реестр, API/проекция, механизм перехода данных и редакторы. Внешний переход ещё не применён; публичный renderer/preview полной HOME остаются следующими этапами. Figma не меняется. Имя файла сохранено от первоначального проекта для совместимости ссылок; актуален статус этой версии.

## 2. Утверждённая общая модель управления

### Хранение и редактор

- Новые текстовые данные принадлежат одному site-scoped PageTemplate(HOME), блоки — PageTemplateBlock.data.
- Идентификаторы типов ниже утверждены и добавлены в read-only API-реестр на этапе 1. Статус каждого нового паспорта: status=APPROVED, passportVersion=1.0.0, editorReadiness=READY после локальной приёмки этапа4. Это не готовность публичного renderer и не внешняя публикация. Статус ACTIVE не присваивается.
- Согласовано расширение редактора в существующей группе шаблонов HOME: один экран с отдельными секциями новых блоков, без конструктора произвольных страниц.
- Порядок блоков, число фиксированных карточек, их смысловые позиции, типы действий, адаптивность, цвета, иконки, стили и размеры — системные. В первом объёме не добавляются drag-and-drop, удаление обязательных секций или переключение на экспериментальные варианты.
- У карточек фиксированные смысловые ключи; редактируются их значения. Порядок технических JSON-массивов не даёт права менять утверждённую композицию.
- Заголовок/описание/допустимые текстовые поля могут использовать только разрешённые SITE-переменные действующего каталога. CITY/TARIFF-переменные общей HOME не подставляются. Имена и доступность переменных проверяются сервером. У изображений, URL, системных действий и ключей карточек переменных нет.
- Новые поля содержат обычный текст, без HTML. Специальная грамматика красного выделения остаётся только в существующем Hero; автоматически на другие заголовки не распространяется.

Это контракт будущей реализации; существующий API таких полей пока не предоставляет.

### Сохранение, ошибки и публикация

- Сохранение меняет только рабочую ревизию с expectedWorkingRevision и before/after аудитом.
- Безопасный неполный черновик можно сохранить с перечнем незаполненных полей. Публикация новой композиции требует заполнения обязательных полей и известных типов/действий.
- Ошибка указывает блок, карточку и поле; черновик не теряется. Изменения в рабочей версии не меняют текущий сайт.
- Для всего состава HOME вводится самостоятельная версия композиции, отдельно от home.hero/2.0.0. Старые опубликованные снимки не переписываются.
- В административном preview навигация, ввод и отправка отключены. Визуальное соответствие данных проверяется на D/T/M; реальная работа формы — отдельной функциональной приёмкой.
- Изображения: локальный безопасный путь или HTTPS URL по существующему контракту, без credentials, javascript/data URL и обхода пути. Альтернативный текст обязателен для смысловой иллюстрации. Загрузчик медиа/файлов не входит в первый объём.
- Неизвестное системное действие не подменяется произвольным href. Отсутствующая целевая страница не заменяется ссылкой # или другой услугой.

**Действия:** A20. Дополнительная ссылка «Все вопросы и ответы» не добавляется по решению владельца.

**Пустота/проверка:** пустой безопасный список допустим в черновике. Для новой опубликованной композиции требуется минимум1 заполненная пара; реальные данные и готовность к выпуску FAQ согласуются отдельно. Демоданные не добавляются в рабочую БД как автоматически утверждённый контент. Диапазон4–6 из ранней сводки — исходный состав/рекомендация, не жёсткий предел редактора. Утверждённый верхний технический предел —50 пар. Вопросы/ответы не сокращаются ради высоты; HTML запрещён.

### Условия передачи контекста форм

- Городские переходы используют Ctx; это не основание автоматически записывать московский город в консультационную заявку на общей HOME.
- Для FLOW1 на общей HOME без ручного выбора города не подставляется дефолт Москвы. Подтверждённый выбранный город/контекст городской страницы сохраняется согласно действующему контракту; оператор может уточнить город. Это правило проверить при интеграции2e с общим контроллером.
- Для FLOW2 сохраняются source-контекст страницы, структурированный адрес и результат проверки. Реально выбранный адрес другого города допускается действующей межгородской проверкой; новый блок не вводит запрет.
- Успех показывается только после подтверждения API. Повтор отправки не создаёт новую заявку из-за новой UI-оболочки. Сбор новых полей, новый reasonCode и изменение доставки не предлагаются.
- Согласие не отмечается автоматически; открытие документов и возврат не очищают ввод.
- Фиксированные user-facing сообщения FLOW и юридические тексты не становятся отдельными копиями в каждом блоке.

## 7. Решения владельца от 16 октября 2026 года

**D1. Недостающие страницы — отдельным этапом.** Сохраняются целевые назначения /movix, /faq, /contacts, /wifi-router и тематических городских страниц из раздела 6. Их создание не входит в текущую фиксацию паспортов. Отсутствие маршрутов остаётся явной зависимостью функциональной приёмки переходов до внешнего выпуска. Это не разрешение удалять CTA, менять дизайн или подставлять случайные страницы/#.

**D2. Действия Header утверждены.** «Подключить» открывает существующий адресный FLOW2. «Помощь» ведёт напрямую на FAQ /faq; создание этой страницы относится к отдельному этапу D1. Новое раскрывающееся меню этими действиями не предусмотрено.

**D3. «Пользовательское соглашение» пока не трогать.** Вопрос отложен по прямому поручению владельца: не менять пункт, текст, назначение или макет; не создавать документ/маршрут и не подменять его согласием. Действующий legal-контракт сохраняется. Это отложенная работа, а не незакрытый вопрос для начала реализации остальных утверждённых паспортов.

**D4. Девять паспортов и граница управления утверждены.** Поля, источники, ограничения и карта действий принимаются в версии 1.0 этого документа. Header/Footer остаются кодовыми, контакты/города/юридические данные — системными. Редактор произвольного меню, CMS-конструктор страницы, media upload и управление стилями в объём не входят. Новые редакторы ещё не реализованы.

**D5. FAQ и отложенные блоки.** Утверждён переменный контентный список FAQ; текущие демопары — только fixture разработки/preview. Реальные ответы и решение о выпуске с ними — отдельно. Акции#340 и Новости#341 остаются в бэклоге.

Утверждение паспортов не является поручением писать код. Владелец прямо указал: «Зафиксируй решения, код пока не меняй». При исходной фиксации менялась только документация. Последующее поручение разрешило этап 1; его [локальный результат](../research/2026-10-16-general-home-stage1-contracts-acceptance.md) фиксирует исходную границу. Последующим отдельным поручением владелец разрешил автономно завершить все этапы; [результат этапа 2](../research/2026-10-16-general-home-stage2-api-acceptance.md).
