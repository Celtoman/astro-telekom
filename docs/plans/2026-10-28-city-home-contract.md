# CITY_HOME: договорённости внедрения и редактируемые поля

28 октября 2026. Статус: **КОНТРАКТ СОГЛАСОВАН, ВНЕДРЕНИЕ РАЗРЕШЕНО**. Владелец разрешил самостоятельные commit/push/deploy/проверки полного внедрения; перечни полей уточнены в диалоге grilling Q24–Q38. Последняя поправка Q38: фиксированное «До 1 Гбит/с» используется только в преимуществах HOME; CITY_HOME сохраняет вычисление скорости из опубликованных тарифов города по Q31. Разрешение на реализацию, commit/push/deploy действует в этой области. Этот документ фиксирует целевое поведение и сам по себе не доказывает наличие в коде или выпуск.

## Подтверждённая цель и область

- Полная страница, CMS и preview должны работать в действующем защищённом test-контуре. Готовность к реальному публичному трафику не утверждается.
- Один CITY_HOME для опубликованных городов; Казань — первый контрольный пример. Принятый состав: шапка → Hero → каталог → сравнение → помощь → преимущества → этапы → Movix → города региона → FAQ → контакты без офиса → футер.
- Шапка/футер обновляются на всех существующих публичных типах страниц, общие блоки — там, где уже присутствуют. Состав остальных страниц автоматически не расширяется.
- Тексты HOME и CITY_HOME независимы. Общие факты имеют единый источник. Состав и порядок городской композиции фиксированы; свободного конструктора и ручного отключения блоков нет. Системное скрытие при отсутствии данных определяется контрактом.
- Выпуск кода и CMS-активация разделены; прежний обслуживаемый снимок сохраняется до активации новой версии.

## Подтверждённые действия и данные

1. «Заказать звонок», «Оставить заявку» и все «Подключить», включая карточки, таблицу и tariff detail, открывают FLOW1 без обязательного адресного gate. Название выбранного тарифа и город показываются как нередактируемый контекст и сохраняются для оператора. Обычный callback очищает прежний тариф. Комплектацию/оборудование/опции/рассчитанную стоимость конфигуратора в callback не передавать.
2. «Проверить адрес» ведёт в действующий FLOW2. Отдельную логику устаревшего предложения не добавлять; существующая серверная проверка остаётся предметом реализации.
3. Телефон подключения подписывается графиком8:00–22:00, онлайн-заявки принимаются круглосуточно. Начальный срок обратного звонка15 минут.
4. Категории и быстрые признаки работают по AND. Категория «Все тарифы» снимает только ограничение типа. Полный сброс снимает все фильтры. При смене отбора каталог возвращается к настроенному initialCount, мобильная лента — к началу; фокус остаётся на фильтре, вся страница не прокручивается. «Показать ещё» раскрывает весь остаток.
5. Пустая выдача сохраняет отбор, показывает сообщение и сброс. Сравнение не фильтруется и содержит весь опубликованный каталог города.
6. В сравнении строгая сортировка по цене/скорости, закрепление не обходит числовой порядок. При равенстве — порядок каталога; неизвестная скорость в конце. Четыре режима и начальная PriceAsc соответствуют макету.
7. Новый снимок блокируется при опубликованном городе без тарифов. Ошибка указывает город; исправление — добавить тариф или вручную снять город с публикации. Автоматически города не исключать; действующий снимок продолжает работать.
8. FAQ начинается с шести содержательных вопросов/ответов; список редактируется, добавление/удаление/порядок разрешены,1–50 для публикации. Числа берутся из данных города. Вопрос без необходимого показателя скрывается.
9. Региональные города — другие опубликованные города того же региона; при отсутствии списка блок скрывается.

## Подтверждённые поля Q24–Q36

### Общие настройки сайта — Q24

Единые редактируемые телефон подключения, телефон поддержки, график приёма звонков, график поддержки, график онлайн-заявок и срок обратного звонка в минутах. Шапка, контакты, формы и футер только подставляют значения, локальных копий нет. Телефоны уже существуют; остальные поля требуют реализации.

### Шапка BLK-0001 — Q25A

Отдельного редактора нет. Город определяется контекстом, телефоны/график — общими настройками. Логотип, подписи меню/кнопок, состав и действия фиксированы.

### Футер BLK-0016 — Q26

Два общих поля для всех страниц: информационно-юридический абзац (исходно утверждённый текст владельца) и подпись кнопки обращения (исходно «Оставить заявку»). Телефоны/графики общие; группы, ссылки и назначения системные. Эти поля не редактируют содержание самостоятельных юридических страниц.

### Первый экран BLK-0002 — Q27

Семь полей: H1, поясняющий текст, изображение, описание изображения для доступности, подсказка адреса, подпись проверки адреса, подпись перехода к тарифам. SITE/CITY-подстановки в H1 и пояснении. Цена/скорость/каналы и их смысловые подписи вычисляемые/системные.

Текущие границы API: title120, text1000, image2048, imageAlt250, addressPlaceholder120, checkButtonText80, tariffsCtaText80. Подтверждён перечень существующего редактора; вводить другие поля автоматически нельзя.

### Каталог BLK-0006 — Q28

Семь полей: заголовок, вводный текст, подписи подключения/подробностей/раскрытия, initialCount1–100 (по умолчанию6), сортировка карточек PRICE_ASC/PRICE_DESC с приоритетом закрепления. Смена фильтров использует настроенное initialCount. Данные карточек принадлежат редактору тарифов. Категории, три быстрых признака, порог500 Мбит/с, счётчик и сброс системные.

Текущие текстовые границы API: title120, необязательный text1000, три подписи кнопок по80. Источник — tariff-collection.ts.

### Сравнение BLK-0007 — Q29

Три поля: заголовок, пояснение, подпись подключения в строках. Данные общие с каталогом; столбцы/их заголовки, четыре режима сортировки и начальное PriceAsc фиксированы. Ручного списка строк и отдельных тарифных показателей нет. Схема/паспорт/редактор требуют реализации.

### Помощь с выбором BLK-0005 — Q30

Шесть независимых для HOME и CITY_HOME полей: заголовок блока, поясняющий текст, заголовок формы, подпись поля телефона, подсказка внутри поля телефона, подпись отправки. Номер подключения, график и срок обратного звонка подставляются из общих настроек. Согласие, ссылки на документы, ошибки и успешная отправка системные.

### Преимущества BLK-0019 — Q31

Заголовок блока и заголовок/описание каждой из шести фиксированных карточек редактируются независимо для HOME и CITY_HOME. Состав: скорость, технологии подключения, Wi-Fi, Movix, онлайн-заявка, поддержка. Количество, порядок и иконки фиксированы.

Короткая подпись скорости CITY_HOME вычисляется из опубликованных тарифов города; при отсутствии скорости скрывается подпись, сама карточка остаётся. В преимуществах HOME подпись «До 1 Гбит/с» фиксирована кодом, не редактируется в CMS и не вычисляется из тарифов (поправка Q38 «Только на HOME»). График поддержки берётся из общих настроек. Четыре остальные короткие подписи — технологии подключения, возможности Wi-Fi, объём библиотеки Movix и онлайн-заявка — общие редактируемые поля HOME/CITY_HOME. Эти четыре общих поля предстоит реализовать; локальные копии factText не должны становиться конкурирующими источниками.

### Этапы подключения BLK-0021 — Q32

Редактируются заголовок блока, вводный текст, заголовок/описание каждого из четырёх этапов и подпись кнопки обращения. Этапы фиксированы: заявка → согласование времени → установка → подтверждение подключения. Порядок, нумерация и иконки системные. Телефон общий, действие кнопки — FLOW1.

### Movix BLK-0009 — Q33

Редактируются заголовок/вводный текст, заголовки/описания трёх преимуществ, основное изображение/alt, подпись группы кинотеатров, изображения/alt шести логотипов, подписи основной кнопки/дополнительной ссылки и оговорка о зависимости наполнения от тарифа. Состав/порядок преимуществ и кинотеатров фиксированы. Тексты HOME и CITY_HOME независимы. Логотипы описывают сервис Movix, а включение конкретных подписок определяется данными тарифа.

Q37: дополнительная ссылка внутри блока временно скрывается до появления отдельной страницы; основная кнопка перехода к тарифам остаётся. Пункты «О Movix» в шапке/футере сохраняют ранее согласованный переход к секции. Это согласованное отступление от Screens при внедрении, без изменений самого файла Figma.

### Города региона BLK-0032 — Q34

Три редактируемых поля: заголовок, поясняющий текст, подпись ссылки всех городов обслуживания. Регион в чипе берётся из справочника. Другие опубликованные города того же региона выводятся автоматически по алфавиту, текущий город исключается. Названия/URL вручную здесь не редактируются. При отсутствии других городов весь блок скрывается. Поиска, алфавитного указателя, счётчика и ручного списка нет.

### FAQ BLK-0014 — Q35

Редактируются заголовок блока и вопрос/ответ каждой пары; разрешены добавление/удаление/перестановка, 1–50 пар. Город, телефоны, графики, минимальная цена, максимальная скорость и число каналов вставляются редактором через список подстановок. Если значение используемой подстановки отсутствует, скрывается вся использующая его пара. Без таких подстановок вопрос показывается всегда. При скрытии всех пар скрывается весь блок. Отдельные условия показа каждой пары редактор не задаёт; зависимости определяются явными подстановками, а не анализом произвольной формулировки текста.

### Контакты BLK-0015 — Q36, вариант А

Восемь редактируемых полей: заголовок блока, заголовок карточки подключения, её подпись аудитории, подпись кнопки обращения, заголовок карточки поддержки, её подпись аудитории, текст о бесплатном звонке и пояснение тем поддержки. Телефоны, графики и обещание обратного звонка подставляются из общих настроек. Подписи приёма звонков/онлайн-заявок системные.

На сайте сохраняется принятая композиция двух карточек без офиса. Данные HAS_OFFICE в CMS не добавляют третью карточку автоматически. Вариант с офисом в Figma сохраняется.

## Завершение согласования

Перечни полей и источников согласованы. На уточнение о фиксированной подписи скорости HOME/CITY_HOME владелец ответил «Только на HOME». Следовательно, HOME использует константу, CITY_HOME — расчёт по Q31. Подтверждения Q24–Q38 завершают согласование в ранее разрешённом полном внедрении; повторное разрешение на те же действия не требуется. План исполнения и проверки ведётся отдельно, факт результата подтверждается кодом, тестами, CI и действующим защищённым test-контуром.
