# HOME Hero 1d: паспорт и порядок замены

Дата: 13 октября 2026 года. Объект: первый экран общей главной `/`, существующий ID `home.hero`.

**Статус:** паспорт HOME `2.0.0` утверждён владельцем 13 октября 2026 года: согласованы поля с исключением `cityLabel`, один заголовок с инструментом `<red>…</red>`, хранение города до закрытия вкладки, подпись «Найти город» в Selected и результаты сразу при вводе. Контракт реализован локально; внешний deployment и CMS-публикация не выполнялись. Legacy HOME 1.0.0 и CITY_HOME 1.0.0 сохраняют совместимость.

Исполнение ведётся в [task #277](https://github.com/Celtoman/astro-telekom/issues/277); исправление адресного перехода — её native sub-issue [#276](https://github.com/Celtoman/astro-telekom/issues/276). Статусы определяются Issues, а не этим документом.

- Состав: один H1, описание, поиск города, основная кнопка, семь быстрых городов при наличии в опубликованном каталоге, «Все города», схема 01–03.
- Городской Hero, тарифные страницы, FLOW 1 / FLOW 2 и legal-модалки сохраняют свои контракты. Соседние блоки общей главной внедряются отдельно согласно [согласованной композиции](2026-10-12-general-home-block-agreement.md).
- Автоопределение отложено: [#274](https://github.com/Celtoman/astro-telekom/issues/274). Поиск использует собственный опубликованный справочник без внешних запросов.

## Город и назначения элементов

Под «все ссылки формируются на Москву» понимаются ссылки, зависящие от города. Логотип `/`, справочник `/goroda-obsluzhivaniya`, общая карта, legal-ссылки и `tel:` сохраняют своё назначение.

| Элемент на общей главной | Назначение |
| --- | --- |
| «Тарифы» | `/{activeCity}#tariffs`; до выбора `/moskva#tariffs` |
| «Проверить адрес» | `/{activeCity}#address-check`; до выбора `/moskva#address-check`. Локальный якорь `/` и выбор города вместо целевого действия не используются |
| Поле и «Найти город» | Поиск по опубликованному справочнику, без запуска адресной проверки |
| Быстрый город / результат | Выбор конкретного ID города и переход в Selected; следующий CTA/Enter открывает его страницу, как в Figma |
| «Все города» | Окно O01 со всем опубликованным справочником |
| Схема 01–03 | Пояснение порядка действий; строки схемы не становятся кнопками без отдельного решения |
| «Заказать звонок» | Существующий FLOW 1 с контекстом активного города; адресная проверка не подменяет callback |

На CITY_HOME и тарифных страницах контекст города задаётся URL. Ввод запроса не меняет активный город: это происходит только после выбора конкретной записи. Очистка поискового поля не сбрасывает ранее подтверждённый город навигации. Результаты и href строятся только из опубликованного каталога; первый город списка не заменяет Москву. При отсутствии опубликованной Москвы и подтверждённого города недоступное действие явно сообщает причину; фиктивный `/moskva` не создаётся. При отсутствии города остаётся выбор из опубликованного справочника.

Решение владельца: выбор сохраняется в текущей вкладке до её закрытия. Для этого используется `sessionStorage` с ID города; при возврате на `/` городские ссылки используют эту запись вместо Москвы. Межсессионное хранение не вводится. Недоступность browser storage не блокирует выбор и переход; сохранённый ID проверяется по текущему опубликованному каталогу. Это реализованный локальный контракт; внешний контур ещё не проверен.

## Утверждённые поля версии 2.0.0

Контент принадлежит `PageTemplate(HOME)/PageTemplateBlock.data`; один общий шаблон сайта, без городских копий. Ниже — согласованный контракт редактора и API. Отдельного редактируемого названия поля поиска нет; доступное имя «Поиск города» задаётся системой.

| Поле | Правило | Исходное значение / источник |
| --- | --- | --- |
| `title` | Один обязательный H1 до 120 видимых символов; безопасный парный маркер `<red>…</red>`; сырой текст до 2048 символов | `Домашний интернет и ТВ Дом.ру <red>в вашем городе</red>` |
| `text` | Обязательное описание до 1000 символов | «Выберите город, чтобы посмотреть тарифы Дом.ру. Возможность подключения проверим по адресу.» |
| `cityPlaceholder` | Обязательная подсказка до 120 символов | «Ваш город, например, Москва.» |
| `searchButtonText` | Обязательная общая подпись основной кнопки до 80 символов; одинакова до и после выбора города | «Найти город»; владелец сохранил подпись Figma в Selected. Отдельного поля `selectedButtonText` нет |
| `allCitiesText` | Обязательная подпись открытия O01 до 80 символов | «Все города» |
| `emptyMessage` | Сообщение об отсутствии совпадений до 250 символов | «Город не найден. Проверьте название или выберите его из списка.» |
| `inputErrorMessage` | Ошибка попытки поиска без запроса до 250 символов | «Введите название города или выберите его из списка.» |
| `steps` | Ровно три записи `title` до 80 и `text` до 250 символов, все обязательны | Тексты схемы Figma, таблица ниже |

| Шаг | Заголовок | Описание |
| --- | --- | --- |
| 01 | Выберите город | Найдите свой город в списке. |
| 02 | Посмотрите тарифы | Сравните тарифы интернета и ТВ |
| 03 | Проверьте адрес | Узнайте, можно ли подключить Дом.ру в вашем доме |

Номера, иконки, порядок шагов, размеры, цвета и поведение элементов системные. Список быстрых городов: Москва, Санкт-Петербург, Екатеринбург, Иркутск, Казань, Самара, Саратов; отсутствующие в опубликованном каталоге пропускаются. ID, названия, регионы, slug, число результатов и URL принадлежат каталогу, а не текстовым полям Hero.

Произвольный HTML/JavaScript и href запрещены. В `title` разрешён только маркер `<red>…</red>` без атрибутов, вложенности и пустой выделенной части; остальные поля содержат обычный текст. Редактор предлагает «Выделить красным» и «Снять выделение» для выбранного диапазона; переменная выделяется целиком. Маркер разбирается в текстовые сегменты и фиксированный цвет #e0231e, не исполняется как HTML. Переменные контекста сайта разрешены для `title`, `text`; разрешение и лимиты проверяются после разрешения заголовка. Обычные подписи и сообщения — простой текст. Неполный безопасный черновик сохраняется с перечнем пустых полей; публикация блокируется. CITY_HOME сохраняет собственный контракт `1.0.0` и прежний набор полей.

## Поведение поиска

Figma задаёт визуальные состояния и иллюстративные связи; клавиши K/X в прототипе показывают примеры результатов, а не правила production-поиска.

| Состояние | Условие и действие |
| --- | --- |
| Default | Пустой запрос, быстрые города и ссылка O01; Москва используется для навигации, но не подставляется как введённый запрос |
| Focus | Фокус поля, доступный индикатор; ввод сам по себе не выбирает город |
| Results | Фильтрация со знакомого первого символа по всему опубликованному каталогу; название и регион, без регистра, trim и нормализация ё/е; алфавитная сортировка. Число результатов вычисляется, список прокручивается |
| NoResults | Непустой запрос без совпадений; сообщение и доступ к O01. Отсутствие совпадения не трактуется как отсутствие покрытия |
| InputError | Нажатие поиска/Enter с пустым запросом; сообщение связано с полем, фокус остаётся в нём |
| Selected | Выбрана конкретная запись: видны название и выбранный быстрый город; активный город обновляет зависимые ссылки. Следующий CTA/Enter открывает `/{slug}` с тарифами на странице |

Выбор строки или быстрого города ведёт в Selected, а CTA/Enter из Selected — на городскую страницу. Подпись CTA остаётся «Найти город», как в Figma. Владелец явно выбрал сохранение подписи после предложения заменить её на «Посмотреть тарифы»; предложение переименования отклонено. Для обеих фаз используется одно поле `searchButtonText`; автоматического переименования и дополнительной CTA нет. Состояние Selected и последующее подтверждение сохраняют двухшаговый сценарий Figma.

Нажатие поиска с несколькими совпадениями раскрывает список; неоднозначный запрос не выбирает первый город автоматически. Поведение единственного совпадения такое же: выбор строки, затем подтверждение. ArrowDown/ArrowUp перемещают активный результат, Enter выбирает его, Escape закрывает список, Tab сохраняет обычный порядок фокуса. При изменении запроса выбранная запись поля сбрасывается, подтверждённый город навигации остаётся до следующего явного выбора.

O01 переиспользуется с режимом действия инициатора: вызов из Hero возвращает выбранный город в его состояние; вызов из шапки сохраняет назначение инициатора и ведёт к нужной городской функции. Без JavaScript быстрые города имеют реальные ссылки на CITY_HOME, справочник остаётся доступен по обычной ссылке; поиск не выдаётся за работающий.

## Замена контента и совместимость

| Текущий HOME 1.0.0 | Реализованное преобразование |
| --- | --- |
| `title`, `text` | Сохранить исходные значения в before-history; в рабочей версии 2.0.0 использовать утверждённые тексты Figma. Не переносить адресное описание в поиск автоматически |
| `image`, `imageAlt` | Сохранить в истории; новый блок не требует изображения оборудования |
| `addressPlaceholder`, `checkButtonText` | Сохранить в истории; не переименовывать в подписи поиска |
| `chips` | Сохранить в истории; создать новую схему шагов из Figma, а не трактовать пояснения как города |
| ID/позиция `home.hero` | Сохранить; второй Hero на странице не создавать |

Одна транзакция обновляет только рабочий HOME, пишет before/after, ContentRevision, AuditEvent и увеличивает рабочую ревизию один раз. Повторное преобразование не меняет уже обновлённый шаблон; неизвестный состав блокирует операцию. Опубликованные snapshots, городской шаблон и тарифные данные не переписываются. Новые сайты и create-only seed получают утверждённый контракт 2.0.0.

Код явно различает HOME 1.0.0/2.0.0; отсутствие версии у исторического снимка означает известный legacy-контракт, а неизвестная версия блокирует сборку. Версия проходит через API catalog до Astro и административного preview. Выпуск CODE читает обслуживаемый старый снимок и сохраняет прежний HOME до отдельной CMS-публикации новой рабочей версии. Поддержка старого контракта включает каталог, API-валидатор, preview, styles/assets и renderer.

Возврат требует заранее проверенного обратного изменения рабочего HOME и новой CMS-публикации. Наличие истории само по себе не является универсальным rollback; старый publication ID нельзя произвольно активировать в обход действующей revision policy.

## Алгоритм внедрения и проверки

1. Зафиксировать утверждённый паспорт, таблицу преобразования и критерии приёмки. Уже утверждённые решения — Москва до ручного выбора, хранение до закрытия вкладки и подпись «Найти город» в Selected — не пересогласовываются. Исполнение и связанные проблемы ведутся по [task-management](../task-management.md).
2. Разделить версии HOME/CITY_HOME и добавить совместимость старого контракта. Проверить чтение legacy-снимка до изменения рабочих данных.
3. Реализовать отдельный `GeneralHomeHero.astro`, общую модель поиска/активного города и навигацию. Переиспользовать O01 и существующие FLOW без изменения назначения их действий.
4. Обновить `first-screen.ts`, `admin-page-templates.controller.ts`, `site-catalog.service.ts`, `block-passports.ts`, `HomeScreensApp.tsx`, `preview-document.mjs`, `preview-public-styles.mjs`, загрузчик web catalog, создание нового сайта и seed. Добавить отдельную идемпотентную миграцию рабочего HOME и rehearsal возврата.
5. Выполнить профильные тесты, API build перед тестами `dist`, реальную Astro-сборку и browser-проверку. Сверить визуальные состояния с Figma. Обновить README и профильные документы, проверить ссылки и `git diff --check`.
6. Выполнить полный `pnpm check` на итоговом коде; дать владельцу локальную страницу и результаты проверки для приёмки. Push и внешний выпуск требуют отдельного разрешения.
7. После разрешённого push и зелёного CI выпустить точный SHA, подтвердить старый обслуживаемый снимок и рабочий новый контент; затем отдельно выполнить разрешённую CMS-публикацию и live readback HTML/действий.

Проверки должны покрыть 320/390/834/1440 px; длинные тексты, все шесть состояний, одноимённые города/регион, ё/е, пустой каталог и отсутствие Москвы, опубликованные реальные href, выбор/очистку/повторный выбор, возврат на `/`, недоступный storage, клавиатуру, touch и noscript. Отдельно: working/published, конфликт ревизий, блокировку неполного/небезопасного контента, повтор миграции, before/after, старую CODE-сборку и CITY_HOME без изменений. Preview остаётся визуальным с отключёнными действиями; browser E2E проходит на реальном сайте.

Для будущего нового блока порядок тот же; вместо преобразования старого контента отдельно согласуются ID, размещение и состав шаблона. Согласованный Figma-макет сам по себе не утверждает CMS-поля, системные источники или выпуск.

## Статус приёмки

Продуктовые решения локального объёма зафиксированы. Внешний выпуск требует отдельного разрешения: push → CI → deployment точного SHA → отдельная CMS-публикация и live readback. [Локальные проверки и их границы](../research/2026-10-13-home-hero-1d-local-acceptance.md) зафиксированы в отчёте приёмки.
