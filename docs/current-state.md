## Контракт данных и публикации

Только API пишет в PostgreSQL. Admin, public browser и worker используют HTTP. Сохранение меняет рабочую ревизию и audit, но не опубликованный сайт. Ручная публикация выпускает весь сохранённый снимок, включая города, тарифы, тексты и SEO.

В Coolify public HTML, runtime redirects, quote/address/lead API следуют exact обслуживаемому снимку из доверенного Caddy/controller context. Успех подтверждается durable receipt и независимой сверкой SQL; потерянный activation outcome сохраняет ту же rebuild job для восстановления. Code deployment пересобирает уже обслуживаемый snapshot новым renderer, не публикуя черновики.

Public content общих страниц ещё разрешается Provider → Site → Page, городской HOME — через общий PageTemplate. Legacy deep merge удаляется только после переноса всех непустых значений и проверки эквивалентности; SEO override cleanup уже завершена отдельно.

## Навигация админки после #260 / #271

Рабочие разделы админки используют общий сохраняемый AdminWorkspace React-root. Меню, шапка и publication polling сохраняются, экраны монтируются заново по pathname/query; код выбранного раздела предварительно загружается по hover/focus ссылки. Совпадающие одновременные GET объединяются. Для быстрого возврата списки городов/тарифов, справочники, паспорта и read-only каталог подстановок используют ограниченный кэш в памяти сессии (до 30 секунд, до 32 ответов) с обязательной проверкой в фоне и явным состоянием обновления. Доступ проверяется на сервере при каждом запросе; смена пользователя/logout/401 сбрасывают данные. Любая мутация сбрасывает кэш при начале и завершении, завершение публикации — при смене publishedRevision. Поздние ответы прежнего поколения не восстанавливают кэш. Редакторы получают свежие данные и сохраняют expectedWorkingRevision; городская форма фиксирует ревизию прочитанной строки при открытии и недоступна до завершения проверки каталога. Несохранённые формы защищены при внутренних переходах и Back/Forward. `/preview`, login и lead-access сохраняют отдельные документы. [Измерения и границы проверки](research/2026-10-08-admin-navigation-cache.md).

Городской редактор очищает форму, исходное состояние и её ревизию только после успешного ответа сохранения/смены URL или подтверждённого отказа от правок. После закрытия ложного предупреждения при переходе или перезагрузке нет. Отказ от закрытия, ошибка API и конфликт версии сохраняют введённые значения, защиту и исходную expectedWorkingRevision; повторное сохранение не обходит конфликт. Исправление [#272](https://github.com/Celtoman/astro-telekom/issues/272) проверяется обработчиками реального CitiesApp и локальной browser-приёмкой; внешний rollout подтверждается отдельно.
