## Правило

Интерфейс `apps/admin` строится на обязательной дизайн-системе, источником которой служат:

- Репозиторий: [github.com/arhamkhnz/next-shadcn-admin-dashboard-aria](https://github.com/arhamkhnz/next-shadcn-admin-dashboard-aria)
- Живой пример: [studio-admin.arhamkhnz.com](https://studio-admin.arhamkhnz.com)

Это Next.js + shadcn/ui на React Aria + Tailwind CSS. Референс обязателен для layout, визуального языка, состояний, accessibility- и keyboard-семантики и готовых UI-паттернов; он не требует превращать `apps/admin` в Next.js-приложение или буквально копировать неподходящий код.

Если в референсе есть подходящий компонент или блок, его адаптируют к нашим данным и API с сохранением React Aria-семантики. Next.js-специфичные части, включая `next/link`, `next/navigation`, Server Components и серверную загрузку данных, не переносятся как есть. Если прямого блока нет, экран собирают из совместимых React Aria-based shadcn/ui-примитивов в стилистике референса. Новый компонент допустим только при документированном отсутствии подходящего паттерна; он не должен создавать параллельную дизайн-систему на ad-hoc CSS.

Интерактивные примитивы `apps/admin` переведены на React Aria в рамках #97; пакет `radix-ui` удалён. [Инвентаризация](research/2026-09-26-admin-react-aria-inventory.md) фиксирует миграцию по issue [#97](https://github.com/Celtoman/astro-telekom/issues/97); проверки поведения и CI завершены.

## Что это означает технически

Целевая архитектура — Astro как static-оболочка и маршрутизация, общий сохраняемый React-root рабочих разделов и отдельные roots для login, lead-access и sandboxed preview, Tailwind и shadcn/ui внутри React. Данные админка получает и изменяет во время работы через HTTP API; она не зависит от данных, зафиксированных во время `astro build`.

`apps/admin` остается Astro 7 static output. React, Tailwind CSS и shadcn/ui используются в `/login`, защищенном shell `/`, `/preview`, каталогах `/tariffs` и `/cities`, вложенных `/tariffs/import` и `/cities/import`, длинной форме `/tariffs/edit?id=...`, `/leads`, `/redirects`, `/audit`, `/trash` и `/lead-access/`. Legacy plain HTML/CSS/vanilla JS страница удалена; shell больше не показывает вымышленные KPI или service-token prompt. Overview служит нейтральной навигацией: он не фиксирует catalog count, опубликованный город или миграционный статус удаленной CRM, а направляет за актуальными счетчиками и состояниями в рабочие разделы.

1. Рендерить интерактивную страницу одним React-root через `@astrojs/react` внутри static Astro route.
2. Использовать Tailwind CSS и локальные shadcn/ui-компоненты из `apps/admin/src/components/ui`.
3. Переносить подходящие компоненты и паттерны из референса либо собирать отсутствующие экраны из React Aria-based shadcn/ui-примитивов в его визуальном языке; получать данные только через существующий HTTP API.

Базовая инфраструктура первых двух пунктов работает на всех текущих admin routes. Интерактивные примитивы локальных shadcn-компонентов переведены на React Aria по issue [#97](https://github.com/Celtoman/astro-telekom/issues/97). Навигация shell задается одной конфигурацией; разделы «Тарифы» и «Города» раскрывают вложенные «Каталог» и «Импорт», а активная группа открывается автоматически. На desktop sidebar сворачивается до иконок с tooltip и доступным выпадающим меню для дочерних маршрутов; состояние панели и раскрытых групп сохраняется как UI-настройка в `localStorage`. `Ctrl+B` и `Cmd+B` переключают панель вне полей ввода. На mobile тот же shortcut и кнопка открывают модальное меню с focus trap и возвратом фокуса через React Aria Modal. Каталоги не смешиваются с XLSX-preview, apply, историей импортов и persistent rebuild status. Паттерн адаптирован из reference в рамках [#123](https://github.com/Celtoman/astro-telekom/issues/123) без новой параллельной дизайн-системы; навигация проверена в рамках #97. Импорт тарифов блокирует смену провайдера/файла во время запроса, отбрасывает запоздалый ответ preview и требует повторной проверки при изменении каталога после preview. Preview v3 отдельно показывает и позволяет искать действия `create/update/archive/unchanged`, раскрывает измененные поля, а архивирование выводит причину, время и связанный import run. В редакторе lifecycle отображается как read-only provenance: оператор меняет publication status, а API атомарно архивирует или восстанавливает запись. `/leads` заменяет функциональность прежнего CRM-приложения реальным журналом, карточкой и сменой статуса; отдельный `apps/crm` выведен из эксплуатации 9 сентября 2026 года.

## Язык и статусная семантика

В редакторе города защита несохранённых правок снимается только после успешного ответа API или подтверждённого отказа от изменений. Оба пути очищают закрытую форму и её исходное состояние. Ошибка сохранения, конфликт версии и отказ от закрытия сохраняют значения и защиту; исходная ревизия запроса не заменяется автоматически. Проверки #272 охватывают внутреннюю навигацию и beforeunload через реальные обработчики экрана и общий реестр защиты.

Общий shell на каждом защищённом экране показывает индикатор публикации из `GET /admin/sites/:siteId/publication-state` и явный переход «Опубликовать изменения» на `/publication`. Этот экран также доступен в меню и из Popover индикатора. Текущий сайт в индикаторе определяется только при ровно одной записи в `/admin/sites`; неоднозначность или сбой API показываются как «Статус публикации недоступен», а не как опубликованное состояние. Popover содержит рабочую и публичную ревизии, последнюю публикацию и ошибку. На узком экране индикатор и действие переносятся на отдельную строку. Индикатор обновляется после успешной административной мутации контента, при возврате фокуса и ограниченным опросом во время публикации; спокойные состояния постоянно не опрашиваются. Карточки в редакторах ведут на общий экран, а непосредственный запуск доступны только после актуальной успешной проверки того же сайта, рабочей и опубликованной ревизий. Ошибка загрузки блокирует действие даже при наличии прежних данных на экране. Использованы существующие `Button`, `Badge`, `StatusBadge` и React Aria Popover в стиле shell. Ключевые действия имеют высоту не менее 44 px; доступен переход с клавиатуры к содержимому, заголовки карточек имеют heading-семантику, статусы озвучиваются через live region, а ожидание учитывает reduced motion.

Рабочий язык оператора — русский. Технические enum-значения остаются частью API-контракта, но не используются как готовый пользовательский текст. Обычный интерфейс должен показывать русское название и, где значение неочевидно, короткое объяснение; неизвестный код выводится только в раскрываемой технической информации рядом с нейтральной подписью «Неизвестный статус».

Статусы используют единую семантическую Tailwind-шкалу во всех разделах: зеленый означает опубликованное или успешно завершенное состояние; синий — выполняемое или поставленное в очередь; янтарный — ожидание, черновик, проверку или повтор; красный — ошибку, отклонение или недоступность; серый — архив, пропуск, неактивное или неизвестное состояние. Цвет всегда дублируется текстом и не является единственным носителем смысла. Единый presentation registry хранит русские `label`, `description` и semantic tone для публикации, импорта, пересборки, заявок, аудита и типов услуг; `StatusBadge` и `SourceLabel` применяют его в таблицах, карточках и формах. Семантические варианты `Badge` используют дизайн-токены `success`, `info`, `warning`, `destructive` и `neutral` с отдельными значениями светлой и темной темы, без локальных raw color classes.

### Реализованные паттерны `/tariffs`, `/tariffs/edit` и `/tariffs/import`

`/tariffs` использует dashboard master-detail: серверную cursor-пагинацию и поиск, таблицу каталога, быстрый просмотр в боковой карточке и отдельную кнопку открытия полной формы. Быстрый просмотр показывает стоимость подключения; до очистки legacy-данных он также может показать ранее сохраненную рекомендацию `show_on_site`, явно отделенную от административного статуса публикации. Канонический XLSX и редактор это поле больше не принимают. `/tariffs/edit?id=...` — статический Astro route с React-root длинной формы: типизированные основные и импортные поля сгруппированы по секциям, справа закреплена навигация и read-only источник, сохранение доступно сверху и снизу только при изменениях. Город, каноническое название и тип являются read-only частями бизнес-ключа; для их изменения создается новый тариф. Slug меняется отдельно: цена, URL, статус и SEO требуют явного подтверждения, а URL дополнительно проходит conflict-check и подготовку 301; optimistic concurrency отклоняет устаревшую форму. После сохранения интерфейс показывает номер рабочей версии и предлагает отдельно опубликовать точную ревизию через общий publication control. Этот блок различает опубликованное состояние, неопубликованные изменения, выполняемую публикацию и ошибку; ведёт на общий review перед ручным запуском. До успешного завершения публикации публичный сайт показывает прежнюю версию. Выбора даты и времени нет. `/tariffs/import` содержит file input, diff, issues, apply, историю runs и такой же явный publication control для каждого сайта выбранного провайдера. `APPLIED` означает только сохраненную рабочую версию: автоматической пересборки больше нет. Для нового полного change set история показывает «Отменить импорт», запрашивает явное подтверждение и объясняет, что результат отмены также нужно опубликовать отдельно; при более поздней правке API блокирует кнопку конфликтом без частичного восстановления. Service token и browser storage не используются.

### Реализованные паттерны `/cities` и `/cities/import`

`/cities` содержит реальные счетчики, поиск по городу, slug и региону, таблицу статусов и условно открываемую боковую форму для изменения названия и публикационного статуса; slug, регион и сайт остаются read-only. Единые телефоны подключения и техподдержки не принадлежат городу и редактируются на `/variables`. Ручное сохранение показывает номер рабочей ревизии и обновляет общий publication control, через который публикация запускается отдельно. Отдельный `/cities/import` показывает каждую валидную строку XLSX и точные изменения, включая смену региона; для существующего slug оператор выбирает `update` или `skip`, для нового — `create` или `skip`, а измененную строку нельзя применить без явного решения. Там же находятся история импортов, guarded undo и общий publication control. Undo показывается только для примененного run с полным change set, требует подтверждения и блокируется, если город/созданные HOME или регионы менялись позже либо у нового города появились зависимые данные. Нативный `select` повторяет уже используемый в shell совместимый Field/Table-паттерн и не вводит новый UI-kit. API принимает только полный action map текущего report, отклоняет недопустимые пары и stale snapshot; errors блокируют apply, warnings требуют отдельного подтверждения. Пока платформа работает в односайтовом режиме: импорт разрешен только при ровно одном найденном сайте, чтобы будущая многосайтовость не привела к молчаливому выбору неправильной цели. Применение и отмена создают attributed рабочую ревизию; оператор отдельно запускает публикацию точного снимка, поэтому APPLIED и UNDONE не означают, что изменения уже видны на сайте.

### Реализованный паттерн `/variables`

Экран сохраняет две вкладки в одном React-root. «Значения сайта» изменяет только два типизированных телефона Site и рабочую ревизию. «Каталог подстановок» доступен только для просмотра: все реализованные коды, русское назначение, тип, источник и статус; поиск и фильтры по статусу, типу и источнику; выбор города и затем тарифа для контекстного рабочего/опубликованного значения. Детальная карточка показывает допустимые поля и места использования в рабочих строках (включая черновики, скрытые блоки и неактивные тарифы), исходных SEO/OG-шаблонах и сохраненном снимке публикации. SEO-запись открывает соответствующий тип в `/seo/templates`. Для исторического снимка без usage-метаданных интерфейс пишет «недоступно», а при старом неполном индексе отдельно предупреждает, что опубликованные SEO-использования неизвестны. Где редактор еще не реализован, ссылка не выдумывается. Каталог не разрешает менять код или технический источник; вставка кода в существующие редакторы SEO/OG и промотекста тарифа уже реализована, а интеграция будущих редакторов Page/Block остается задачей V3. Собран из существующих `Tabs`, `Card`, `Table`, `Field`, `Badge`, `Alert` и нативных `select` в стиле текущего shell; вкладки используют React Aria; клавиатурное поведение проверено в рамках #97.

В `/seo/templates`, `/tariffs/edit` и разрешённых текстовых полях `/templates/home` и `/templates/tariffs` доступна контекстная вставка активных системных кодов в текстовое поле у курсора либо вместо выделения. Палитра загружает компактные определения через защищённый API, показывает только допустимые для текущего поля и Site/City/Tariff-контекста коды, поддерживает поиск и не меняет URL OG-изображения. Сервер проверяет коды в четырёх текстовых полях SEO/OG в `promoText` тарифа и в заголовке/описании тарифного блока до сохранения; контекстные значения окончательно проверяются при построении каталога. Остальная миграция использования остаётся в #190.

### Реализованный паттерн `/leads`

Карточка нового лида показывает первый и последний переход текущей вкладки, время и число посещенных страниц, а IP, полный User-Agent, UTM и маршрут раскрывает в отдельном блоке технических данных. Историческая заявка с `attributionSnapshot=null` показывает явное отсутствие снимка. Данные выводятся React-текстом; возможность менять атрибуцию или использовать ее для маршрутизации отсутствует.

Карточка заявки отдельно показывает исходный пользовательский комментарий и неизменяемый снимок анализа: русскую категорию, точные найденные фрагменты, версию правил и объяснение ручной проверки либо предупреждения. Анализ не редактирует структурированную причину и не предлагает автоматический отказ; пользовательский текст выводится безопасным React-текстом без `innerHTML`.

Для фоновой цепочки карточка показывает проверку абонента, итоговый маршрут и хронологию `LeadDecisionEvent` с временем, номером телефонной попытки и безопасным evidence вместо полного ответа интеграции. Кнопка «Повторить проверку телефона» появляется лишь после финальной технической ошибки без `qc`; новый job имеет следующий глобальный номер и не обходит остальные проверки. «Повторно проанализировать комментарий» доступно только при новой серверной версии правил: исходная причина и текущий маршрут не переписываются автоматически, а предыдущий снимок и оператор остаются в аудите. Оба действия используют существующую cookie-auth границу и общий паттерн ошибок/занятости.

Экран собран как dashboard master-detail из `Card`, `Table`, `Badge`, `Alert`, `Field`, `Input` и `Button`: реальная сводка, поиск и фильтр списка, подробная карточка контекста, проверок, delivery attempts, обычного notification, activity и истории статусов. Журнал отдельно показывает операторский, processing- и notification-статус, а сводка считает заявки, требующие внимания, включая failed/queue-error оповещения. В карточке все address/contract/processing/channel/attempt/external/notification статусы переводятся на понятный русский текст с пояснением и безопасным fallback для неизвестного кода; внешний ID читается из `externalLeadId`, а технические коды оповещения скрыты в раскрываемых деталях. Для `DELIVERY_QUEUE_ERROR`, финальной ошибки delivery и старого orphan `PENDING` доступна кнопка повторной передачи; для финального `LeadNotification.FAILED` — отдельная кнопка повторного оповещения через persistent outbox. Смена одного из пяти операторских статусов отправляет комментарий в существующий `PATCH /crm/leads/:id/status`; конфликт параллельного редактирования остается видимым сообщением API. Данные выводятся React-текстом без `innerHTML`, raw service token и browser storage. Интерактивные примитивы используют React Aria; финальная проверка проведена в [#97](https://github.com/Celtoman/astro-telekom/issues/97). Нативные `select` используются внутри shadcn `Field`, потому что опубликованный `shadcn@4.21.0` CLI не запускается из-за отсутствующей runtime-зависимости `fs-extra`; новая зависимость или параллельный компонент ради обхода не добавлялись.

Для `/leads` и `/tariffs` поиск и фильтрация выполняются сервером, а таблицы получают bounded cursor-страницу вместо полного массива. Журнал заявок также фильтрует по закрытому справочнику причин обращения или отсутствию причины у исторической записи, показывает подпись в строке и неизменяемый снимок причины/маршрута в карточке. Тяжелые lead relations и дополнительные PII запрашиваются только при открытии карточки. Общий `ServerPagination` адаптирует актуальный паттерн React Aria-референса к существующим примитивам: показывает точное число совпадений, размер страницы и доступные кнопки «Назад/Далее» внутри именованной navigation-области. Номер отражает пройденную cursor-цепочку; переход к произвольной странице намеренно не обещается.

На всех фильтруемых каталогах `/leads`, `/tariffs`, `/cities`, `/redirects` и `/audit` постоянно отображается единая кнопка «Сбросить фильтры». Она неактивна при исходном состоянии; при сбросе очищает только поиск и фильтры, а у серверных списков также немедленно возвращает cursor на первую страницу. Размер страницы, открытая карточка и незавершенная форма редактирования сохраняются. Фильтры остаются только в React state до перезагрузки и не записываются в URL, `localStorage`, `sessionStorage` или именованные представления.

### Реализованный паттерн `/audit`

В dashboard-референсе нет отдельного специализированного CMS audit log, поэтому `/audit` адаптирует уже используемый master-detail паттерн: server-paginated таблицу событий и карточку выбранной записи из `Card`, `Table`, `Badge`, `Alert`, `Field`, `Input`, `Skeleton`, `Button` и общего `ServerPagination`. Оператор обязан выбрать сайт при неоднозначности, может фильтровать по сущности и действию и искать по ID, source или email автора. Общий список не загружает тяжелый field-level diff; значения до/после запрашиваются только при открытии записи и безопасно выводятся React-текстом или свернутым JSON без `innerHTML`. Технические enum-коды переведены на русский, неизвестное значение получает нейтральную подпись. Экран read-only: наличие истории не означает автоматический rollback или корзину.

### Реализованный паттерн `/trash`

Корзина использует существующий dashboard card/table-паттерн без нового UI-kit. После явного выбора сайта она показывает отдельные bounded-группы городов, страниц, тарифов, редиректов и блоков, точное общее количество и предупреждение при лимите 100 элементов группы. Оператор сначала выбирает запись, затем подтверждает восстановление в отдельном `Alert`; статусные сущности всегда возвращаются как `DRAFT`, а PageBlock — с прежним `visible`, поэтому восстановление не подменяет публикацию. UI переиспользует профильные versioned PATCH-контракты и отдельный guarded block restore, никогда не отправляет `DELETE`, service token и не хранит состояние в браузере. Время архивации города исторически не хранится в самой City, поэтому интерфейс честно направляет к `/audit`, а не показывает вымышленную дату.

### Реализованный паттерн `/preview`

В dashboard-референсе нет CMS page preview, поэтому экран адаптирует существующие toolbar/card/field-паттерны и не создает второй UI-kit. Оператор выбирает сайт, затем любой URL из текущего рабочего Release 1 inventory и размер 1440/834/390 px. API собирает рабочий catalog в serializable-транзакции и применяет те же проверки HOME, blocks и URL, что фиксация публикационного snapshot. Документ отображается только внутри `sandbox=""` iframe с собственным `default-src 'none'`; все CMS-значения HTML-экранируются, формы и ссылки не выполняются, внешняя ссылка и deployment не создаются. Общий CSP админки разрешает iframe только своего origin; Caddy по-прежнему запрещает встраивать саму админку во внешние страницы. Preview показывает рабочую и публичную ревизии и обновляется только по явной команде, чтобы оператор понимал, какой набор данных проверяет.

### Программный шаблон тарифа `/templates/tariff`

Раздел `/templates/passports` открывает отдельный пункт «Паспорта блоков» внутри группы меню «Страницы». Старый якорь `/templates#block-passports` переводится на этот маршрут. В рамках [#232](https://github.com/Celtoman/astro-telekom/issues/232), по согласованному макету PF-027, реализованы поиск по русскому названию, фильтр размещения, компактный список с ограниченной высотой и прокруткой на компьютере и одна выбранная карточка. В ней видны назначение, русский статус, схематичный пример (не данные сайта), контент и ссылки на существующие источники: `/variables` для телефонов Header и `/tariffs` для данных секций тарифа. Для остальных блоков редактор не выдумывается; городской редактор #193 пока недоступен. Размещение обозначает программный/общий шаблон, а не подтверждённое число использований. Для блоков без примера показано честное пустое состояние.

Технические IDs, версии, источники, ограничения, preview/accessibility и полная JSON-запись доступны в закрытых по умолчанию details; точные Figma device-ссылки и runtime-правила сохранены там. Ссылка на основной Figma-макет доступна в карточке. Ниже 1024 px карточка открывается в React Aria Modal/Dialog: focus trap, Escape, «К списку» и возврат фокуса; поиск и фильтр сохраняются при закрытии. Использованы локальные Card/Button/Input/Tabs/Badge, нативный select и React Aria modal-паттерн обязательного Sheet-референса, повторно сверенного 5 октября 2026 года. Прямого готового реестра паспортов в референсе нет, поэтому доменная карточка собрана из совместимых примитивов без отдельного CSS/UI-kit. Loading, ошибка с повтором, пустой реестр и отсутствие результатов различаются. Все данные читаются из защищённого `GET /admin/block-passports`; CMS не меняет схему или lifecycle. 5 октября в реестр перенесено внешнее согласование владельцем двух первых экранов: они показываются как «Утверждён», версия 1.0.0; остальные паспорта — черновики. Карточка показывает согласованные поля, включая собственные подписи адреса/проверки; два готовых редактора открываются из карточек, для остальных блоков отсутствие редактора отмечено явно.

Отдельная карточка «Страница тарифа» в общем разделе «Шаблоны страниц» показывает фиксированный порядок потенциальных блоков, их источники и пометку «Программный шаблон». Оператор сначала выбирает сайт и город, затем ищет тариф по названию, slug или внешнему ID. Рабочая версия доступна и для черновика или архивной записи; опубликованная берется только из последнего успешного snapshot. Экран показывает список различающихся полей, ревизии и время публикации данных отдельно от версии приложения, последнего успешного deployment и состояния Coolify. Недоступность Coolify выводится явно, без вымышленного статуса.

Структурный preview текущего шаблона имеет режимы 1440/834/390 px и всю доступную ширину. Текст выводится React-экранированием, без `innerHTML`; в самом preview нет ссылок, формы заявки или внешних переходов. Ссылка на защищённый test-контур находится отдельно от canvas. Конфигуратор запрашивает расчёт у защищённого API через общий `quoteTariffConfiguration`, но не создает лид и не меняет публикацию. Ссылка на редактор ведёт только к данным рабочего тарифа, а изменение блоков и кода через CMS не предоставляется. Общий `/preview` остаётся отдельным read-only экраном маршрутов Release 1.

Для рабочей или опубликованной версии API выбирает реальные примеры шести сценариев: интернет, интернет + ТВ, игровой тариф, оборудование, дополнительные услуги и минимальная комплектация. Непокрытый сценарий показывается предупреждением; примерные данные не создаются. Диагностика текущего тарифа проверяет общий с публичной витриной renderer и серверный расчёт, указывает URL, шаблон, блок и поле; ошибка подчеркивает блок схемы или canvas. Ошибка разрешения переменной в рабочем промо-тексте не скрывает весь preview: поле видно в диагностике, а canvas с неразрешённым токеном не отрисовывается. Сохранённый отчёт проверки публикации показывается с ревизией и временем как история, без подсветки текущего canvas: совпадение номера версии приложения не доказывает совпадение commit.

### Реализованный паттерн `/redirects`

В dashboard-референсе нет отдельного специализированного редактора HTTP redirects, поэтому экран собран из уже установленных совместимых примитивов `Card`, `Table`, `Badge`, `Alert`, `Field`, `Input`, `Skeleton` и `Button`. Он использует общий cookie-auth shell, реальные `/admin/sites` и `/admin/redirects`, поддерживает создание, редактирование, архивирование/восстановление, поиск и статистику `hitCount`/`lastHitAt`. Любая ручная мутация сохраняет рабочую ревизию без пересборки, показывает ее номер и обновляет общий publication control. Интерфейс намеренно не дублирует серверные правила: API остается источником проверки опубликованной цели, конфликтов URL, петель и цепочек. В текущем односайтовом UI операция блокируется, если сайт нельзя выбрать однозначно.

### Реализованный паттерн `/seo/sitemap`

Раздел SEO использует вложенную навигацию и отдельный React-workspace Sitemap. Верхний уровень показывает origin, результат последней генерации, validation и общий publication control. Tabs разделяют страницы, города и тарифы; каждая вкладка показывает счетчик включенных URL, поиск, постраничную таблицу источника/статуса, доступный checkbox и обязательную причину исключения. XML-preview сразу учитывает несохраненный выбор. UI прямо объясняет, что исключение влияет только на sitemap, не удаляет страницу и не добавляет `noindex`; сохранение создает рабочую ревизию, после чего оператор отдельно публикует точный snapshot.

`/seo/templates` — отдельный Astro-маршрут с одним cookie-auth React-root. Оператор выбирает один из восьми типов Release 1, правит Title/Description и index/noindex в типизированных полях, видит число затрагиваемых URL и конкретный рабочий/опубликованный URL-preview. Отдельный блок «Социальные сети · Open Graph» содержит необязательные OG Title, Description и image URL; preview показывает фактические fallback-значения. При переходе типа в noindex требуется отдельное подтверждение точного количества URL; рабочий снимок сохраняется с optimistic revision и публикуется отдельно. Неразрешённые переменные и пустые обязательные поля блокируют сборку снимка; длина и дубли дают предупреждения. Административное исключение sitemap по-прежнему не является noindex, но активный noindex-шаблон автоматически выводит URL из sitemap и делает его исключение недоступным для ручного редактирования.

Локальные Page/Tariff/PageTemplate SEO JSON-поля удалены в #200 после сверки метаданных всех 4 018 маршрутов. Рабочие SEO-значения редактируются только через типизированные шаблоны сайта.

`/trash` показывает архивные тарифы вместе с другими сущностями. Отдельная кнопка открывает постраничный read-only предпросмотр физической очистки по 25 тарифов: для каждой строки видны связи, которые запрещают удаление. Только записи без блокирующих связей доступны для пакетного удаления; оператор видит повторное предупреждение о необратимости, а сервер повторно проверяет тот же fingerprint и связи до транзакционной очистки. Результат остаётся рабочей ревизией и не публикуется автоматически. Экран собран из существующих `Card`, `Alert`, `Table`, `Badge` и `Button` без нового UI-паттерна.

### Реализованный паттерн `/lead-access/`

В dashboard-референсе нет специализированного экрана для одноразового просмотра заявки. Поэтому экран собран из перенесенных shadcn/ui-примитивов `Card`, `Alert` и `Skeleton`, используемых самим референсом, без копирования Next.js-специфичного кода. Astro отвечает за маршрут и оболочку, единственный React-root — за получение и отображение данных через API. Raw access token читается из URL fragment, сразу удаляется из адресной строки и проверяется только сервером.

## Область действия

Правило касается только `apps/admin`. `apps/web` (публичная витрина) им не связан. Единственная административная UI-поверхность находится в `apps/admin`; отдельный CRM-workspace не восстанавливать.

## Удаленный legacy `index.astro`

Прежний `apps/admin/src/pages/index.astro` был plain HTML/CSS с inline vanilla JS, вымышленными KPI и `window.prompt` для высокопривилегированного токена. Он удален при создании cookie-auth shell. Не восстанавливать старую верстку и скрипты: недостающие рабочие экраны реализуются React-root компонентами на shadcn/ui и реальных HTTP API-данных.

## DoD-чек для любой новой/переработанной части admin UI

Перед завершением задачи по `apps/admin`:

1. Использован ли подходящий компонент или паттерн из `next-shadcn-admin-dashboard-aria`? Если нет — зафиксировано ли, почему он не подходит или отсутствует?
2. Если готового блока для конкретного экрана нет — собран ли он из совместимых React Aria-based shadcn/ui-примитивов (Button, Table, Sidebar, Card, Dialog и т.д.) в стилистике референса, а не с нуля на голом CSS?
3. Соответствует ли визуально макет живому демо (layout, отступы, типографика, состояния — default/hover/focus/disabled, где применимо)?
4. Проверена ли тёмная тема, если референс её поддерживает для затронутого экрана?
5. Не добавлен ли ad-hoc CSS/HTML в стиле старого `index.astro`, создающий параллельный UI-паттерн?
6. Получает ли интерактивный экран данные через API во время работы и проверяет ли API доступ пользователя независимо от того, что скрыто в интерфейсе?

### Контент двух первых экранов — `/templates/home`

Форма использует существующие Card, FieldGroup/FieldSet/Field, Input, Badge, Alert и Button, а также VariableInsertionPicker с вставкой в курсор title/text. Прямого готового редактора этих доменных паспортов в обязательном референсе нет; применяется его паттерн формы настроек с основным контентом и боковой карточкой проверки. Новая дизайн-система и зависимости не добавлены. Нативные select и textarea повторяют уже принятый паттерн SEO-редактора; CLI shadcn 4.21.1 для документации не запустился из-за отсутствующего @shadcn/registry, поэтому документация сверена на официальном сайте.

Показываются только разрешённые поля: текст, изображение/alt, две собственные подписи формы, три пояснения HOME либо подпись перехода к тарифам CITY_HOME. Системные расчёты и структура недоступны для изменения. Смена блока/сайта и обновление данных предупреждают о несохранённых изменениях; поля блокируются во время сохранения. Неполный безопасный черновик сохраняется как «Не готово». Ошибка API/конфликт сохраняют введённые значения и доступны для повторной загрузки; 401 переводит на login. Published-контент берётся из sourceSnapshot последней успешной публикации; отсутствующий снимок не заменяется рабочими данными. Кнопка preview открывает сохранённую рабочую версию; sandbox отключает формы и переходы. Общий preview пока не является полной визуальной копией public renderer (#235).

### Визуальный контракт общего `/preview`

Рабочий catalog проходит через публичные `tariffView`, `heroFacts` и `legalSections`. ### Переходы из использования переменных

В каталоге переменных `title`/`text` Hero общей и городской HOME открывают текущую рабочую версию `/templates/home` с `kind` и `siteId`. Сайт из ссылки выбирается только среди доступных сайтов; неизвестный siteId не открывает чужой workspace. Опубликованная колонка хранит evidence снимка и явно объясняет, что ссылка ведёт в рабочую версию. Заголовок/описание тарифного блока CITY_HOME ведут в `/templates/tariffs` с тем же site context. Остальные template-поля без редактора не получают фиктивную ссылку; будущие интеграции остаются в #190.

## Переходы между разделами

Разделы админки используют Astro ClientRouter и общий сохраняемый AdminWorkspace React-root. Меню, шапка и publication polling сохраняются, а каждый lazy экран монтируется заново по pathname/query и проверяет свежую сессию и рабочие данные. Совпадающие одновременные GET объединяются; завершённые ответы не кешируются, мутация/401 прекращает объединение старых чтений. Смена пользователя перемонтирует индикатор; изменение component URL после code deployment снимает persistence. Login, lead-access и sandboxed preview сохраняют отдельные документы.

Защита несохранённых форм использует существующие React Aria ModalOverlay/Dialog и Button: начальный фокус на «Остаться», Escape/закрытие отменяет переход, «Перейти без сохранения» разрешает его. Внутренние ссылки и Back/Forward защищены; полная перезагрузка/внешняя ссылка сохраняют beforeunload. После открытия раздела фокус переходит к main, мобильное меню закрывается. Ошибка lazy chunk/render показывает ошибку и кнопку обновления страницы. [приёмка #259/#260](research/2026-10-06-admin-navigation-and-rate-limits.md).

### Рабочий раздел «Страницы» — #193

В sidebar родительская группа «Страницы» раскрывает два пункта: «Шаблоны страниц» и «Паспорта блоков». `/templates` использует существующий Card/list/link-паттерн: две карточки HOME и CITY_HOME, фактический список блоков и прямой вход в их редакторы. Шапка и подвал обозначены как общие элементы CODE; технический тарифный preview доступен вторичной ссылкой `/templates/tariff`. Специализированный CMS layout отсутствует в dashboard-референсе, поэтому экран адаптирует уже принятые Tailwind/shadcn Card, Field, Input, Button, Badge и Alert без отдельного CSS-набора.

`/templates/tariffs` разделяет содержание и показ карточек: семь редактируемых полей, пояснение приоритета, сохранение с optimistic revision, missingFields/черновик и прямые ссылки на общий preview/publication. Число оставшихся карточек задаёт система, цены/состав/закрепление — каталог. Дополнительного выбора города и режимов раскрытия в редакторе нет. Persistent AdminWorkspace, cookie session, dirty navigation guard и loading/error/retry/empty состояния сохраняются. Паспортный master-detail с поиском и React Aria modal остаётся прежним, но выведен в отдельный маршрут; текущий реестр содержит только используемые блоки.


### Диагностика перед публикацией

PublicationIssueCard использует существующие Badge, Button/anchor и семантические Tailwind-токены референса. Порядок: серьёзность → шаблон/блок → русское поле → причина → действие. Системные ошибки и служебные данные без detail URL имеют отдельные формулировки. [publication.md](publication.md).

## Быстрый возврат в разделы (#271)

Кэшем управляет общий HTTP-клиент; он находится только в памяти вкладки, не в localStorage/IndexedDB. Готовые списки городов и тарифов, реестр паспортов и read-only каталог подстановок показываются сразу при повторном открытии в пределах 30 секунд. Каждый возврат всё равно запускает серверную проверку. Состояние «Обновляем данные…»/«Обновляем каталог…»/«Обновляем реестр…» объявляется через role=status; после ответа появляется «Данные обновлены». При неуспехе показаны явная ошибка и ранее загруженные данные, без заявления об их актуальности. Это существующие Tailwind/shadcn Alert и текстовые live-region паттерны; отдельный визуальный компонент или UI-kit не создаётся.

Справочники и списки сбрасываются на начало и завершение мутации, новую опубликованную ревизию, logout, 401 и смену пользователя. Фокус вкладки повторно проверяет только открытый read-only экран. Формы не перезаполняются этим событием. Городская форма недоступна до свежего каталога и фиксирует workingRevision строки при открытии, поэтому обновление метаданных не подменяет ревизию несохранённой формы. Остальные редакторы, заявки/PII и публикация продолжают читать свежие DTO без повторного использования завершённого ответа. Временный сбой проверки сессии в фоне показывается отдельным Alert; следующий переход требует свежей проверки. Код раздела подгружается по hover/focus ссылки, API-запросы и полный каталог при этом не предзагружаются. [Приёмка и измерения](research/2026-10-08-admin-navigation-cache.md).
