## Версия и жизненный цикл

4 октября 2026 года владелец выбрал для реализации Header `79:69`, Hero 1b `873:30` для `/` и Hero V3 `991:2` для городской HOME ([#228](https://github.com/Celtoman/astro-telekom/issues/228)). В публичном коде `hero` читает семь утверждённых полей из управляемого блока, а системные адресная форма, факты доступного каталога и CTA `#tariffs` собираются `HomeHero.astro`. Сохранённые legacy `eyebrow/ctaText/ctaHref` не управляют этими элементами городского V3. Это выбор визуальных вариантов и перенос кода, а не утверждение полей всех паспортов или lifecycle API. Объём C3 уточнён владельцем: два Hero и новый тарифный блок, без редакторов устаревших секций.

Предусмотрен порядок `DRAFT → APPROVED → ACTIVE → DEPRECATED → ARCHIVED`. В CMS **нет действий перехода статуса**, назначения утверждающего, замены или редактирования паспорта. В реестр перенесено внешнее решение владельца: home.hero имеет APPROVED/2.0.0, городской hero и тарифный блок — APPROVED/1.0.0, все с записью о согласовании владельца; Header и девять тарифных блоков остаются DRAFT/0-draft. `editorReadiness=READY` означает наличие проверенного предметного редактора в текущем коде; готовность публичного renderer и preview подтверждается отдельно, внешний deployment и применение миграции проверяются отдельно. `0-draft` не включается в опубликованный snapshot как утверждённая версия. После решения владельца изменение полей или их смысла потребует новой версии, миграции и проверки; используемый блок нельзя физически удалить. Задача C2 уже перевела городские HOME на общий `PageTemplate`; Оставшиеся C4–C6 ведутся отдельно; текущий объём C3 описан ниже.

В #231 были представлены три DRAFT-контракта Header, общей и городской Hero. Согласование владельца 5 октября 2026 года утверждает только два первых экрана и включает собственные поля адресной подсказки и подписи проверки. Header и остальные паспорта этим согласованием не утверждены. Утверждение само по себе не подтверждает ACTIVE или deployment. Реализация двух редакторов отражена отдельно в editorReadiness=READY.

## Тарифы города — `tariff_grid`

Размещение только CITY_HOME; Figma B04 `93:569`, Desktop `93:3`, Tablet `93:195`, Mobile `93:382`. Полный опубликованный каталог без фильтров, ручного списка карточек и ссылки «Все тарифы». Редактор `/templates/tariffs` сохраняет семь полей:

| Поле | Контракт |
| --- | --- |
| title | До 120 символов, обязательно; Site/City переменные |
| text | До 1000 символов, необязательно; Site/City переменные |
| connectButtonText | До 80 символов, обязательно; действие — адресная проверка выбранного тарифа |
| detailsButtonText | До 80 символов, обязательно; действие — существующая detail-страница тарифа |
| moreButtonText | До 80 символов, обязательно; один клик показывает весь остаток |
| initialCount | Целое 1–100, по умолчанию 6; полный каталог не ограничивается |
| sort | PRICE_ASC/PRICE_DESC, по умолчанию PRICE_ASC; настройка администратора |

Закреплённые `attributes.is_sticky=true` идут первыми; внутри двух групп сравнивается текущая месячная цена `promoPrice ?? standardPrice`. Неизвестная цена последняя, одинаковые цены сохраняют порядок каталога. Новое числовое поле приоритета не вводится. Цены, скорость, TV, подписки, игровой вариант и характеристики берутся из TariffView. Разовое подключение и дополнительные опции не участвуют в сортировке.

Рядом с подписью «Показать ещё» система выводит число оставшихся тарифов; при количестве ≤initialCount кнопки нет. Порядок после раскрытия не меняется. Без JavaScript доступен весь каталог; с JavaScript остаток скрывается до одного клика. В sandbox preview видна первая группа и неактивная кнопка, ссылки/заявки отключены. Desktop — три колонки, tablet — две, mobile — горизонтальная лента; длинные реальные значения не обрезаются.

Сохранение меняет только рабочий PageTemplateBlock.data с expectedWorkingRevision и before/after аудитом; безопасный неполный черновик сохраняется, публикация обязательных полей блокируется. Миграция 0058 скрывает старые пять блоков, сохраняет их данные и историю. Старые immutable snapshots не переписываются; renderer поддерживает только точную прежнюю семиблочную композицию и проецирует её в Hero + тарифы. `#tariffs`, общая шапка/подвал и страницы тарифов сохранены.


## Контракты новых блоков общей HOME — этап 1

Исполнимые схемы находятся в [`general-home-model.ts`](../apps/api/src/general-home-model.ts), проверки — в [`general-home.ts`](../apps/api/src/general-home.ts), метаданные паспортов — в [`general-home-passports.ts`](../apps/api/src/general-home-passports.ts). Оболочка Header/Footer в массив десяти контентных блоков не входит.

Фиксированные карточки передаются объектами со смысловыми ключами. Порядок свойств JSON не меняет визуальный порядок; позиция определяется схемой. FAQ — переменный массив пар. Валидатор черновика допускает пустые строки/FAQ, возвращая пропуски; неизвестные поля, неверные типы/ключи, опасные URL, HTML, запрещённые переменные и превышения лимитов отклоняются и в черновике. В строгом режиме пропуск вызывает структурированную ошибку `block/field/reason`. На этапе 2 контракт подключён к publication preflight; сохранение неполного черновика не разрешает его публикацию.
