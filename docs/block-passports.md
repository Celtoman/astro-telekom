# Черновые паспорта блоков прототипа

Статус: **DRAFT, версия `0-draft`** для каждого паспорта. Это инвентаризация текущего кода для [C1/#191](https://github.com/Celtoman/astro-telekom/issues/191), а не утверждение дизайна или разрешение на production-редактор. Владелец утверждает окончательные состав и смысл полей вместе с финальным дизайном (`OPEN-005`). Правила — [продуктовый контракт, раздел 5](product-contract.md#5-шаблоны-и-блоки), [решения, раздел 3](decisions.md#3-блоки-и-паспорта) и `CMS-038–049` в [реестре решений](research/2026-09-16-product-decisions-recovery-register.md).

Типизированный реестр с полями, источниками, контролами, валидацией, поведением пустых данных, preview и доступностью находится в [`apps/api/src/block-passports.ts`](../apps/api/src/block-passports.ts). Авторизованный `GET /api/v1/admin/block-passports` отдаёт его только для чтения; раздел `/templates#block-passports` показывает те же данные без кнопок изменения статуса. Реестр не меняет действующую валидацию, рендеринг, публикацию или схему БД. API по-прежнему валидирует управляемые блоки через `block-validation.ts`, а тарифную страницу строит программный `TariffDetail.astro`.

## Управляемые типы блоков

| ID | Назначение и предполагаемые страницы | Источники и пустые данные | Preview и доступность |
| --- | --- | --- | --- |
| `hero` | Первый экран; текущая городская `HOME` | `PageTemplateBlock.data`: eyebrow, title, text и парная CTA. Нет обязательных title/text — сохранение отклоняется; нет CTA — кнопка отсутствует. | Длинный заголовок и разные CTA; один H1, доступная ссылка, декоративная графика скрыта от скринридера. |
| `rich_text` | Краткий текст; будущие `INTERNET`, `INTERNET_TV`, `TV`, `FAQ` как **черновое предложение**, не маршрут Release 1 | Предлагаемые поля блока `title/text`; физический источник для будущих страниц ещё не реализован; пустые обязательные значения отклоняются. | Длинный текст; H2 и читаемый порядок. |
| `tariff_grid` | Опубликованные тарифы города; текущая `HOME` | `PageTemplateBlock.data.title/serviceType/limit/morePageType` и опубликованный каталог. Без тарифов виден текст пустого состояния. В Release 1 renderer показывает все тарифы города и фиксированный заголовок; сохранённые `title/serviceType/limit/morePageType` сейчас не управляют выводом. | Есть/нет предложений, разные цены; H2/H3, подписанные действия и клавиатурный доступ. |
| `service_grid` | Выбор услуги; текущая `HOME` | `PageTemplateBlock.data.title/items`, 1–8 элементов. Актуальные `INTERNET`, `INTERNET_TV`, `TV` открывают форму со своим типом услуги; `ADDRESS_CHECK` и `FAQ` остаются информационными карточками без кнопки заявки. Пустой список отклоняется. | Один/несколько вариантов; H2/H3 и подписанные кнопки. |
| `feature_grid` | Преимущества; текущая `HOME` | `PageTemplateBlock.data.title/items`, 1–8 пар заголовок/текст; пустые данные отклоняются. | Разная длина карточек; H2/H3, декоративная нумерация. |
| `steps` | Последовательность подключения; текущая `HOME` | `PageTemplateBlock.data.title/items`, 2–8 пар заголовок/текст; меньше двух шагов отклоняется. | Два/восемь этапов; семантический `ol`. |
| `faq` | Вопросы и ответы; текущая `HOME` | `PageTemplateBlock.data.title/items`, 1–12 пар вопрос/ответ; пустые строки отклоняются. | Длинные ответы; нативные `details/summary` и клавиатурное раскрытие. |

В текущем прототипе данные семи блоков городской HOME принадлежат одному site-scoped `PageTemplate(CITY_HOME)` и хранятся в `PageTemplateBlock`. Прежние 207 наборов `PageBlock` сохранены только как исторические read-only строки до C6; новый город получает HOME-shell со ссылкой на шаблон без локальной композиции. Область `TEMPLATE` реализована для городской HOME, но окончательные паспорта будущих типов страниц ещё **не утверждены** владельцем. Read-only API реестра пока описывает старый источник `PageBlock.data`; это отдельная открытая [#227](https://github.com/Celtoman/astro-telekom/issues/227). Городская HOME Release 1 требует одну фиксированную последовательность из семи видимых блоков, включая два `feature_grid`; список выше перечисляет **типы**, поэтому записей семь.

## Программные секции страницы тарифа

Все секции ниже имеют предполагаемую область `CODE`, страницу `CITY_TARIFF_DETAIL` и только read-only паспорт. Состав и порядок задаёт `TariffDetail.astro`; данные тарифа меняются в редакторе тарифа, а код секции — через разработку и deployment.

| ID | Источник | Если данных нет / что проверить |
| --- | --- | --- |
| `tariff.hero` | Имя, тип услуги, скорость, TV-состав и цены опубликованного тарифа | Обязательная цена или несовместимый состав блокирует renderer; проверить один H1 и явный состав. |
| `tariff.description` | `opisanie_tarifa` | Секция скрыта без текста; проверить безопасный вывод. |
| `tariff.cinemas` | Закрытые коды `online_cinemas` | Нет кодов — секция скрыта; неизвестный код блокирует renderer. |
| `tariff.equipment` | Типизированные цены выкупа и рассрочки | Нет полного доступного варианта — секция скрыта; проверить сумму и период. |
| `tariff.services` | Статусы услуг, цены и `game_code` | Нет валидных сервисов — секция скрыта; проверить известные коды. |
| `tariff.configurator` | Серверный quote опубликованного снимка | Ошибка расчёта блокирует проверку; не подставлять нулевую цену. |
| `tariff.address` | Системная AddressForm и address-check API | Форма остаётся; в admin preview отправка отключена. |
| `tariff.related` | Другие опубликованные тарифы того же города | Нет подходящих — секция скрыта. |
| `tariff.faq` | Фиксированные вопросы и опубликованная форма имени города | Секция остаётся; нативное раскрытие вопросов. |

Подробные поля, контрольные сценарии и требования доступности каждой секции перечислены в типизированном реестре и отображаются в админке. В частности, preview должен проверять `INTERNET` и `INTERNET_TV`, пустые условные секции, недопустимые коды и клавиатурное управление.

## Версия и жизненный цикл

Предусмотрен порядок `DRAFT → APPROVED → ACTIVE → DEPRECATED → ARCHIVED`. В текущем коде **нет переходов статуса**, утверждающего лица, замены или CMS-редактирования паспорта: все 16 записей остаются `DRAFT` и `approvedBy=null`. `0-draft` не включается в опубликованный snapshot как утверждённая версия. После решения владельца изменение полей или их смысла потребует новой версии, миграции и проверки; используемый блок нельзя физически удалить. Задача C2 уже перевела городские HOME на общий `PageTemplate`; C3–C6 остаются отдельными задачами редакторов и очистки legacy-контента.
