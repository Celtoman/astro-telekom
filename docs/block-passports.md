# Паспорта блоков

Текущий реестр содержит **13 паспортов**: два первых экрана и `tariff_grid` имеют **APPROVED/1.0.0**, `editorReadiness=READY`. Header и девять блоков страниц тарифов остаются **DRAFT/0-draft**, управляются кодом. APPROVED не становится ACTIVE автоматически. `/templates/home` редактирует Hero, `/templates/tariffs` — тарифы города; внешнее применение миграций и deployment подтверждается отдельно.

Для замены `home.hero` на Figma Hero 1d подготовлен [предлагаемый паспорт версии 2.0.0 и порядок внедрения](plans/2026-10-13-home-hero-1d-contract.md). Порядок согласован 13 октября 2026 года с поправкой городской навигации; точные поля и открытые решения проходят отдельный review. Типизированный реестр и API пока используют 1.0.0; черновик не меняет статус действующего паспорта и не подтверждает внедрение.

Типизированный реестр с полями, источниками, контролами, валидацией, поведением пустых данных, preview и доступностью находится в [`apps/api/src/block-passports.ts`](../apps/api/src/block-passports.ts). Авторизованный `GET /api/v1/admin/block-passports` отдаёт его только для чтения; раздел `/templates/passports` показывает те же данные без кнопок изменения статуса. С 5 октября 2026 года (#232) обычный просмотр содержит поиск, фильтр размещения и выбранную карточку; полный контракт доступен в свёрнутых технических подробностях. Примеры в карточке схематичны и не являются live preview сайта. Переходы к источникам контента используют существующие переменные сайта и каталог тарифов; два первых экрана ведут в свой редактор `/templates/home`; остальные формы главной пока не подключены. Реестр не меняет действующую валидацию, рендеринг, публикацию или схему БД. Первые экраны дополнительно валидируются через `first-screen.ts`; API валидирует остальные управляемые блоки через `block-validation.ts`, а тарифную страницу строит программный `TariffDetail.astro`.

Исторически реестр #231 содержал 18 записей. По решению владельца в #193 пять старых типов `rich_text/service_grid/feature_grid/steps/faq` исключены из текущего реестра и главных страниц; новые Figma-блоки будут добавляться отдельно. Их legacy данные/история сохраняются, как и все блоки страниц тарифов.

## Шапка сайта — `header`

- **Назначение и страницы:** общая навигация и контакты на `/`, CITY_HOME, CITY_TARIFF_DETAIL, обязательных общих страницах и 404.
- **Область:** `CODE`; шапка размещается глобально через `BaseLayout.astro`. Контакты принадлежат глобальному `Site`, список городов — опубликованному каталогу. Локальных копий контента для городов нет.
- **Дизайн:** [Block/B01 Header — `79:69`](https://www.figma.com/design/PiSCXYR88uqqcS6tKVfd8T?node-id=79-69); Desktop `79:3`, Tablet `79:28`, Mobile `79:50`, сверены в живой Figma 4 октября.

| Поле | Источник и правило | Редактирование |
| --- | --- | --- |
| `logo` | `/images/figma/domru-logo.png`, фиксированные Дом.ру и ссылка `/`; не из `Site.name` | В коде |
| `activeCity` | `City` текущего URL имеет приоритет; иначе опубликованный `City.slug=moskva` | Через выбор опубликованного города и переход на его HOME |
| `publishedCities` | `loadSiteData().cities`: название, slug и регион; поиск по городу/региону без регистра, с нормализацией ё/е | В каталоге городов |
| `connectionPhone`, `supportPhone` | Обязательные глобальные телефоны `Site`; `tel:` очищается от форматирования | В глобальном источнике Site |
| `navigation` | Тарифы выбранного города, справочник городов, карта покрытия | В коде |
| `addressAction` | Локальный `#address-check` на HOME с Москвой и CITY_HOME; иначе `/{city}#address-check` | В коде |
| `callback` | Существующая адресная проверка с пояснением; межстранично `?callback=1#address-check` | В коде |
| `subscriberMode` | Существующий режим абонента заменяет основной номер/подпись на поддержку | Системное состояние |

**Пустые данные:** если Москва не опубликована и URL не задаёт город, надпись «Москва» остаётся обозначением исходного города; тарифы/адрес/callback открывают выбор опубликованного города. Несуществующая ссылка `/moskva` не создаётся и первый город каталога не подставляется. Пустой каталог и поиск без совпадений имеют разные сообщения. Отсутствующий обязательный телефон отклоняется при загрузке каталога; фиктивный номер не выводится.

**Поведение:** выбор города меняет URL и переносит якорь исходного действия; сохранения выбранного города в браузере нет. «Заказать звонок» объясняет необходимость адресной проверки, телефон запрашивается только после положительного результата. Отдельная callback-форма/API не реализованы; идея — `PF-026`. Неподтверждённые часы работы не показываются.

**Адаптивность и доступность:** desktop >1100 px — строки 40/88 px; tablet 621–1100 px — 40/80 px, телефон скрыт, при ≤760 px навигация скрыта; mobile ≤620 px — 36/72 px, телефон и меню, CTA внутри меню. При ≤360 px скрывается иконка телефона. Нативные dialog имеют заголовок, подписанный поиск, Escape и возврат фокуса; переход меню → выбор города/адрес сохраняет конечный фокус. Иконки декоративные, логотип имеет alt.

**Редактор и preview:** контракт только для чтения, отдельной формы Header нет. Проверить URL-город/Москву/отсутствующую Москву, пустой каталог, поиск и ё/е, локальный и межстраничный callback, поддержку в режиме абонента, клавиатуру и ширины 320/390/834/1440 px.

**Утверждение:** владелец, 2026-10-05, версия `1.0.0`, статус APPROVED. **Область:** контент своего шаблона `PageTemplate(HOME)`, только `/`. **Дизайн:** Figma `873:30`, варианты `873:31` / `873:57` / `873:80`.

| `text` | Обязательное описание до 1000 символов | Многострочное поле |

| `checkButtonText` | Обязательная подпись проверки до 80 символов | Собственное поле этого первого экрана |

HTML/JavaScript запрещены. «Введите ваш адрес» и «Проверить» не являются глобальными значениями AddressForm и могут отличаться от городской главной. Логика формы общая: дом → проверка → телефон только при TARGET_AVAILABLE → согласие и заявка. Москва остаётся исходным опубликованным городом; без неё предлагается выбор города. Тарифов и тарифных показателей на `/` нет.

**Фактическая реализация:** `PageTemplate(HOME)` хранит один `home.hero`; API отдаёт его как `catalog.homeHero`, а `index.astro` передаёт поля в `HomeHero.astro`. Специализированный валидатор `first-screen.ts` проверяет семь полей независимо от старого BLOCK_TYPES. Миграция 0056 переносит текущие значения; новые сайты получают HOME при создании. Неполный безопасный контент сохраняется как «Не готово», обязательные поля блокируют публикацию. Исторические опубликованные snapshots без homeHero сохраняют прежний программный рендеринг.

**Preview и доступность:** длинные тексты/alt, другое изображение, три пояснения, свои подписи адреса/проверки, опубликованная/отсутствующая Москва, все состояния формы; 320/390/834/1440 px. Один H1, подписанное поле адреса независимо от placeholder, доступная кнопка и описательный alt; декоративные иконки скрыты от скринридера.

### Первый экран городской главной — `hero`

**Утверждение:** владелец, 2026-10-05, версия `1.0.0`, статус APPROVED. **Область:** общий `PageTemplate(CITY_HOME)`, без индивидуального контента города. **Дизайн:** Figma `991:2`, варианты `991:3` / `991:17` / `991:31`.

Редактируются обязательные `title`, `text`, `image`, `imageAlt`, `addressPlaceholder`, `checkButtonText` с теми же типами и ограничениями, что у первого экрана общей главной. Заголовок/описание поддерживают разрешённые переменные города, например `{CITY_NAME_PREPOSITIONAL}`. Дополнительно редактируется `tariffsCtaText` — текст перехода к тарифам до 80 символов; ссылка фиксирована `#tariffs`. Трёх пояснений общей главной здесь нет.

**Источники:** редактируемые значения — `PageTemplateBlock.data` общего шаблона; подсказка адреса и подпись проверки принадлежат этому первому экрану независимо от общей главной. Системные город и адресный сценарий не редактируются. Минимальная стоимость, максимальная скорость и число каналов считаются из доступных опубликованных тарифов города; null не становится нулём, показатели могут относиться к разным предложениям. Legacy `eyebrow/ctaText/ctaHref` не входят в утверждённый редактируемый контракт и не управляют V3.

**Фактическая реализация:** renderer использует семь утверждённых полей. `/templates/home?kind=CITY_HOME` меняет только данные hero, сохраняя состав, ID, видимость и порядок остальных блоков; expectedWorkingRevision и serializable transaction защищают от перезаписи параллельных изменений. Миграция 0056 сохраняет title/text и переносит программные значения; legacy eyebrow/ctaText/ctaHref удаляются только из рабочего шаблона. Неполный черновик сохраняется, но блокирует публикацию. content шаблона фиксирует firstScreenPassportVersion=1.0.0 и firstScreenImplementationVersion=first-screen-editor-v1, поэтому они входят в неизменяемый sourceSnapshot.

**Preview и доступность:** разные города и тарифные составы, неизвестные показатели, длинные тексты/alt, собственные подписи адреса и кнопок, 320/390/834/1440 px и все состояния общей формы. Один H1, показатели `dl/dt/dd`, доступные форма/ссылка, описательный alt, декоративные иконки скрыты от скринридера.

## Версия и жизненный цикл

4 октября 2026 года владелец выбрал для реализации Header `79:69`, Hero 1b `873:30` для `/` и Hero V3 `991:2` для городской HOME ([#228](https://github.com/Celtoman/astro-telekom/issues/228)). В публичном коде `hero` читает семь утверждённых полей из управляемого блока, а системные адресная форма, факты доступного каталога и CTA `#tariffs` собираются `HomeHero.astro`. Сохранённые legacy `eyebrow/ctaText/ctaHref` не управляют этими элементами городского V3. Это выбор визуальных вариантов и перенос кода, а не утверждение полей всех паспортов или lifecycle API. Объём C3 уточнён владельцем: два Hero и новый тарифный блок, без редакторов устаревших секций.

Предусмотрен порядок `DRAFT → APPROVED → ACTIVE → DEPRECATED → ARCHIVED`. В CMS **нет действий перехода статуса**, назначения утверждающего, замены или редактирования паспорта. В реестр перенесено внешнее решение владельца: два первых экрана и тарифный блок имеют APPROVED/1.0.0 и запись о согласовании владельца; Header и девять тарифных блоков остаются DRAFT/0-draft. `editorReadiness=READY` у двух первых экранов и тарифного блока означает наличие специализированного редактора и runtime в текущем коде; внешний deployment и применение миграции проверяются отдельно. `0-draft` не включается в опубликованный snapshot как утверждённая версия. После решения владельца изменение полей или их смысла потребует новой версии, миграции и проверки; используемый блок нельзя физически удалить. Задача C2 уже перевела городские HOME на общий `PageTemplate`; Оставшиеся C4–C6 ведутся отдельно; текущий объём C3 описан ниже.

В #231 были представлены три DRAFT-контракта Header, общей и городской Hero. Согласование владельца 5 октября 2026 года утверждает только два первых экрана и включает собственные поля адресной подсказки и подписи проверки. Header и остальные паспорта этим согласованием не утверждены. Утверждение само по себе не подтверждает ACTIVE или deployment. Реализация двух редакторов отражена отдельно в editorReadiness=READY.

## Тарифы города — `tariff_grid`

Размещение только CITY_HOME; Figma B04 `93:569`, Desktop `93:3`, Tablet `93:195`, Mobile `93:382`. Полный опубликованный каталог без фильтров, ручного списка карточек и ссылки «Все тарифы». Редактор `/templates/tariffs` сохраняет семь полей:

| Поле | Контракт |
| --- | --- |
| title | До 120 символов, обязательно; Site/City переменные |
| text | До 1000 символов, необязательно; Site/City переменные |
| connectButtonText | До 80 символов, обязательно; действие — адресная проверка выбранного тарифа |
| detailsButtonText | До 80 символов, обязательно; действие — существующая detail-страница тарифа |
| moreButtonText | До 80 символов, обязательно; один клик показывает весь остаток |
| initialCount | Целое 1–100, по умолчанию 6; полный каталог не ограничивается |
| sort | PRICE_ASC/PRICE_DESC, по умолчанию PRICE_ASC; настройка администратора |

Закреплённые `attributes.is_sticky=true` идут первыми; внутри двух групп сравнивается текущая месячная цена `promoPrice ?? standardPrice`. Неизвестная цена последняя, одинаковые цены сохраняют порядок каталога. Новое числовое поле приоритета не вводится. Цены, скорость, TV, подписки, игровой вариант и характеристики берутся из TariffView. Разовое подключение и дополнительные опции не участвуют в сортировке.

Рядом с подписью «Показать ещё» система выводит число оставшихся тарифов; при количестве ≤initialCount кнопки нет. Порядок после раскрытия не меняется. Без JavaScript доступен весь каталог; с JavaScript остаток скрывается до одного клика. В sandbox preview видна первая группа и неактивная кнопка, ссылки/заявки отключены. Desktop — три колонки, tablet — две, mobile — горизонтальная лента; длинные реальные значения не обрезаются.
