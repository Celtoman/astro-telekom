# API-контракты текущего прототипа

Базовый prefix: `/api/v1`. Документ сверен 15 сентября 2026 года с маршрутами, зарегистрированными в `apps/api/src/module.ts`. Он не обещает endpoints из продукта, если их нет в коде.

## Общие правила

- API работает на NestJS/Fastify и принимает JSON; server body limit — 35 MB.
- Browser CORS использует credentialed requests для `ADMIN_URL` и явно разрешает методы `GET`, `HEAD`, `POST`, `PATCH`, `DELETE`, `OPTIONS`. Не полагаться на default methods Fastify CORS: без явного списка browser preflight блокирует существующие admin mutation routes.
- `POST /auth/login` создает 12-часовую сессию и возвращает только expiry и пользователя; raw token передается браузеру исключительно в `HttpOnly`, `SameSite=Strict` cookie `admin_session`. В PostgreSQL хранится SHA-256 hash.
- Защищенные административные маршруты принимают cookie-сессию или совместимый `Authorization: Bearer <token>`. `x-admin-token`, совпадающий с `ADMIN_API_TOKEN`, предназначен для машинного сценария; `/internal/*` принимает только его и отклоняет пользовательские сессии.
- У пользовательского доступа один уровень — администратор. Любой активный пользователь с действующей сессией имеет одинаковый полный доступ ко всем административным routes, включая `/crm/leads`; ролевой модели нет.
- Глобальный `ValidationPipe` преобразует DTO, не допускает лишние поля (`forbidNonWhitelisted`) и не возвращает значения в validation errors. Строгими class-based DTO покрыты login, `address-checks`, `leads` и `lead-access`; часть admin CRUD пока сохраняет ручную валидацию.
- Глобальный Redis-backed rate limiter по IP возвращает `429`, но хранит отдельные счетчики по назначению route: по умолчанию 5 login-запросов, 60 запросов подсказок, по 10 запросов проверки адреса, создания заявки и lead-access, а также 300 остальных запросов за 60 секунд. Значения настраиваются `RATE_LIMIT_*`; query string не создает новый bucket, а один API-route не расходует лимит другого. При ошибке Redis limiter не пропускает запрос. Production Compose включает `TRUST_PROXY=true`, поскольку API доступен только через Caddy.

## Public routes

| Method | Route | Реальное поведение |
| --- | --- | --- |
| GET | `/health/live` | Liveness процесса: возвращает `{ status: "ok", service: "api" }` без обращения к зависимостям. |
| GET | `/health/ready` | Readiness PostgreSQL и Redis: HTTP 200 при обеих доступных зависимостях, HTTP 503 при сбое; ответ содержит только `up`/`down`, без адресов и внутренних ошибок. |
| GET | `/health` | Совместимый alias readiness с тем же 200/503-контрактом; Compose использует явный `/health/ready`. |
| GET | `/public/sites/:siteSlug/cities` | Возвращает последний `SUCCEEDED` publication snapshot: `site` с форматированными телефонами подключения и техподдержки, отдельные `globalPages`, города с Page/Tariff/visible blocks, authoritative `routes` и эффективные redirects. Рабочие изменения и failed/running публикации сюда не попадают. Переходный `content` разрешается по цепочке Provider → Site → Page; удаленные Region/City override не участвуют. SEO читается из Page/Tariff до перехода на общие SEO-шаблоны. Внутри снимка сохраняется строгий Release 1 contract `N + T + 6`; для каждого опубликованного города требуется ровно одна HOME с пустым slug и каноническими семью блоками. Отсутствие, дубль, непустой HOME slug или коллизия блокируют создание/сборку снимка. |
| GET | `/public/sites/:siteSlug/cities/:citySlug` | Возвращает город из последнего успешного publication snapshot. Если город есть только в рабочей версии либо отсутствует в опубликованном снимке, отвечает 404. |
| POST | `/public/sites/:siteSlug/cities/:citySlug/tariffs/:tariffSlug/quote` | Read-only предварительный расчёт по тарифу только из последнего `SUCCEEDED` snapshot; тело `{router?: "NONE"|"INSTALLMENT"|"BUYOUT", tvbox?: ..., services?: string[]}`. Возвращает доступные варианты, выбор, отдельные ежемесячные и разовые строки, итоги и SHA-256 `fingerprint` снимка расчёта. По умолчанию нет оборудования и дополнительных услуг. Денежные поля ядра принимают целые числа либо строгие целые строки Prisma Decimal (`"850"`, `"850.00"`); дробные и произвольные строки отклоняются. `connectionFee: null` сохраняется как неизвестная стоимость, а `0` — как подтверждённый ноль. Сервер отклоняет недоступные, включённые, неполно оценённые и подделанные варианты; ONT не выбирается. Только видеонаблюдение `OPTIONAL` с ценой услуги, оборудования и подключения участвует в выборе. Сам endpoint не сохраняет выбор; его `selection` и `fingerprint` передаются в POST `/leads`. Текущий NestJS default ответ `201` вместо `200` учтён в P3 [#208](https://github.com/Celtoman/astro-telekom/issues/208). |
| GET | `/public/sites/:siteSlug/redirects/:id` | Ищет redirect и target в последнем успешном publication snapshot, затем атомарно увеличивает `hitCount` живой записи и возвращает HTTP 301. Рабочая правка правила не влияет на посетителей до успешной публикации. |
| POST | `/address-suggestions` | Проверяет опубликованные site/city, один раз на 24 часа получает мягкий КЛАДР-приоритет через DaData IPLocate и серверно вызывает `suggest/address`; возвращает до 5 структурированных подсказок, не раскрывая DaData credentials браузеру. |
| POST | `/address-checks` | Серверно нормализует обязательную выбранную DaData-подсказку через `clean/address`, требует номер дома, вызывает официальный Tarifnik `address/check`, сохраняет полный проверенный snapshot и возвращает один typed public result без raw provider response. |
| POST | `/leads` | Сохраняет заявку только после persisted `AddressCheck` с однозначным `AVAILABLE` и найденным Дом.ру, нормализует телефон, выявляет дубликат и принимает routing-решение. Повтор одного `submissionKey` идемпотентно возвращает первый результат; очередь ставится только после однозначного `NOT_FOUND`. |
| POST | `/lead-access/:leadId/consume` | Однократно обменивает 43-символьный fallback token на минимальную карточку одной заявки; истекший, измененный, отозванный, повторный или относящийся к другой заявке token возвращает 401. |

Для `address-suggestions`, `address-checks` и `leads` по умолчанию подставляется единый `siteSlug=domru-site`; endpoint публично принимает только published site/city/page/tariff. Казань передается отдельно как `citySlug`, а не кодируется в идентичности сайта.

### `POST /address-suggestions`

Тело: обязательный `query`; опциональны `siteSlug`, `citySlug` и пустой honeypot `website`. API принимает только published site/city как проверенный контекст страницы, ограничивает query официальным максимумом 300 символов и передает в DaData глобальный запрос с `count: 5`. Первый запрос без валидной `address_city_kladr` cookie вызывает серверный IPLocate по `request.ip`; API сохраняет на 24 часа только 13-значный КЛАДР-код либо `none` в HttpOnly/SameSite=Lax cookie. Полученный код передается исключительно в `locations_boost`; IP и определенная география не сохраняются в БД/Redis/заявке. При ошибке, таймауте, локальном IP или `location: null` используется мягкий boost `{ region, city }` опубликованной страницы. Параметр `locations` не передается, поэтому пользователь может выбрать адрес любого города. Валидный ответ без совпадений возвращает пустой список; настоящий HTTP/сетевой сбой или невалидный ответ `suggest/address` возвращает `503`, а сбой IPLocate не меняет успешность подсказок. Собственный rate limit API возвращает `429` с `Retry-After`.

### `POST /address-checks`

Тело: обязательны `address` и структурированная `suggestion` с `value`, `unrestricted_value`, `data`; опциональны `siteSlug`, `citySlug`, `pageSlug`, `objectType`. Отсутствующий `pageSlug` не отправляется: пустая строка не является slug и строго отклоняется. Поля ограничены по типу и длине, неизвестные поля возвращают 400. Публичная форма также отправляет пустое honeypot-поле `website`; непустое значение отклоняется до БД и внешних интеграций. После `clean/address` требуется непустой `data.house`: адрес без номера дома возвращает HTTP 422, не вызывает Tarifnik и не создает `AddressCheck`.

Перед Tarifnik API выбранная подсказка проходит серверный DaData `clean/address`; результат преобразуется в тот же envelope, что в рабочем боте: `value=source`, `unrestricted_value=source`, `data=<clean result>`. География нормализованного адреса не сравнивается с городом страницы: `citySlug` определяет опубликованный контекст и источник обращения, а Tarifnik получает фактический адрес пользователя. `POST /address/check` получает ровно `{ suggestion }` с Bearer token. HTTP 200 обязан содержать непустой словарь `providerId: providerName`; HTTP 404 — однозначный пустой список провайдеров; 403/422, сеть, невалидный JSON или неверная структура дают внутренний `ERROR`. Без полного DaData/Tarifnik набора переменных либо без нормализованной подсказки внутренний статус будет `MANUAL_CHECK`; ни один из этих исходов не интерпретируется как разрешение delivery.

Публичный ответ является discriminated union и не раскрывает внутренние coverage-статусы. Бизнес-ветка имеет `type: "business"`, `checkId`, `address`, `citySlug` и ровно один из трех `outcome`: `TARGET_AVAILABLE`, `ALTERNATIVES_AVAILABLE`, `NO_PROVIDERS`. Только `ALTERNATIVES_AVAILABLE` дополнительно содержит безопасный список `providers: [{ id, name }]` и единый `actionUrl` на Tarifnik. `AMBIGUOUS`, `MANUAL_CHECK`, `ERROR`, сетевой сбой клиента или невалидный ответ не становятся четвертым бизнес-исходом: API/клиент показывают отдельный восстановимый `type: "technical_error"` с `retryable: true`, кодом и безопасным сообщением.

В persisted snapshot раздельно сохраняются `providers`, `targetProviderId`, `hasAnyProvider` и `hasTargetProvider`. Наличие хотя бы одного провайдера запускает проверку действующего абонента независимо от наличия Дом.ру, но delivery дополнительно требует присутствия Дом.ру. Публичные embedded/modal entry points используют один client state machine: собственный autocomplete блокирует проверку до выбора подсказки с домом, ручное изменение сбрасывает подтверждение, а generation token и `AbortController` не дают позднему ответу заменить более новое состояние. Городская HOME сохраняет встроенную форму; tariff/service CTA и карточки городов на карте покрытия открывают общий native dialog. Карточка карты передает выбранный `citySlug` в тот же компонент без дублирования формы на каждый город. Три business outcomes открываются в доступном native dialog; technical error имеет отдельные действия повторения и изменения адреса.

### `POST /leads`

Обязательны `phone`, `citySlug`, UUID `submissionKey` и точная техническая версия текста согласия `consentVersion=lead-form-v1-2026-09-22`. Для подключения и старых клиентов без причины обязателен `addressCheckId` с положительным снимком. Необязательный `reasonCode` принимает только пять кодов закрытого справочника: `new_connection`, `existing_subscriber_support`, `billing`, `relocation`, `other`; Домофон не допускается. Код, русская подпись, маршрут и версия справочника сохраняются сервером в неизменяемом снимке. Текущая адресная форма явно передает `new_connection`; старый запрос без причины остается совместимым. `new_connection` идет по прежнему sales-пути, `existing_subscriber_support` и `billing` сохраняются без sales-проверок и Tarifnik, `relocation` и `other` направляются на ручное решение. Для этих несбытовых/ручных веток положительный `addressCheckId` не требуется. Новый read-only `GET /crm/leads/reasons` возвращает справочник для фильтра админки; `GET /crm/leads` принимает `reasonCode` из справочника либо `NONE` для исторических записей без снимка.

Телефон принимает только полный российский мобильный номер: `+7`/`7`/внутрироссийская `8` и затем `9` плюс еще девять цифр; десятизначная национальная запись обязана начинаться с `9`. Значение сохраняется только как `79XXXXXXXXX`; неполный номер, не-мобильный префикс и международная запись `+8` возвращают 400. `submissionKey` создается один раз для показанного положительного результата и повторно используется при сетевом retry. Существующий лид ищется до проверки текущего каталога: тот же ключ с теми же site/city/check/page/tariff/service/phone/reason, адресом и отпечатком расчёта возвращает ранее созданный результат без нового notification/delivery даже после архивации рабочей страницы/тарифа или смены публикации. Повторное использование с другим контекстом отклоняется; новая заявка по устаревшему тарифному расчёту по-прежнему требует актуального опубликованного snapshot. Также допускаются slug страницы/тарифа, контакты, адрес, service type, UTM, referrer, URL, form name, time on site, device, до 50 viewed pages и до 100 activity events. Браузерные numeric IDs и неизвестные поля не принимаются: API разрешает только slug. UTM допускает только стандартные `utm_id`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `utm_source_platform`, `utm_creative_format` и `utm_marketing_tactic` со строками до 256 символов. `viewedPages` ограничен 16 KB JSON, весь `activity` — 64 KB, а `activity[].data` — 4 KB, 20 ключами, короткими безопасными именами, строками до 500 символов и не более одним уровнем вложенных containers. Непустое honeypot-поле `website` отклоняется до сохранения.

`citySlug` и сохраняемый `Lead.cityId` обозначают город страницы-источника, а не обязаны совпадать с географией адреса подключения. Для sales-пути фактический нормализованный адрес и DaData city/settlement/region берутся только из связанного persisted snapshot; check обязан принадлежать тому же сайту и контексту страницы, иметь статус `AVAILABLE` и `hasTargetProvider=true`. Отсутствующая, техническая, альтернативная либо пустая проверка отклоняется до contract check и создания sales-лида. Несбытовая/ручная ветка сохраняется без address check и не вызывает проверку абонента или доставку; обычное оповещение оператора сохраняется.

Для тарифной заявки форма передаёт `configuration: { selection: { router, tvbox, services }, fingerprint }` из опубликованного quote. Сервер повторно считает комбинацию по последнему `SUCCEEDED` каталогу, сравнивает отпечаток и отклоняет устаревшую цену или недопустимый вариант до создания лида. Выбранный опубликованный тариф определяется по снимку, даже если его рабочая строка уже архивирована; связь остаётся с тем же `tariffId` и городом. В `Lead.configurationSnapshot` фиксируются выбор, названия и коды компонентов, все строки цен, итоги и время; админка показывает этот снимок прежде текущей изменяемой строки тарифа. Повтор `submissionKey` требует того же отпечатка, не создавая второй лид. Старые клиенты без `configuration` и исторические лиды с `null` остаются совместимыми.

Контроллер сравнивает телефон или нормализованный адрес с лидами того же сайта за последние 24 часа. Статусы обработки: `PENDING`, `DELIVERED`, `DUPLICATE_SUPPRESSED`, `ACTIVE_SUBSCRIBER_NOT_SENT`, `PROVIDER_NOT_AVAILABLE_NOT_SENT`, `NO_PROVIDERS_NOT_SENT`, `NON_SALES_NOT_SENT`, `MANUAL_CHECK`, `ADDRESS_CLARIFICATION`, `MANUAL_CHECK_API`, `DELIVERY_QUEUE_ERROR`, `DELIVERY_ERROR_EMAIL_SENT`, `DELIVERY_ERROR_EMAIL_FAILED`, `DELIVERY_EMAIL_OUTCOME_UNKNOWN`. Сбой постановки BullMQ job не маскируется как ожидание: создается failed attempt канала `QUEUE`, а лид получает `DELIVERY_QUEUE_ERROR`.

Проверка действующего абонента использует фактическую схему рабочего бота: общий публичный endpoint Дом.ру `contract-asterisked`, телефон `7XXXXXXXXXX` в query-параметре `contact`, `isActive=1` и городской профиль `origin/providerid/referer`. Профиль выбирается по нормализованным DaData городу и региону из встроенного UTF-8 справочника: 555 исходных строк, 551 уникальная пара «регион + населенный пункт» и 37 явных региональных fallback-профилей. В окружении требуется только `DOMRU_CONTRACT_API_URL`; отдельного API key нет. Неопределенный город или отсутствующий профиль дает `NOT_CONFIGURED`.

Только валидный JSON с явно присутствующим `contacts: []` означает `NOT_FOUND` и разрешает дальнейшее решение о delivery. Непустой массив означает `ACTIVE`. HTML, пустое тело, невалидный JSON, отсутствие массива `contacts`, неверный телефон, HTTP- или сетевая ошибка дают `ERROR`; лид остается на ручной проверке через `MANUAL_CHECK_API`, и автоматическая передача в Tarifnik не запускается.

Worker повторно проверяет persisted coverage snapshot и однозначный `contractResult.status=NOT_FOUND`/`active=false` перед внешним вызовом. Административный retry разрешен после ошибки очереди, после исчерпанной доставки либо для старого orphan `PENDING` без единой API-попытки; ручные/ошибочные решения coverage или проверки абонента обойти нельзя. Перед email/webhook fallback записывается `DELIVERY_EMAIL_OUTCOME_UNKNOWN`; сбой записи блокирует внешний вызов, сбой после принятого письма оставляет видимый неопределённый статус и не вызывает автоматическую переотправку. Для такого статуса и старого orphan `PENDING` после терминальной API-ошибки `POST /crm/leads/:id/retry-delivery` требует тело `{ "confirmUnknownOutcome": true }` и двухминутную паузу с последнего изменения заявки: оператор сначала проверяет внешний канал, потому что повтор может создать дубль. Новый ручной цикл начинается со следующего свободного глобального номера API-attempt, но получает собственный retry budget. Официальный `appeal/create` payload содержит только `utm_campaign` из runtime-конфигурации, нормализованный `phone`, допустимый `belong_type`, исходный нормализованный `suggestion` и опциональное имя. HTTP 200 считается успехом только при `result: created | created_duplicate` и непустом `appeal_id`. Автоматические повторы через 5 и 30 минут выполняются только для сети/таймаута, HTTP 408, 425, 429 и 5xx; `Retry-After` для 429 учитывается с верхней границей 24 часа. Постоянный 4xx, невалидный JSON или неожиданный 2xx сразу переводят доставку в email/webhook fallback.

Browser-форма сначала создает `AddressCheck` без телефона. Только результат с Дом.ру открывает второй шаг: поле мягко проверяется на blur и окончательно на submit, показывает маску `+7 (XXX) XXX-XX-XX`, блокирует повторный submit и отправляет выбранный тариф вместе с технической версией согласия. Ошибка сохраняет телефон и summary и переводит кнопку в «Попробовать ещё раз» с тем же `submissionKey`; успех заменяет форму экраном «Спасибо! Заявка отправлена» без раскрытия внутреннего routing outcome. Альтернативы ведут на `tarifnik.ru`, пустой список показывает телефон поддержки, а ошибочный/неоднозначный результат не создает лид.

`POST /leads` возвращает `subscriberMode: true` только при persisted-решении `ACTIVE_SUBSCRIBER_NOT_SENT`. Это подсказка для некритичной UI-персонализации, а не credential: API не возвращает HMAC/cookie и не принимает browser-флаг в решении о доставке.

### Контракт `PageBlock`

Корневой объект допускает только `blockType`, `position`, `visible`, `data`, `source`. При создании обязательны `blockType`, неотрицательный целый `position` до `2147483647` и объект `data`; `visible`, если передан, должен быть boolean, а `source` — `null` либо непустая строка до 200 символов без HTML-разметки. Неизвестные корневые поля отклоняются. Строки внутри `data` должны быть непустыми после trim и не могут содержать `<` или `>`.

| `blockType` | Точный объект `data` |
| --- | --- |
| `hero` | Обязательные `title` (до 120) и `text` (до 1000); опциональный CTA задается парой `ctaText` (до 80) + `ctaHref` (до 2048), отдельно они не принимаются; `eyebrow` (до 80) также опционален. CTA принимает локальный path без завершающего слэша, простой `#fragment` или внешний HTTPS URL без credentials; whitespace, backslash, protocol-relative и executable schemes отклоняются. |
| `rich_text` | Обязательные `title` до 120 и `text` до 4000 символов. |
| `tariff_grid` | Обязательный `title` до 120 символов; опциональные `serviceType` (`INTERNET`, `INTERNET_TV`, `TV`), целый `limit` 1–12 и сохраненный для будущих релизов `morePageType`. Тарифы не хранятся в блоке: Release 1 renderer выводит опубликованные предложения текущего города. Каждая карточка ведёт на `/{citySlug}/{tariffSlug}` и отдельно к встроенной проверке `#address-check`. |
| `service_grid` | `title` до 120 и `items` из 1–8 объектов с точными полями `pageType`, `title`, `text`; разрешены page types `INTERNET`, `INTERNET_TV`, `TV`, `ADDRESS_CHECK`, `FAQ`, строки ограничены 120/1000 символами. В Release 1 `pageType` сохраняется как будущая семантика, а действие карточки ведет к `#address-check`. |
| `feature_grid` | `title` до 120 и `items` из 1–8 объектов `{ title, text }` с лимитами 120/1000. |
| `steps` | `title` до 120 и `items` из 2–8 объектов `{ title, text }` с лимитами 120/1000. |
| `faq` | `title` до 120 и `items` из 1–12 объектов `{ question, answer }` с лимитами 240/4000. |

Во всех `data` и элементах массивов действует exact allowlist ключей. Admin list и public catalog стабильно сортируют активные блоки по `position`, затем по `id`; `archivedAt IS NOT NULL` исключает блок из обоих списков. PATCH, меняющий discriminator или `data`, валидирует полный объединенный блок и условно записывает его только при неизменном сохраненном `blockType`; архивный блок нельзя менять до восстановления, конкурентная смена типа дает 409. Public catalog возвращает только `visible` и неархивные blocks, повторно валидирует каждый сохраненный блок и fail-closed требует ровно один видимый `hero` у любой непустой блочной страницы. Для опубликованного города до рендера дополнительно требуется ровно одна `HOME` с пустым slug и точной семиблочной последовательностью. В Release 1 Astro рендерит блоки городской `HOME`; остальные опубликованные Page могут оставаться в каталоге как данные будущих релизов, но маршрутов не получают. Адресная форма остается системным компонентом и не входит в `PageBlock`.

`SiteRebuild` дедуплицируется по сайту; `affectedPaths` сейчас всегда `["/*"]`, потому что пересобирается весь static artifact. BullMQ делает до трех попыток с exponential backoff 30 секунд. Legacy webhook получает `rebuildId`, `siteId`, `dedupeKey`, `affectedPaths`, `revision` и idempotency header `<rebuildId>:<revision>` и обязан вернуть финальный `SUCCEEDED`. Coolify adapter запускает resource, сохраняет `deployment_uuid`, опрашивает deployment и преобразует только `finished` в `SUCCEEDED`; pending/failure/timeout опубликованную ревизию не меняют.

### Import contracts

Тарифный import читает первый лист и требует точный 37-колоночный состав из `CANONICAL_IMPORT_COLUMNS`; `external_id`, `show_on_site`, производные тексты оборудования, отдельное название игры и игровой флаг запрещены. Поддерживаются только типы `Интернет` и `Интернет+ТВ`; `post_title` после очистки обязан совпасть с `nazvanie_tarifa`. Цены, скорость, каналы и сроки принимаются только как целые значения: текст с единицами, дроби, отрицательные значения и недопустимый ноль блокируют строку. Для `Интернет` TV-поля пусты, для `Интернет+ТВ` общее число каналов положительно, а HD при наличии также положительно и не больше общего. Import и ручное создание рассчитывают один обязательный `identityKey` из города, нормализованного канонического названия и типа; slug, цена и скорость в ключ не входят. Ручная правка не может изменить бизнес-ключ существующей записи: для такого изменения создается новый тариф. Full-snapshot lifecycle использует `ACTIVE/ARCHIVED`; архивный тариф исключается из public catalog, route inventory, sitemap, redirect targets и выбора для новой заявки.

Все source-specific поля закрыты единым реестром `TARIFF_ATTRIBUTE_FIELDS`: очищенный одно- и многострочный текст, booleans, положительные/неотрицательные integers, TV-счетчики, закрытые коды онлайн-кинотеатров и игр, оборудование/цены и внутренние статусы услуг. Импорт и PATCH используют один нормализатор типов и отклоняют неизвестные ключи; пустые значения не создают JSON-ключ. Пара рассрочки `price/months` либо целиком отсутствует (`0/0` и пустые значения нормализуются совместно), либо содержит две положительные величины. `UNAVAILABLE` несовместим с зависимыми ценами или `game_code`; доступное игровое предложение требует известный код. Реестр возвращается detail endpoint как схема формы. `connection_cost` нормализуется отдельно в nullable `Tariff.connectionFee` и входит в public catalog для build-time отображения.

Городской import принимает русские и латинские aliases для субъекта, грамматических форм, slug, legacy URL и офиса, включая фактические комбинированные заголовки канонического `data/imports/cities.xlsx`. Apply блокируется при errors, а при warnings требует явного `confirmWarnings: true`. Регионы и города предварительно загружаются в transaction-local maps, одинаковый нормализованный slug объединяет «Республика Татарстан» из seed и «Татарстан» из XLSX. Каждый примененный город получает `PUBLISHED`; новый город создается с одной `PUBLISHED` страницей `HOME`. Полный пакет выполняется с transaction timeout 30 секунд.

Apply тарифа трактует файл как полный snapshot провайдера: partial apply через `acceptedKeys` отклоняется, перед записью повторно сверяются exact tariff snapshot и конфликты slug, а legacy report требует новой проверки файла. Все строки и условный переход run `VALIDATED -> APPLIED` применяются в одной serializable-транзакции с timeout 120 секунд; отсутствующие в новом файле активные тарифы архивируются с provenance, но не удаляются. Apply сохраняет только рабочую версию, а пересборка начинается после отдельной явной публикации нужного сайта. Ручная смена city/slug тарифа сохраняет provenance-aware redirect; он становится эффективным только после успешной публикации снимка, в котором новая tariff detail-цель входит в актуальный route inventory. Public catalog и runtime resolver fail-closed пропускают только активные target.

## Заявки администратора и internal routes

| Method | Route | Поведение |
| --- | --- | --- |
| GET | `/crm/leads` | Cursor-страница минимального list DTO заявок; поддерживает `limit`, `cursor`, поиск `q`, фильтры `status` и `reasonCode` (включая `NONE` для исторических записей). Тяжелые relations доступны только в detail endpoint. |
| GET | `/crm/leads/reasons` | Закрытый справочник причин обращения с русской подписью, версией и маршрутом; чтение требует admin-сессию. |
| GET | `/crm/leads/:id` | Детальная карточка с адресной проверкой, delivery attempts, notification evidence и activity. |
| PATCH | `/crm/leads/:id/status` | Изменяет операторский status и добавляет history с optimistic concurrency. |
| POST | `/crm/leads/:id/retry-delivery` | Безопасно повторно ставит eligible lead в очередь после `DELIVERY_QUEUE_ERROR`, исчерпанной доставки либо orphan `PENDING` без API-attempts. Возвращает фактический `PENDING` или `DELIVERY_QUEUE_ERROR`; не обходит coverage/subscriber routing. |
| POST | `/crm/leads/:id/retry-notification` | Повторно ставит обычное оповещение только после финального `FAILED`; увеличивает revision, создает новый provider idempotency key и возвращает `QUEUED` либо сохраненный `PENDING`. Автоматические попытки внутри revision используют общий ключ. |
| POST | `/crm/leads/:id/revoke-fallback-access` | Отзывает все еще активные одноразовые fallback tokens заявки. Защищен общим admin guard. |
| POST | `/internal/lead-deliveries/:id` | Worker-only handler очереди. Защищен тем же guard. |
| POST | `/internal/lead-notifications/:id` | Worker-only обработчик persistent outbox; принимает attempt/maxAttempts/revision и сохраняет безопасный outcome. Защищен service token guard. |
| POST | `/internal/pii-retention` | Worker-only bounded purge: требует service `x-admin-token` и валидный `PII_RETENTION_DAYS`, удаляет один batch просроченных лидов с cascade-данными, истекшие fallback tokens и осиротевшие старые AddressCheck; возвращает только cutoff и счетчики. |

Cursor-list endpoints используют стабильную сортировку по timestamp и `id`, `limit=25` по умолчанию и жесткий максимум 100. `cursor` — непрозрачная base64url-позиция; неверное значение дает HTTP 400. Ответ имеет вид `{ items, pageInfo: { limit, total, hasNextPage, nextCursor } }`, где `total` относится ко всему текущему фильтру, а не только к остатку после cursor. `/crm/leads` дополнительно возвращает глобальную `summary` для карточек `total/new/pending/attention`. List DTO заявки содержит только поля журнала, город и безопасный статус notification; история, delivery attempts, activity, результаты проверок и остальные PII загружаются через `/crm/leads/:id` после явного открытия карточки. Audit list аналогично откладывает `changes` до detail-запроса.

Retention endpoint физически удаляет весь `Lead`, чтобы PII не осталось в `contractResult`, `apiResult`, UTM или delivery JSON. Cascade удаляет `LeadDeliveryAttempt`, `LeadNotification`, `LeadActivityEvent`, `LeadStatusHistory` и `LeadAccessToken`; старые `AddressCheck` удаляются только после исчезновения всех ссылок. Свежий duplicate, ссылающийся на удаляемый лид, предварительно отвязывается. Один вызов ограничен `PII_RETENTION_BATCH_SIZE` (default 500, максимум 5000); worker повторяет batches и запускает scheduler ежедневно. Согласованный срок для сырых заявок — 180 дней. Без валидного `PII_RETENTION_DAYS` endpoint возвращает 503, scheduler отключен, а release readiness остается `blocked`.

## Отсутствующие routes

В коде нет admin endpoints для media, analytics, универсального каталога/реестра variables, per-entity rollback, SEO validation, page templates и предложений редиректов из 404. Узкий `GET/PATCH /admin/sites/:siteId/values` уже реализован и управляет только двумя типизированными телефонными значениями Site; он не является API произвольных переменных и не заменяет будущие V1–V3. Реализованный preview endpoint read-only собирает текущий рабочий Release 1 catalog: он не является отдельным deployment-артефактом или публичной ссылкой. Общий read-only audit журнал показывает сохраненные действия и field-level diff, но не является редактором истории или механизмом восстановления. Защищенный build endpoint publication snapshot также не заменяет эти пользовательские функции. Callback от Tarifnik не реализован, поскольку партнерский API его не предоставляет. Эти возможности нельзя считать частью текущего API.
