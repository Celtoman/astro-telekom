## Правила структуры

1. В таблицах ниже указан только path без домена. Корень сайта обозначается `/`.
2. Все HTML-URL, кроме `/`, используются без завершающего `/`.
3. `{location}` — slug опубликованного города. Для каждого опубликованного города создаётся отдельная страница `/{location}`.
4. Остальные параметры обозначаются единообразно: `{tariffSlug}`, `{newsSlug}`, `{articleSlug}` и `{promotionSlug}`.
5. Строка с параметром описывает один шаблон маршрута, а не одну физическую страницу. Например, `/{location}` создаёт столько страниц, сколько городов опубликовано.
6. Для новых URL при использовании бренда применяется написание `domru`. Уточнение владельца от 12 октября: существующие URL сохраняемых страниц остаются неизменными, включая исторические `dom-ru` и другие варианты написания. MTS-идентификаторы в целевой структуре не используются.
7. Столбец «Первый релиз» задаёт минимальный публичный набор Release 1. Страницы со значением «позже» входят в полную структуру, но не создаются и не попадают в публичную навигацию или sitemap до отдельного решения о релизе.
8. Зелёная заливка исходной таблицы не несёт смысла и не влияет на публикацию.
9. `/robots.txt` и `/sitemap.xml` — системные endpoints, а не контентные страницы. Они обязательны для работающего сайта, но не входят в реестр ниже. Страница `/sitemap` — отдельная будущая HTML-страница.
10. `404` — шаблон ответа для неизвестного URL, а не самостоятельный публичный маршрут `/404`.
11. SEO-шаблоны выбираются по поддерживаемому типу маршрута, а не отдельно для каждого города или тарифа. `noindex` не удаляет HTML-маршрут, но исключает URL из sitemap того же снимка. Точный набор HTML задаёт inventory конкретного snapshot: исторический вариант с ADDRESS — `2N + T + 6`; опциональные ACCOUNT/OFFICIAL_SITE/SPEED_TEST/EQUIPMENT_ROUTER и редакционные маршруты новостей учитываются дополнительно. Наличие CITY_SUPPORT в снимке добавляет ещё N городских URL. Поддерживаемые типы и фактический вывод описаны в [current-state.md](current-state.md).

Правила смены и сохранения активного города, а также итоговый состав меню обсуждаются отдельно.

## Критерии соответствия Release 1

Структура первого запуска соответствует этому документу, когда одновременно выполнены условия:

1. `/` создаётся ровно один раз.
2. `/{location}` создаётся для каждого и только для опубликованного города; Казань не имеет отдельного правила в маршрутизации.
3. `/{location}/{tariffSlug}` создаётся для каждого и только для опубликованного тарифа опубликованного города; дубли и коллизии URL блокируют сборку.
4. Карта покрытия, города обслуживания и три legal-страницы доступны по зафиксированным общим URL.
5. Неизвестный URL возвращает корректную страницу с HTTP 404.
6. Ни один маршрут со значением «позже» не попадает в публичную сборку, внутреннюю навигацию или sitemap Release 1.
7. `/robots.txt` и `/sitemap.xml` отражают фактически опубликованный Release 1.
8. Публичные URL не содержат `mts`, `rostelekom` или иной идентификатор чужого провайдера.
9. Все города из примененного канонического импорта опубликованы; каждый `/{location}` использует каноническую композицию CITY_HOME 3.0.0 из десяти блоков, имеет хотя бы один опубликованный тариф, показывает полный тарифный snapshot и ведёт с карточек на страницы соответствующих тарифов.
10. Страница тарифа собирается одним типизированным шаблоном для `INTERNET` и `INTERNET_TV` в фиксированном порядке: hero с составом и раздельной текущей/обычной ценой, описание, онлайн-кинотеатры, оборудование, дополнительные сервисы или игра, проверка адреса, предложения того же города и FAQ. Условные секции появляются только из валидных структурированных данных; интернет-тариф явно сообщает, что ТВ не включено, а неизвестный атрибут или системный код блокирует сборку. Форма передаёт выбранный `tariffSlug`.
11. `/goroda-obsluzhivaniya` содержит все опубликованные города в серверном HTML, группирует их по фактическим регионам и позволяет искать город без создания дополнительных URL.

## ADDRESS: контракт выпуска от 4 ноября 2026

Для каждого опубликованного города добавлен тип CITY_ADDRESS_CHECK по согласованному URL. Он входит в Release 1 наряду с HOME города и тарифами. Целевой inventory после CMS-публикации ADDRESS: `2N + T + 6`; исторический `N + T + 6` сохраняется только для прежних immutable snapshots. Шапка и футер направляют на ADDRESS текущего города; смена города сохраняет тип страницы и сбрасывает введённый адрес/результат. Встроенные формы других страниц продолжают FLOW2 без промежуточного перехода.

Состав: вводная → проверка адреса → пояснение результата → популярные тарифы → этапы → преимущества → консультация → FAQ; общие шапка и футер завершают десять визуальных секций. Контент ADDRESS независим от HOME/CITY_HOME. Собственный SEO-шаблон, canonical собственного URL и sitemap для INDEX-страниц. ## ACCOUNT: опциональный маршрут внедрения

В коде поддержан один глобальный `/lichnyy-kabinet-dom-ru` типа ACCOUNT; это информационный гид партнёра, действия входа/оплаты/управления договором выполняются у провайдера. ACCOUNT опционален для исторических snapshots и не становится шестой обязательной общей страницей задним числом. Новая валидная публикация с ACCOUNT добавляет ровно один маршрут. Недостающие `/official-site-domru`, `/faq`, `/proverit-skorost-interneta`, `/{location}/tehpodderzhka` остаются зависимостями публичного выпуска; новые страницы и fake targets не добавлены.
