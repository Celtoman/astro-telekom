Статус: **целевая структура**. Документ фиксирует обязательные URL, иерархию и состав первого публичного релиза. Фактически реализованное поведение описывается отдельно в [current-state.md](current-state.md).

Источник: рабочая таблица `Структура Дом.ру.xlsx` и уточнения владельца проекта от 14 сентября 2026 года, включая прямое решение вернуть отдельные страницы тарифов в Release 1.

Уточнение владельца от 12 октября 2026 года: основа новой структуры — действующий [tarify-dom.ru](https://tarify-dom.ru/), см. [исследование источника](research/2026-10-12-tarify-dom-site-structure.md). Состав типов страниц и их URL собраны в [сводке согласования](plans/2026-10-12-site-structure-agreement.md) и [матрице URL](plans/2026-10-12-site-url-agreement.md); принято сохранять адреса сохраняемых страниц, пять новых адресов и redirect для `/akcii-domru` утверждены. Остальные переходы со старых страниц отложены: владелец решит самостоятельно позже; они исключены из текущего обсуждения и не блокируют согласование структуры и блоков. Состав и порядок 13 блоков общей главной `/` согласованы в [сводке](plans/2026-10-12-general-home-block-agreement.md); 13 октября 2026 года утверждены этапы подключения после преимуществ, перед акциями. Блоки локаций и выпуск новой структуры ещё не согласованы. Минимальный Release 1 ниже отражает прежний контракт приложения; действующие маршруты и публикационная policy автоматически не меняются.

## Правила структуры

1. В таблицах ниже указан только path без домена. Корень сайта обозначается `/`.
2. Все HTML-URL, кроме `/`, используются без завершающего `/`.
3. `{location}` — slug опубликованного города. Для каждого опубликованного города создаётся отдельная страница `/{location}`.
4. Остальные параметры обозначаются единообразно: `{tariffSlug}`, `{newsSlug}`, `{articleSlug}` и `{promotionSlug}`.
5. Строка с параметром описывает один шаблон маршрута, а не одну физическую страницу. Например, `/{location}` создаёт столько страниц, сколько городов опубликовано.
6. Для новых URL при использовании бренда применяется написание `domru`. Уточнение владельца от 12 октября: существующие URL сохраняемых страниц остаются неизменными, включая исторические `dom-ru` и другие варианты написания. MTS-идентификаторы в целевой структуре не используются.
7. Столбец «Первый релиз» задаёт минимальный публичный набор Release 1. Страницы со значением «позже» входят в полную структуру, но не создаются и не попадают в публичную навигацию или sitemap до отдельного решения о релизе.
8. Зелёная заливка исходной таблицы не несёт смысла и не влияет на публикацию.
9. `/robots.txt` и `/sitemap.xml` — системные endpoints, а не контентные страницы. Они обязательны для работающего сайта, но не входят в реестр ниже. Страница `/sitemap` — отдельная будущая HTML-страница.
10. `404` — шаблон ответа для неизвестного URL, а не самостоятельный публичный маршрут `/404`.
11. SEO-шаблон задаётся для каждого из восьми типов маршрута Release 1, а не для отдельного города или тарифа. `noindex` не удаляет HTML-маршрут, но исключает соответствующие URL из sitemap того же снимка публикации. Количество HTML-страниц поэтому остаётся `N + T + 6`, а число индексируемых URL может быть меньше.

## Минимальный набор Release 1

Это ранее действующий минимальный контракт, а не полный состав новой структуры от 12 октября. Здесь сохранены прежние пути и формула `N + T + 6`; изменение приложения и его inventory выполняется отдельной реализацией. Согласованные новые адреса находятся в следующем разделе и матрице URL.

| ID | Страница | URL | Правило публикации |
| --- | --- | --- | --- |
| `HOME` | Главная | `/` | Одна страница на сайт |
| `CITY_HOME` | Страница города | `/{location}` | По одной странице для каждого опубликованного города |
| `CITY_TARIFF_DETAIL` | Страница тарифа | `/{location}/{tariffSlug}` | По одной странице для каждого опубликованного тарифа опубликованного города |
| `COVERAGE` | Карта покрытия | `/karta-pokrytiya-provaydera` | Одна общая страница |
| `CITIES` | Города обслуживания | `/goroda-obsluzhivaniya` | Одна общая страница со всеми опубликованными городами, поиском и группировкой по регионам |
| `PRIVACY` | Политика конфиденциальности | `/politika-konfidencialnosti` | Одна общая страница |
| `PERSONAL_DATA_CONSENT` | Согласие на обработку персональных данных | `/soglasie-na-obrabotku-personalnyh-dannyh` | Одна общая страница |
| `COOKIE_POLICY` | Политика обработки файлов cookie | `/politika-obrabotki-faylov-kuki` | Одна общая страница |
| `NOT_FOUND` | Страница 404 | — | Возвращается для любого неизвестного URL |

Если опубликовано `N` городов и `T` тарифов, принадлежащих этим городам, Release 1 содержит `N + T + 6` обычных HTML-маршрутов и один общий шаблон 404. Канонический импорт публикует все входящие города вместе с единственной HOME-shell, связанной с общим `PageTemplate(CITY_HOME)` сайта; каждый опубликованный тариф получает самостоятельный URL и остаётся карточкой на городской странице. Черновой или архивный тариф URL не создаёт.

Уточнение владельца от 4 октября 2026 года: исходный город для навигации общей главной `/` — **Москва**. На самой общей главной **тарифов нет**; каталог тарифов находится на странице соответствующего города. Это не добавляет новый маршрут и не меняет URL городской страницы Москвы. Правила смены и сохранения активного города, а также итоговый состав меню обсуждаются отдельно.

## Полная структура

Утверждённые владельцем новые URL от 12 октября: проверка подключения `/{location}/proverka-podklyucheniya-k-domru-po-adresu`, техподдержка `/{location}/tehpodderzhka`, карта покрытия `/karta-pokrytiya-domru`, контакты `/contacts`, общая HTML-карта `/sitemap`. Для `/akcii-domru` согласован 301 на `/akcii-i-skidki`. Остальные решения о старых исключённых/перенесённых адресах отложены владельцем до его отдельного решения, см. [запись об отсрочке](plans/2026-10-12-site-redirect-agreement.md).

Решение об URL от 12 октября: сохраняемые страницы оставляют действующие адреса tarify-dom.ru. Принятые адреса источника и ещё не утверждённые новые маршруты перечислены в [матрице URL](plans/2026-10-12-site-url-agreement.md). При сопоставлении с предварительными адресами старых таблиц для новой структуры приоритет имеет это решение; действующий Release 1 inventory приложения автоматически не меняется.

Решение о юридических документах от 12 октября 2026 года: сохраняются три общие страницы — политика конфиденциальности, согласие на обработку персональных данных и политика cookie. Согласовано их присутствие в новой структуре; тексты и окончательные URL этим решением не утверждены. Сводка текущего согласованного состава — [перечень страниц](plans/2026-10-12-site-structure-agreement.md).

Сводка текущего согласования по ответам владельца: [состав страниц на 12 октября](plans/2026-10-12-site-structure-agreement.md). В ней собраны общие страницы, вложенность локаций, исключения текущего этапа и оставшиеся вопросы. Она не меняет автоматически действующий Release 1 inventory.

Пакет решений от 12 октября 2026 года: сохраняются общие информационная страница «Официальный сайт Дом.ру», страница контактов партнёра и одна общая HTML-карта сайта. Блог со статьями, каталог дополнительных услуг и отдельные страницы услуг пока не добавляются. Самостоятельная страница «Способы оплаты» не создаётся: информация размещается в «Личном кабинете» и FAQ. Точные URL и блоки будут согласованы отдельно.

Решение о личном кабинете от 12 октября 2026 года: сохраняется одна общая информационная страница «Личный кабинет» с инструкцией и ссылкой на кабинет провайдера (`ACCOUNT`). Точный URL и состав блоков будут согласованы отдельно; path в таблице ниже остаётся предварительным. Это информационная страница партнёрского сайта, а не собственная система авторизации абонентов.

Решение о проверке скорости от 12 октября 2026 года: сохраняется одна общая страница «Проверка скорости интернета» для всего сайта (`SPEED_TEST`). Точный URL, состав блоков и способ измерения скорости будут согласованы отдельно; path в таблице ниже сохраняет прежний предварительный вариант.

Решение о FAQ от 12 октября 2026 года: «Вопросы и ответы» сохраняются одной общей страницей для всего сайта (`FAQ`), URL `/faq` утверждён. Блок на общей главной также согласован: 4–6 общих вопросов и ссылка на полную страницу. Блоки самой страницы FAQ и других шаблонов ещё не утверждены.

Решение о техподдержке от 12 октября 2026 года: внутри каждой локации добавляется отдельная страница «Техподдержка» (`CITY_SUPPORT`), по аналогии с отдельной страницей проверки подключения. Общая страница техподдержки в новую структуру не переносится. URL утверждён: `/{location}/tehpodderzhka`; состав блоков ещё не утверждён. Согласование страницы не означает, что маршрут уже реализован.

Решение о покрытии от 12 октября 2026 года: сохраняется отдельная общая страница «Карта покрытия» наряду со справочником «Города обслуживания» и отдельной страницей проверки адреса внутри каждой локации. URL утверждён владельцем: `/karta-pokrytiya-domru`. Состав блоков и способ представления покрытия будут согласованы отдельно.

Решение о справочнике локаций от 12 октября 2026 года: сохраняется отдельная общая страница «Города обслуживания» со списком всех локаций сайта. Это общий справочник со ссылками на страницы локаций; точный URL и состав блоков новой версии будут согласованы отдельно.

Решение об адресной проверке от 12 октября 2026 года: внутри каждой локации добавляется отдельная страница проверки подключения по адресу (`CITY_ADDRESS_CHECK`). Это самостоятельная страница в дополнение к основной странице локации и страницам конкретных тарифов. Отдельная общая страница этой проверки в новой структуре не сохраняется. URL утверждён: `/{location}/proverka-podklyucheniya-k-domru-po-adresu`; состав блоков ещё не утверждён. Добавление в новую структуру не означает наличие маршрута в действующей сборке.

Решение о публикациях от 12 октября 2026 года: в новой структуре «Новости» и «Акции» являются двумя самостоятельными общими разделами, каждый со своим списком и отдельными страницами публикаций. Общий listing действующего сайта `/akcii-domru` не принимается как единый раздел новой версии. Окончательные URL разделов и публикаций, состав блоков и реализация будут согласованы отдельно.

Решение об оборудовании от 12 октября 2026 года: на текущем этапе сохраняются только две общие страницы оборудования — «Роутеры» и «Movix». Отдельные страницы моделей роутеров и ТВ-приставок не входят в текущий согласованный состав. Окончательные URL и состав блоков общих страниц будут согласованы отдельно.

Дополнительное решение владельца от 12 октября 2026 года: на текущем этапе в новой структуре сохраняются две отдельные общие страницы тарифов кабельного и цифрового телевидения, без привязки к локации. На действующем сайте это `/kabelnoe-televidenie-obshhij-tarif` и `/cifrovoe-televidenie-obshhij-tarif`; окончательные URL новой версии и состав блоков ещё не утверждены. Решение о типах страниц не добавляет эти маршруты автоматически в действующий Release 1 inventory и не изменяет формулу его текущего состава выше.

Уточнение владельца в обсуждении 12 октября 2026 года: на текущем этапе для каждой локации сохраняется одна основная страница `/{location}`; отдельные страницы категорий «Домашний интернет», «Интернет + ТВ» и «Цифровое ТВ» не создаются. Отдельные страницы конкретных тарифов сохраняются по действующему контракту. Это решение касается состава страниц, а не утверждения прежних блоков: состав, порядок и содержимое блоков локации будут переработаны и согласованы отдельно. ## Критерии соответствия Release 1

Структура первого запуска соответствует этому документу, когда одновременно выполнены условия:

1. `/` создаётся ровно один раз.
2. `/{location}` создаётся для каждого и только для опубликованного города; Казань не имеет отдельного правила в маршрутизации.
3. `/{location}/{tariffSlug}` создаётся для каждого и только для опубликованного тарифа опубликованного города; дубли и коллизии URL блокируют сборку.
4. Карта покрытия, города обслуживания и три legal-страницы доступны по зафиксированным общим URL.
5. Неизвестный URL возвращает корректную страницу с HTTP 404.
6. Ни один маршрут со значением «позже» не попадает в публичную сборку, внутреннюю навигацию или sitemap Release 1.
7. `/robots.txt` и `/sitemap.xml` отражают фактически опубликованный Release 1.
8. Публичные URL не содержат `mts`, `rostelekom` или иной идентификатор чужого провайдера.
9. Все города из примененного канонического импорта опубликованы; каждый `/{location}` использует каноническую композицию CITY_HOME 3.0.0 из десяти блоков, имеет хотя бы один опубликованный тариф, показывает полный тарифный snapshot и ведёт с карточек на страницы соответствующих тарифов.
10. Страница тарифа собирается одним типизированным шаблоном для `INTERNET` и `INTERNET_TV` в фиксированном порядке: hero с составом и раздельной текущей/обычной ценой, описание, онлайн-кинотеатры, оборудование, дополнительные сервисы или игра, проверка адреса, предложения того же города и FAQ. Условные секции появляются только из валидных структурированных данных; интернет-тариф явно сообщает, что ТВ не включено, а неизвестный атрибут или системный код блокирует сборку. Форма передаёт выбранный `tariffSlug`.
11. `/goroda-obsluzhivaniya` содержит все опубликованные города в серверном HTML, группирует их по фактическим регионам и позволяет искать город без создания дополнительных URL.
